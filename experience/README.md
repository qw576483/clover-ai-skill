# 经验库（`experience/`）—— 从一个真实项目里摔出来的东西

> 这个文件夹不是"规范"，是**实战复盘**：来自真实项目的翻车记录。**每条经验都对应一次翻车**，写在这里是为了不再摔第二次。
>
> **使用时机**：
> - 用户说"做个 XX 游戏 / 一键出 XX / 删库重建一个 XX" → **先读 `experience/README.md` + `time-sinks.md`**；
> - **用户说"卡 / 掉帧 / 有 1 帧吗" → 先读 `perf-triage.md`**（**先证伪环境，再查代码**）；
> - 写客户端操作 / 相机 / 移动同步之前 → `reference/engine-mental-model.md` §3 / §5；
> - 交付前自证 / 取证 → `verify-recipes.md`；
> - 感觉"又要做很久"时 → `time-sinks.md`（照着避开，能省掉大部分返工）。

## 文件索引

| 文件 | 作用 |
|---|---|
| **`time-sinks.md`** | **为什么上一个项目做了那么久**：17 个时间黑洞 + **3 条静默失败**（编译不报错 / 日志不报警），每条写清「现象 / 根因 / 正确做法 / **判据** / 如何提前预防」 |
| **`perf-triage.md`** | **掉帧 / 卡顿排查配方**：先证伪环境（渲染设备 / 软件渲染）→ CPU·GPU 拆分 → A/B → 才轮到代码红旗 |
| **`verify-recipes.md`** | 自证与取证配方：运行时自证脚本、服务端探针、截图 + 校验、日志解析、回归测试命令、**跑 `verify.ps1` 的实操坑** |
| **`per-frame-jitter-evidence.md`** | **逐帧现象（抖 / 飘 / 抽搐 / 攻击被打断）的取证通道**：逐帧采样怎么做、口径怎么定，判据事故案例（假红 / 永远不可能通过 / 负控打空 / 剔除瞬态 ≠ 隐藏证据），以及"抖动不在表现层时"的定位与修法 |
| （参照）`reference/architecture.md` | 分层与模块化强制规范（App ≤200 行、模块门面、依赖单向） |

## 一句话教训总表（按"代价"排序）

| 教训 | 代价 |
|---|---|
| **先搞懂引擎的"谁自动挂 / 谁必须业务挂"，再写业务代码** | 漏 `CloverRes.Init` ⇒ 模型**从头到尾没加载成功**，被误判成"同步问题"，白跑好几轮 |
| **三段一次做完**（启动/菜单/创角链路 + 首场景 + 游戏内流程；不许先交骨架） | 被用户连续四轮骂"半成品" |
| **不许"打开就直接进游戏场景"**（菜单链路不能省） | 一眼假 |
| **交付前必须自审"像不像参考游戏"**（不像 = 不可交付） | 只跑通就交 ⇒ 一句"不像" ⇒ 全面返工；**没有参考游戏名就先问用户要** |
| **不许分步汇报**（做一项报一次） | 用户暴怒；他只想知道"做完没有" |
| **"卡 / 掉帧"先证伪环境，再查代码** | 跑满 6 次 Play 分析代码层性能红旗，而机器其实在跑 **WARP 软件渲染**（GPU 255ms/帧、3.5 fps）—— 根因在第 1 条命令 `SystemInfo.graphicsDeviceName` 里 |
| **移动 / 相机的标准做法先搜再做** | 被拽回、镜头穿墙 |
| **移动同步三件套必须同时上**（本地碰撞 + 预测&校正&回放 + 停发闸门） | 少任何一条都表现为"按了键不动 / 被拽回" |
| **验收靠自证与截图，不靠"看着像"** | 用户看到的和 AI 以为的完全不是一回事 |
| **分层分模块** | Bootstrap 上帝类，改一处炸全局，被用户点名 |
| **改几何就重跑导出** | 客户端与服务端错位（客户端有墙、服务端不挡） |
| **量测优先**（第三方素材单位 / 枢轴、坐标格中心） | 模型 100 倍大 / 半埋 / 整体偏移半格 |
| **高频日志必须降频** | 一次断线刷 3262 条、一次未鉴权刷 747 条 |
| **驱动活编辑器**（别跑 batch） | 被"项目已在编辑器中打开"卡住，浪费大量等待 |
| **Go 判据交给后台长任务收**（前台超时不算结论） | 把 `go vet` / `go test` 当"秒级命令"跑 ⇒ 前台被超时杀掉、判据一条没拿到 |
| **采集前先算"获取一次要多久"**（窗口 N 秒 < 往返耗时 ⇒ 改用一次跑完的长任务） | 启动画面只停 2 s，而 `eval_file` 一次往返 1.5–2 s ⇒ 连追两次都拍到主菜单 |
| **"改参数→截图"必须分两次 eval**（截图取的是上一帧，不会为你重绘） | 12 张 HUD alpha 帧**逐张错位一格**，据此算出的读数全错，而闸门完全看不出来 |
| **静默失败只能靠运行时判据抓**（组件为 null / 空白屏零日志 / 日志刷屏） | 编译期**全是绿的**、一条报错都没有 ⇒ 只能靠「活节点树读数 + 计数 + 唯一色数」，⛔ 拿"编译过了 / 代码里写了"当证据 = 白跑 |

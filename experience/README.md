# 经验库（`experience/`）

> 这个文件夹不是"规范"，是**实战复盘**：每条经验都对应一次翻车，写在这里是为了不再摔第二次。
> 三条通用判据：**先证伪环境，再查代码**；**跑通 ≠ 做完**；**编译绿 ≠ 没坏**。

## 使用时机

- 用户说"做个 XX 游戏 / 一键出 XX / 删库重建一个 XX" → 先读 `time-sinks.md`；
- 用户说"卡 / 掉帧 / 有 1 帧吗" → 读 `perf-triage.md`（**先证伪环境，再查代码**）；
- 写客户端操作 / 相机 / 移动同步之前 → `reference/engine-mental-model.md` §3 / §5；
- 现象是逐帧尺度（抖 / 飘 / 抽搐 / 攻击被打断）→ `per-frame-jitter-evidence.md`；
- 交付前自证 / 取证 → `verify-recipes.md`。

## 文件索引

| 文件 | 作用 |
|---|---|
| `time-sinks.md` | **17 个时间黑洞 + 3 条静默失败**（编译不报错 / 日志不报警），每条写清「现象 / 根因 / 正确做法 / **判据** / 预防」 |
| `perf-triage.md` | **掉帧 / 卡顿排查配方**：先证伪环境（渲染设备 / 软件渲染）→ CPU·GPU 拆分 → A/B → 才轮到代码红旗 |
| `per-frame-jitter-evidence.md` | **逐帧现象的取证通道**：采样怎么搭、口径怎么定，判据事故（假红 / 永远不可能通过 / 负控打空 / 剔除瞬态 ≠ 隐藏证据），以及"抖动不在表现层时"的定位与修法 |
| `verify-recipes.md` | 自证与取证配方：运行时自证脚本、服务端探针、截图 + 校验、日志解析、回归测试命令、实操坑 |

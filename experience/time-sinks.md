# 17 个时间黑洞 + 3 条静默失败

> 写法：**现象 → 根因 → 正确做法 → 预防**，每条都是实际摔过的。★ = 最贵的那几类。
> **"删库重建"时照着走，能把返工砍掉大半。**

## T1. 没先读引擎就写业务：资源域必须业务显式挂（★ 最贵）

- **现象**：客户端只显示胶囊体 / "进去看不到角色" / `EnsureView` 抛 `NullReferenceException`。
- **根因**：以为 `Game.Launch` 会把模块都挂上 —— 表现域确实自动挂，**资源域（`Game.Res`）必须业务显式 `CloverRes.Init(root)`**。
- **正确做法 / 预防**：动手前产出「模块挂载矩阵」（谁自动挂、谁必须业务挂：`Res` / `Input` / `Net` / `Data`）+ 启动顺序（`reference/engine-mental-model.md` §1 照抄）；第一件事是"把资源加载起来并打日志证明"。

## T2. 把"骨架能跑"当成果交付 → 被判"半成品"

- **现象**：链路通了（能登录 / 能进图 / 位置同步），但**没操作、没相机、没动画、UI 是 OnGUI 调试字**；而且**一打开就直接站在游戏场景里**。
- **正确做法**：**三段一次交付** —— ① 启动 / 菜单 / 创角链路 ② 首场景全部内容（场景 / 操作 / 相机 / 动画 / UI / 战斗 / 音效 / 复活）③ 游戏内流程（暂停 / 结算 / 回主菜单）。
- **预防**：按 `patterns/game-demo.md` §0.0c 的**原版系统清单**开工就贴进计划逐项打勾，缺项不许交付；菜单链路照 `patterns/client/app-flow.md`；`reference/game-delivery.md` §2 的 16 条铁律。

## T3. 做一项汇报一次

**正确做法**：只在 ① 被阻塞必须问用户 ② 全部做完 时说话，中间不播报进度（`SKILL.md` 铁律 3 / `reference/game-delivery.md` §2 第 9 条）。

## T4. 没有本地碰撞就做第三人称操作 → "被拽回来"的六环链条

- **现象**：往前走就被拽回原点；按 WASD 看着不动。
- **根因链**：客户端**完全没有碰撞**（连角色胶囊的 collider 都删了）→ 能穿墙 / 出图 → 服务端按地图拒绝 → 本地预测与服务端越差越大 → 被硬贴回。
- **正确做法（缺一不可）**：① **同一份地图数据**给客户端（引擎烘焙器一次写服务端与客户端两份）；② 客户端**本地碰撞解算**：半径 8 向采样 + **分轴滑墙** + **扫掠细分（每段 ≤0.25m）**；③ 上行带**输入序号**，服务端拒绝时**回校正（带 ack）**，客户端「置权威值 + 丢弃已确认 + **回放未确认**」；④ **未进图 / 断线必须停发**（否则网关按 `unauthenticated` 拒绝并刷屏）。
- **预防**：三件套齐全（`reference/engine-mental-model.md` §3 / §5）。

## T5. 相机凭直觉做 → "被遮挡时不会避障"

- **现象 / 根因**：把 `MinDistance` 当**硬下限** ⇒ 被挡时机位仍留在墙里；只探一条射线 ⇒ 墙沿露缝。
- **正确做法**：多高度探针取最小 + **被挡允许拉到 0.2m** + `CheckSphere` 重叠兜底 + 收缩快 / 恢复慢 + 贴脸隐藏角色 + 机位不钻地。**动手前先搜标准做法**（`reference/engine-mental-model.md` §5 第 3 条）。

## T6. 写死了"上帝视角"还不自知

- **现象**：相机 `position = 角色 + (0,18,-14)`、`Euler(55,0,0)` ⇒ 用户："我进去是上帝视角，WASD 移动不了"。
- **正确做法**：有角色就**必须**第三人称（或第一人称）；pitch / FOV / 距离 / 灵敏度一开始就定，场景初始机位也按第三人称摆（写进《参考规格》）。

## T7. 重复登录 / 双实例 → 两个客户端同账号互相拽回

- **现象**：日志**每条出现两次**；服务端大量未鉴权拒绝；位置来回跳。
- **根因**：① 场景里有**第二个 Bootstrap**；② 后加的重连逻辑**把首次登录也触发了一遍**（旧绑定被顶掉却仍在发消息）。
- **正确做法**：`Awake` **单实例守卫**（多于 1 个自毁）；`LoginFlowAsync` 加**重入保护**；`OnConnected` 只在"曾登录且本连接未绑定"时重登；**服务端要有"同账号顶号"踢旧连接**。

## T8. 改了场景几何却没重导地图

**现象**：客户端看得见墙、服务端不挡（或反过来）。**正确做法**：**几何变更 = 必须重新烘焙**；烘焙器一次写服务端与客户端两份；这条写进项目 `constraints.md`（`reference/engine-mental-model.md` §4「地图 / 场景」行）。

## T9. 靠"看着像"验收

**现象**：AI 说"已经好了"，用户说"按 WASD 不动"。**正确做法**：**运行时自证**（`eval_file` 打印对象状态）+ **探针消息**（服务端权威答复）+ **截图**（含 HUD，PNG + 颜色多样性校验）+ **既有回归测试**；交付说明只能引用这些证据（`experience/verify-recipes.md`）。

## T10. 高频失败日志不降频 → 刷屏

**现象**：一次断线刷出数千条 `unauthenticated` / 回包失败。**正确做法**：高频路径"首次 + 每 N 次"，精确次数交给 metrics；**改引擎要留痕**（根因写进代码注释 + 回归用例；业务 `constraints.md` 写清依赖的 `文件:方法` + 回归方式），见 `patterns/engine-fix.md`。

## T11. 低级几何错误（半格偏移 / 单位差异）

**现象**：模型放到"格角点"而非"格中心" ⇒ 整图偏移半格，探针在建筑外沿判"可走"；第三方 FBX 单位不一致 ⇒ 100 倍大或半埋。**正确做法**：**一律量测**（`Renderer.bounds` 反算缩放 + 按包围盒贴地 + 传格中心），写完用"点探针"验关键点（`reference/engine-mental-model.md` §6）。

## T12. 没分层 → Bootstrap 上帝类

**现象**：一个文件里同时有登录、实体视图创建 / 销毁、模型加载归一化、动画装配、HUD 刷新、热键 / 探针、相机装配 ⇒ 改一处要动同一文件，一次网络异常引发全功能瘫痪。**正确做法**：`Def / Core / Module（每系统一个）/ UI / App` 五层，依赖单向，模块只暴露一个门面接口，**App ≤ 200 行**（`reference/architecture.md`，含 7 条反耦合自检 grep）。

## T13. 工具用错：前台等 batch、被"项目已在编辑器中打开"卡住

**正确做法**：**驱动正在运行的编辑器**（`unity status` → `eval_file` / `editor_play` / `capture_game_view` / `recompile_status`）；长任务后台起 + 轮询；console 先落盘再正则取 `"message"`（`reference/unity-cli.md` §8.1）。

## T14. 只"跑通"就交付，从没和参考游戏比过（★ 最贵之一）

- **现象**：功能全在、日志全绿、自证数字也对，用户看一眼："这不像 XX" —— 菜单层级 / HUD 位置 / 手感 / 配色全不对。
- **根因**：把"功能验收"当"交付验收"；审查只看了数字 / 日志，**没看画面**。
- **正确做法**：① 动手前**必须有参考游戏名**（没给就问用户要）；② 参考截图 + 自己的**同角度**截图一一配对；③ 逐项只允许写 `一致` / `不一致（差在哪）`；④ **一项不一致 ⇒ 该版本不可交付**，改 → 重截 → 再对照，**循环到全部一致**。
- **预防**：`SKILL.md` 铁律 2 + §6 第 3 条；`patterns/game-demo.md` §0.0 第 0 / 4 步；`reference/design-review.md` §3.6。

## T15. 把 `go vet` / `go test` 当前台秒级判据跑 → 超时被杀，一条判据都没拿到

- **现象**：`go build ./...` 秒回，`go vet ./...` / `go test ./...` 几十秒不返回；换 `-vet=off` / `-c` / 缓存目录都没用；前台超时杀掉 ⇒ 报告只能写"没跑成"，更糟的是把"被杀"当"通过"。
- **根因**：**宿主 / 杀软层面的 I/O 等待**，不是"缓存没热"（换缓存位置、换包大小都复现；`go build -o <exe> .` 却能跑完）。
- **正确做法**：① **Go 判据交给后台长任务收**（后台起、输出重定向到文件、跑完再读）；**前台超时不算结论**，⛔ 超时后不反复重试同一条。② 只要**产物真的重建**（`-o` 产物 mtime **晚于**源文件），"go build 通过"就算拿到。③ **拿不到就如实写"未取到"**，⛔ 不许写成"通过"。④ ⛔ 别把 `GOPATH` 指到空目录排缓存（会强制重下全部依赖）。

## T16. "某个状态只存在 N 秒"时，先算**获取一次要多久**

- **现象**：`editor_play` 后连续两次 `eval_file` 都落在 `Main`；改试 `LoadScene("Boot")` + `Time.timeScale = 0` 按住画面，拍到的是**登录页**，还覆盖了同名取证图。
- **根因**：① 启动画面停留是引擎自带 `Timer.After(...)`，**不吃 `Time.timeScale`**；② 真正跑不赢的是**进程往返**：窗口 2 s，而 `unity command eval_file` 起进程 + IPC 要 1.5–2 s。
- **正确做法**：改用 `run_script` 的 **async 入口** —— 同一进程里 `LoadScene("Boot")` 之后用**真实时间** `await Task.Yield()` 等 0.6 s 再截图：
  ```bash
  unity command run_script --file <root>/.ai-tmp/drivers/xxx-boot.cs \
        --entry XxxBoot.Capture --timeout_ms 30000 --project-path <root>/client
  ```
- **预防**：获取耗时 ≥ 窗口 ⇒ ⛔ 别用逐次起进程的命令，改用一次跑完的长任务（`run_script` / 后台 loop）→ `reference/visual-loop.md` §8.2。

## T17. "改一个显示参数 → 立刻截图" = 整条序列逐张错位一格

- **现象**：每张帧都比文件名所写的配置**滞后一格**（"设完立刻拍"拍到的是上一态）⇒ 读数已被污染，而自检完全看不出来。
- **根因**：把「改参数」与「截图」放在**同一次 eval** —— `CaptureGameView` 取的是**上一帧**已渲染好的后备缓冲，**不会为你重绘**。
- **正确做法**：**改一步、拍一步**（两次 eval）。术后自检：两张**没有任何状态变化**的连续帧如果长得完全不同 ⇒ 截图滞后 —— **一条不需要知道机制就能判的判据**（同一件事见 `reference/visual-loop.md` 第八节）。

## 静默失败三条（**编译不报错 / 日志不报警**）

> 与上面 17 条的区别：那 17 条至少**看得到**症状（报错、卡住、被骂），这三条**一条日志都不给你**
> ——「组件是 null」「画面空白」「内存暴涨」，**编译期全是绿的**。
> ⇒ 只能靠**运行时判据**抓（节点树读数 / 计数 / 唯一色数），⛔ 不能拿"编译过了 + 我在代码里写了"当证据。判据怎么采见 `scaffold/probe-harness.md`。

### S1. 预制体的 `m_Script` 指向 `fileID: 0` ⇒ 组件运行时为 null

- **症状 / 根因**：面板 / 组件运行时为 null、`GetComponent<T>()` 拿不到，**编译期零报错**、Play 也不抛异常。根因是**一个 `.cs` 里放了多个 `MonoBehaviour`** —— Unity 只解析**与文件名同名的那个类**，其余挂不上；序列化进预制体就落成 `m_Script: {fileID: 0}`。
- **判据**：① 离线：**一个 `.cs` 一个 `MonoBehaviour`**（逐文件数 `: MonoBehaviour`，>1 即违规）；② 离线：对预制体 grep `m_Script: \{fileID: 0\}`，命中即违规；③ 运行时：逐个打印 `Game.UI.Get<T>()` / `GetComponent<T>()`，**拿到 null 就 `Error`** —— "代码里写了"不算，**活节点树上的读数**才算。

### S2. `AudioListener` 挂在会被切换的场景相机上 ⇒ 切场景刷屏、内存暴涨

- **症状 / 根因**：每次切场景同一条告警每分钟成百上千条、日志十几分钟涨到几十 MB；`AudioListener` 随**场景相机**销毁 / 重建 ⇒ 切换瞬间 listener 数变成 0（或 ≥2），引擎每帧告警。画面本身正常，容易被当成"日志有点多"。
- **判据**：① 机械：`AudioListener` **必须挂常驻物体**（`DontDestroyOnLoad` 根物体 / Bootstrap），⛔ 不许挂场景相机；② 运行时：跨场景采样 **listener 数恒为 1**（0 或 ≥2 打 `Error`）；③ 日志：**同一告警的单位时间出现次数**要能被断言。

### S3. 面板栈 `CloseAll()` 之后 `Transition(同一个状态)` 是 no-op ⇒ 空白屏且零日志

- **症状 / 根因**：**画面空白 + 一条日志都没有**。状态机对"切到**当前所在状态**"是 no-op；UI 的 `Open<T>` 在注册表**已有该类型**时直接走 OnOpen 返回（不新建、不报错）⇒ 看起来像界面挂了却无从排查。
- **判据**：凡是"**先清面板、再靠状态切换把界面带回来**"的地方，**必须先判当前状态**：同状态 ⇒ **自己显式 `Open<该面板>()` 并打一行日志**（"界面已重建"）。机械判据 = 这条路径上**必有一行重建日志**，**没有就判红**；"整个路径零日志"本身就是最强症状，⛔ 不许当"没报错 = 正常"。

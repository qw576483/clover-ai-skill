# Game Demo 一键交付 SOP（**原版级完整成品**）

> 回答："帮我实现一个 XX 游戏 / demo / 玩法原型"进来后，怎么一步步产出**和原版一模一样的完整成品**：启动画面 → 主菜单 → 创角/选角 → 读条进图，到首场景全部系统，能编译、能连服，**画面 / 操作 / 动画 / 音效都是成品级**。
>
> **起点不是零前提**：动手前先看 ① **本项目自己**的 skill → ② **本项目里**已有的同类代码（沿用其 API / 模块名 / 入口 / 目录）→ ③ 才用本文示例。项目已有实现时**冲突以用户项目为准，⛔ 禁止照抄示例**（示例只给形状）。
> ⛔ **新建项目红线**：工作区里**别的** `clover-project-*`（含 `client/`、`tools/ai-skill/`、`策划/验收表.md`、`Assets/Editor/*.cs`、素材）**不许读 / grep / 照抄**；新项目一切从 0 自己设计，通用形状只从引擎源码、`clover-doc`、本 skill 的 `patterns`/`scaffold`/`experience` 取。**两个例外**：① 用户本轮点名"参考某个已有工程"；② [游戏 Demo 清单](https://github.com/qw576483/clover-doc/blob/main/ai/game-demo.md) 里列出的成品工程（可对照做法与形状，⛔ 领域内容不许沿用）。
>
> **第零 / 第一铁律先于本文一切规则**（`SKILL.md` 开篇）：1:1 复刻、不许发挥；必须做完才交付。没有参考物时按 `SKILL.md`「初始化清单」第 3 条办；开工前把需求问清是鼓励的（第 10 条），被禁的是"问要不要做 / 问进度 / 求许可"。
>
> **五条底线（压倒其它一切考虑）**：
> 1. **交的是完整成品，不是半成品更不是骨架** —— ① 启动/菜单/创角链路 + ② 首场景全部内容 + ③ 游戏内流程，三段缺一不可；**没有一个完整游戏是"打开就直接站在游戏场景里"的**。⛔ 纯色块 / 内置 Cube / "动画留空实现" / "框架已预留" 都不算交付。
> 2. **像原版** —— 原版的系统 / 菜单 / 手感 / 数值 / UI 布局 / 音效时机逐项做出来；§0.0c 清单里**空着的行就是没做完**。
> 3. **有角色就必须有操作** —— 第三人称（或第一人称）相机 + 移动必须真的可用：WASD 生效、鼠标能转视角、跟随不抖不穿墙。⛔ 不许上帝视角俯视。
> 4. **用户必须"看得到"工程** —— 登记进 Unity Hub 并置顶，交付说明写清「Hub 里的名字 + 绝对路径」（`reference/unity-cli.md` §6.1）。
> 5. **按成品标准做** —— 优先**直接采用同类参考游戏的成套素材**（画风统一）；**本项目非商用 ⇒ 不设许可门槛，能下到合适的就用**（记一行来源）；只有"登录 / 会员 / 付费 / 点按钮"才让用户下。占位只是兜底，不是交付形态。
>
> **不许砍范围**：时间 / token / 规模 / agent 数量都不是理由 —— 复杂就拆多 agent（`patterns/multi-agent.md`，10 个 100 个都行）。**交付的 demo 就是引擎能力的唯一证明**：用户若觉得连"菜单 + 创角 + 首场景"都做不出来，压根不会用这套引擎。
> **交付前自己跑一遍（产出为主，不办验收）**：**不确定就**编译 → 用一条链路进 Play 把关键路径跑一遍（⛔ 不逐项进出）→ `数值类` 看日志行、`表现类` 看一眼截图，见 `SKILL.md` §4 与 `reference/unity-cli.md` §8.1。⚠️ "一条链路"说的是"别逐项重复"，⛔ **不是次数上限**：没跑完 / 新批次 ⇒ 照常再进。

## 0.0 参考游戏保真协议（**动手前必做**；用户没给游戏名就先问）

> 目标：玩家一眼认得出"这就是 <A>"。**手感 / 操作 / 镜头 / UI / 动画 / 音效 / 场景**都按 A 来。⛔ 不许凭印象开工，也不许说"不知道 A 什么感觉"就算了 —— 去搜。

**第 0 步：必须拿到参考游戏名**（用户没给 → **停下来问**）
- 用户点名了 A 就用 A；**只报品类也要问**（品类不是参考物）。⛔ 禁止"我自己挑个同类型的吧" —— 做出来必然"不像"，等用户看到再返工是最贵的路径。
- 拿到名字后先产出 `策划/策划案/{A}参考规格.md`，再写代码。

**第 1 步：研究 A，把"可实现的规格"抄成文档**

```bash
# 多搜几轮、中英文都搜；搜的是"能落成代码的量"，不是剧情
web_search "<A> 操作手感 movement 数值 移动速度 武器参数 镜头 FOV UI 布局 音效"
web_search "<A> gameplay mechanics movement speed jump height weapon stats UI layout"
```

产出 `策划/策划案/{A}参考规格.md`，至少覆盖：

| 维度 | 要抄下来的 |
|---|---|
| 操作 | 键位、第一/第三人称、鼠标灵敏度、有无加速/惯性/蹲/跳/冲刺 |
| 镜头 | 视角高度、FOV、后坐力/晃动、是否有瞄准缩放 |
| 数值 | 移动速度、跳跃高度、射速/伤害/冷却、回合或关卡时长 |
| UI | 屏幕各位置显示什么、字体层级、准星/血条/弹药样式 |
| 表现 | 动画状态机（idle/run/attack/hit/death）、特效、音效触发点 |
| 节奏 | 一局多久、胜负条件、核心循环、复活规则 |

**第 2 步：素材必须来自 A（或 A 的同源）** —— 见 §4.0 四级链。

**第 3 步：逐项对照实现（这张表就是"完成度"）**

| 项（来自 A） | A 的表现 | 我们的实现 | 状态 |
|---|---|---|---|
| 移动速度 | 6.0 m/s | `PlayerMotor.RunSpeed = 6` | ✅ |
| 镜头 | 第三人称后视 | `ThirdPersonCamera`（pitch 16，可调） | ✅ |
| 攻击 | 左键挥砍 + 命中反馈 | 已播攻击动画；**伤害/命中未做** | ❌ 待做 |

> **空着的行 = 还没做完 ⇒ 不许交付**（⛔ 不需要再另填证据列 / 类别列 / 覆盖矩阵）。

**第 4 步：交付前自审「像不像 A」（不通过 = 不可交付）**
1. **准备对照物**：A 的截图 / 视频切片（启动 / 主菜单 / 创角 / HUD / 战斗 / 场景 / 结算）存 `策划/参考图/`，自己的**同角度**画面存 `策划/自审对比/`，**放在一起看**（多屏才考虑拼联络图，`reference/visual-loop.md` 第八节）。
2. **逐项对照**，每项只写 `一致` / `不一致（差在哪）`（⛔ 不许写"基本一致 / 大致像"）：菜单层级与按钮文案、创角字段与布局、HUD 位置/比例/配色/字号、移动速度与转身、攻击节奏与镜头、动画切换、命中反馈、场景风格与色调、音效时机、节奏时长。
3. **判定**：只要有一项不像 ⇒ 该版本不可交付 → 改 → **重新截一张再看**，**循环到像为止**。
4. **必须看图**：`表现类` 要真的看一眼自己的截图（`reference/design-review.md` §3.4）；**数字全对但画面不像 = 不合格**。
5. ⛔ 禁止把"不一致"写进交付说明当免责（"略有差异 / 后续可优化" = 没做完）。

## 0.0b 策划自审：先出《行为 → 表现规格》表（**写任何代码之前**）

「一键出游戏」不是"把功能堆出来"，而是"把一个**说得清的玩法**做对"（完整模板与感官验收清单见 `reference/design-review.md`）：
1. 用 5 问说清这个游戏（类型/参考游戏、核心循环、每个行为的表现、数值与节奏、哪些"不行"是设计内）；
2. 把核心循环里**每个行为**填进《行为 → 表现规格》表：**画面 / 动画 / 声音 / UI·数值反馈 / 网络 / 验收方法**；
3. 不知道就先搜参考游戏，搜不到就写"不确定"并问用户 —— ⛔ 不许凭感觉糊；
4. 这张表**同时是收尾清单**：交付前对着它跑一遍关键路径（`数值类` 看日志行，`表现类` 看一眼截图）。

> 反例（真实踩过）：动画状态机没接好（一直播第一个动作）、攻击无命中反馈、敌人没血条、占位胶囊体当敌人没隐藏 —— 每项都"能跑"，没一项像游戏。

## 0.0c 原版系统清单（**动手前先列，逐项做完，不许砍**）

> 这不是可选清单，是**交付合同**：动手前把 A 的系统清单写进 `策划/策划案/{A}参考规格.md`，一行一个系统，写清「做法 + 验收方法 + 状态」；**空着的行 = 没做完，不得交付**。

**列法**：照原版从"打开游戏"到"玩完第一个循环"走一遍，每步都记下来：
1. **启动链路**：启动画面 / Logo / 厂商字 → 主菜单（开始 / 继续 / 设置 / 退出；联机加登录 / 注册）→ 创角（名字 / 外观 / 职业 / 属性）或选角 → 读条 → 进游戏；
2. **游戏内**：地图（含**随机地形**）、NPC 与**对话**、商店、普通怪、**精英怪与词缀**、Boss、技能与技能树、背包与装备、掉落与拾取、任务、传送 / 回城、存档、图鉴；
3. **游戏内流程**：暂停菜单、设置、结算、回主菜单、退出；
4. **联机类**：登录 / 注册、匹配 / 房间列表、选阵营、观战、记分板、断线重连。

**示例（不是模板 —— 按 A 的真实内容列）**：

| 游戏 | 必做清单（节选） |
|---|---|
| 暗黑破坏神 2 | 启动画面 / 主菜单 / **创角（职业·外观·属性点）** / 进游戏 / 地图与**随机地形** / 普通怪 / **精英怪与词缀** / 技能与技能树 / 背包与装备 / NPC 与**对话** / 商店 / 掉落 / 传送（回城书）/ 存档 / 回主菜单 |
| CS | 主菜单 / **选阵营** / 买枪与经济 / 地图 / 射击与后坐力 / 命中反馈 / 观战 / 联机匹配 / 记分板 / 回合结算 |
| 梦幻西游 | 启动 / 登录 / **创角（门派·加点）** / 主城 / NPC **对话**与任务 / 背包 / 商店 / 战斗（回合）/ 组队 / 结算 |

**硬规则**：⛔ 不许用"范围太大 / 时间不够 / 下次再做 / 框架已预留"结案 —— 做不完就**拆多 agent**，不是砍范围；清单项**允许排优先级但不允许消失**；原版**手感 / 数值 / UI 布局 / 音效时机**同样进清单。

## 0. 范围：**原版级完整成品**（不做 MVP、不做骨架）

用户的"一键出 <某游戏>" = **交付这个游戏的完整成品**，三段都要有：

| 段 | 内容 | 缺了会怎样 |
|---|---|---|
| **① 启动与菜单链路** | 启动画面 / Logo → 主菜单 → 创角（或选角）→ 读条进图 | 一眼假 |
| **② 首场景 / 首关卡完整版** | 真素材 + 真动画 + 真操作（手感对）+ 真 UI + 真音效 + 完整闭环 | 能跑不能玩 |
| **③ 游戏内流程** | 暂停菜单 / 设置 / 结算 / 回主菜单 / 退出 | 进去出不来 |

菜单与流程编排的写法（状态机 + 面板 + 场景三元组）见 `patterns/client/app-flow.md`。

**判定口径（硬）**：**完整版** = 从启动到进图链路走通（启动画面 → 主菜单 → 创角/选角 → 读条进图）+ 点进去能玩一整轮（操作 → 战斗/交互 → 反馈 → 结算/循环/回菜单），视觉 / 听觉 / 手感都像那么回事；**不是完整版** = 直接进游戏场景 / 菜单点了没反应 / 能跑但没动画·没音效·操作别扭·UI 是调试字·场景是白盒 ⇒ **半成品，不许交付**。允许花很久（不设时长上限），但必须多轮实测；确定做不到的部分当场说清"为什么做不到"，⛔ 不许偷偷降级成最小可用。

### 0.1 交付纪律：**三段一次做完，全程只在"做完"时汇报一次**（硬规则）

**三段（含 §0.0c 全部内容）一次性交付** —— 不存在"阶段 1 = 骨架 / 阶段 2 = 补内容"这种切法；⛔ 不许把"剩下的下次再做"写进交付说明。**起手就把 ①②③ 全部内容 + §0.0c 清单列入待办，做到全部完成再说话**；允许做很久，⛔ **宁可不交付，也不交半成品**（物理上限靠换手接力跨过，见 `SKILL.md`「谁来做」）。

```text
本轮（一次性做完）：三段全部内容
  ① 启动与菜单链路（启动画面 / 主菜单 / 创角或选角 → 读条进图）
  ② 首场景全部内容（地图与引擎烘焙碰撞 / 操作 / 动画全接线 / 真 HUD / 战斗闭环 / 音效 / 复活循环 / §0.0c 每一项）
  ③ 游戏内流程（暂停 / 结算 / 退出 / 回主菜单后能再进一次）+ 分层分模块 + 按类别取证
      ↓  一次完整交付说明（只有这一次汇报）
下一轮 = 用户看过成品之后提出的新内容（更多关卡 / 角色 / 系统…）
```

⛔ 禁止"先生成个能跑的骨架 → 停下来等用户确认 → 再补动画音效"；⛔ 禁止"做完一项汇报一次"（过程中只在**被阻塞必须问** / **全部做完**两种情况说话）；用户实测反馈不通过 ⇒ 改成他要的效果（属返工，不算新一轮）。
**⛔ 不许把"分层分模块"当建议**：一个系统一个模块、依赖单向、**App ≤ 200 行**、UI 不引用业务模块、网络只走 Net 门面（`reference/architecture.md`）。**要自查分层时**（`SKILL.md` §4：你不确定 / 用户反复报同一条）**才跑 §4 的 7 项，并把数字写进交付说明**（⛔ 默认不跑）（App 行数 / 跨模块耦合命中数 / UI 引用业务模块命中数 / 业务直连网络命中数 / 裸事件名命中数 / **硬规则命中数** / **临时文件散落数**）—— **数据说话，不许只写一句"已分层"**。

### 0.2 能力归属判定：先分清「引擎缺口」还是「业务产物」（四桶）

用户问「能不能做 XX」，或你要说明「缺什么」时，**必须先把缺的东西归到下面四桶之一** —— 否则极易把业务产物误报成"引擎不支持"，让用户以为要改引擎（**最伤信任的误报**）。

| 桶 | 含义 | 谁写 | 例子 |
|---|---|---|---|
| **A 引擎已实现** | 拿来直接用 | 引擎 | AOI（**三维球体视野，默认开**）/ 寻路（2D 网格 + **3D 分层**）/ 碰撞（2D 宽相 + **3D 宽相与立体弹道**）/ 物理 / 伤害内核 / Buff / 帧同步 / 房间生命周期 / 数据层 / 配表 / 单机启动 / **地图管线**（Unity 烘焙 → CloverMap 二进制 → 服务端 `NavGrid3`+`Collider3` / 客户端 `Game.Map`） |
| **B 引擎显式留了口** | 引擎代码里有**注册位 / 接口**，且文档写明"业务实现" | 业务（引擎在等） | **`room.Kernel`**（状态同步内核）—— **全仓仅此一项** |
| **C 业务自己写** | 引擎**不提供、也不需要提供**；业务用 A 类能力 + 通用 API（含 **Unity 原生 API**）自行实现 | 业务 | 回合出手序 / 匹配 / 开局 / 房间列表 / AOE 形状 / 命中闪避 / 属性聚合 / 房间人数上限 / 背包 / 卡牌 / 抽卡 / 任务 / 邮件 / 商城 / 平台 SDK / **分包** / UI / 数值 / **客户端 3D 表现与操作** / **本地预测解算**（引擎只给"这一格能不能走"，手感归业务） |
| **D 必须改引擎** | 业务绕不开 | 引擎 | **当前为空**（服务端立体空间已实现：三维视野 / `collide.Grid3` / `SweepCCD` / `Raycast` / `NavGrid3` / `mover` 重力·跳跃·飞行）。**客户端 3D 不算 D** |

**规则**：
- **B 与 C 的唯一区别 = 引擎有没有替你留一个「注册位」**；`room.Kernel` 是引擎声明好的接口（填实现即可），而**回合出手序 / AOE / 匹配**这类引擎**既没留口也不需要留**。**两者都不改引擎。**
- **A / B / C 一律不许说成"引擎不支持"**（C 桶最容易被误报），也不许把 C 说成"引擎留了口"。
- **只有 D 桶**可以回"需要改引擎"，且必须先说清量级、拿到用户确认再开工。**当前 D 桶为空 ⇒ 对任何玩法默认「引擎够用」**。
- 拿不准用一把尺子：**「数据层 + `Timer` + 房间域 + etcd 发现」够不够搭出来？** 够搭 = C；只差一个引擎**已声明的接口** = B；接口都没有且业务绕不开 = D。
- ⛔ **典型误判（不许再犯）**：把「回合出手序 / 匹配 / 状态同步内核 / 命中闪避 / AOE / 场景 tick / 属性聚合」说成引擎缺口；把「背包 / 卡牌 / 抽卡 / 任务 / 平台 SDK / 分包」说成引擎不支持；把「**客户端 3D 相机 / 角色控制 / 物理 / 射线**」说成引擎缺口 —— 业务在自己的 Unity 工程里可直接用 Unity 原生组件。**立体空间也不再是引擎缺口**（引擎已提供三维视野 / 三维碰撞 / 分层寻路，业务只需**建图**，属 C 桶）。
- 支持度**只给二值**：**✅ = D 桶为空（引擎够用）** / **❌ = D 桶非空（需改引擎）** —— 按当前状态**一律 ✅**。⛔ 不要用"骨架支持 / 部分支持"这类中间档，也**不要把量产规模结论混进"首场景支持度"**里。
- 引擎侧小瑕疵（`SceneBeat` 不自动驱动、`pathfinding.FindPath` 只支持单单位）**不属 D 桶**（业务可绕开）。
- **客户端本地预测 / 回滚由业务自己做**（引擎只提供"服务端权威 + 客户端插值"）—— 属 **C 桶**，**不是引擎缺口**。
- 归属判定与逐游戏证据表随各项目保存在项目自己的 `策划/` 下（不在本 skill 内）。

## 1. 触发与适用前提

触发词：用户说"做一个 XX 游戏 / 实现一个 XX / 搭一个 XX demo / 帮我把 XX 做出来"。
前提（满足才走本 SOP）：需求落在 Clover 全家桶内（`clover-server-engine` + `clover-client-unity-engine`）；跑在用户已有工程上，或新起 `clover-{name}` 工程。

**工程初始化**：新工程一律以 **`scaffold/new-project.md`** 为唯一依据（每个文件的完整内容模板，字段已逐条比对引擎源码确认，可直接复制）。
- import 路径用 `{module}` 占位，生成时替换为实际 module 名（如 `clover-cq`）；
- 若用户明确要求"跑在某已有工程上"，沿用该工程自己的结构与配置。

## 1.5 前置：先判定横版/竖版，再判定形态，最后才决定「要不要服务器」（**顺序不许反**）

### 第 1 步：判定横版 / 竖版（屏幕方向；**这一步不做完，连 UI 草图都别画**）

规则见 `SKILL.md`「初始化清单」第 1 条。

| # | 问题 | 怎么看 |
|---|---|---|
| 1 | **原版是横版还是竖版？** | **联网搜一轮**（`<游戏名> 横版还是竖版` / `<game> portrait or landscape`），再看 A 的**官方截图**：宽 > 高 = 横版，高 > 宽 = 竖版 |
| 2 | 用户本轮明说了吗？ | 出现"竖版 / 横版 / 手机竖屏 / 竖构图"才算 |
| 3 | 画布参考分辨率？ | 竖版 `1080×1920`；横版 `1920×1080` |

**判定规则**：原版是竖版 ⇒ **整套 UI 按竖版做**（内容框宽 ≤ ~1000、上下排布、角锚点）；⛔ 不许"照着 1920×1080 横屏模板拼一版"，⛔ 不许用 `preserveAspect` 把竖图塞进横画布了事。
**落地三处**：① `ProjectSettings.asset` 的屏幕方向与 `defaultScreenWidth/Height`；② 引擎 `CanvasScaler.referenceResolution`（`CloverPresentation.ReferenceResolution` 默认 1920×1080，竖版项目在业务侧设成 1080×1920）；③ **每个面板的布局常量**。判定结果与形态**同一处**写进 `策划/策划案/{A}参考规格.md` 顶部，**只判一次**。

### 第 2 步：判定形态（**这一步不做完，后面一个字都别写**）

规则见 `SKILL.md`「初始化清单」第 2 条。落地到本 SOP 就是三个问题：

| # | 问题 | 怎么看 |
|---|---|---|
| 1 | **原版是什么形态？** | **联网搜一轮**（`<游戏名> single player or multiplayer`）—— 这是**第一依据** |
| 2 | **用户这一轮明确要求联机了吗？** | 出现"联机 / 多人 / 服务器 / 对战 / 排行榜 / 房间 / 匹配"才算 |
| 3 | **联网方式是什么？**（仅联机时需要） | 权威服务器 / 局域网 / P2P / 大厅+房间 / 直连 IP |

**判定规则**：
- 原版是**单机** → **做单机**：不建 `server/`、不调 `CloverNet.Init`、**不查服务器环境**、不跑 `env.exe`；交付说明**首行**标注「单机版」，其余交付标准**一点不降**。
- 原版**同时有单机与联机两种模式**（如暗黑破坏神 2）→ **默认做单机模式**；用户点名要联机才做联机。
- 原版是**纯网游**（MMO / 对战竞技 / 大逃杀）→ 做联服，此时才走第 3 步。
- **拿不准**：先搜；搜完仍拿不准，**问用户一句话**。⛔ 禁止"一边拿不准、一边反复探测本地服务器环境" —— **反复自检 = 已经判错方向的信号**。
- 判定结果写进规格顶部「**形态**」一节并**只判一次**，中途不许反复改变、不许反复自检。

### 第 3 步：只有**形态为联机**时，才做服务器环境自检

**触发条件（两条同时满足）**：① 第 2 步判定为联机；② 马上要写 C2S 回路代码。**单机任务整段跳过。**

```bash
clover-server-tools/windows-env/core/env.exe info    # 环境在不在 / 组件就绪没
clover-server-tools/windows-env/core/env.exe start   # 没起就起
```

| 检查结果 | 处理 |
|---|---|
| env.exe 在，etcd/nats/redis/mysql 全就绪 | 正常开工 |
| env.exe 在，组件未起 | `env.exe start` 后 `info` 复检 |
| 组件缺失（未下载） | 按 `reference/server-env.md` §2 让**用户**下载，AI 只做校验 / 放置 / 启动 |
| `windows-env/` 整个不存在 | 环境未安装 → **停下来告诉用户**，不许绕过 |

**铁律：不许静默降级成"单机 / 离线 / 模拟模式"。** 以下行为一律算交付失败：悄悄把联服玩法改成"AI 随机出拳 / 本地算结果"；客户端加"服务器不可用就自动切模拟模式"兜底；注释掉 `server.yaml` 里的 mysql/etcd/nats 依赖来"简化"；点名的模式只留空壳（"框架已预留，暂未实现"）。
**环境不可用时先把情况摆给用户、等回答再动手**，三选一：① 装 / 起环境（下载交给用户）；② 用户**明确同意**做离线版 ⇒ 才降级，且必须：联服代码留 TODO 不删 + 交付说明首行标注「⚠️ 离线版：联服流程未验证」+ `client/资源欠缺清单.md` 登记"联服验证"为待办；③ 只交服务端代码（`go build` 过）+ 编译说明，不起服。

## 2. 第 0 步：一句话需求 → 结构化假设

**不要只回一句"请再说详细点"。** AI 自行抽取并做合理假设，只对"玩法核心"必须与用户确认，其余写明"我按 XX 假设做了"，可自洽就开工。

| 字段 | 默认假设 |
|---|---|
| 玩法与胜负判定 | （必问：若整句都没有，停下来问一句） |
| 玩家规模 / 房间制 | 默认 2 人同房间、demo 单服 |
| 实时 or 回合 | 按玩法推：卡牌/棋类=回合，竞技=实时 |
| 数值与结算 | 默认简版：积分制，胜负广播 |
| 是否需要配表 | 默认不配（数值写进逻辑即可）；但"会被策划改 / 会随版本增长"的数据（道具·关卡·怪物·掉落）**必须走配表**，见 `patterns/table.md` |
| 是否要客户端界面 | 默认要：**真 HUD/面板**（`Resources/UI/{类名}` 预制体 + `Game.UI.Open<T>()`）；选"否"= 纯服务端 + 消息验证 |
| 跑在哪 | 默认新起 `clover-{name}`；或按用户点名的已有工程 |
| 美术/音频/动画规格 | 默认按 §4.0 找同类参考游戏的**成套素材**直接接入；角色动画**必须接线**（Animator + 真实 clip）、音效接入真音频；仅当确实**下不到**时才占位，且必须在回复首行高亮「此处为占位，非成品」 |
| 操作方式 | 有可操控角色时默认**第三人称**（WASD + 鼠标转视角 + 相机跟随）；纯 2D/卡牌按玩法定 |

交付物形态（回复模板）：

```text
玩法理解：……
房间：N 人，x 局定胜负
数据：需要/不需要落库（score / 胜负记录）
交互：WASD + 鼠标（第三人称相机跟随）
美术：采用 <素材包名>（许可 CC0/…）真素材；角色动画已接 Animator（idle/run/attack…）；音效已接入
UI：真 HUD（血条/信息/按钮），预制体在 Resources/UI/
我将按上述假设实现，其中「xx」请确认；其余可随时推翻。
```

**必须与用户确认**：玩法核心机制（必问）；**操作方式**（第三人称 / 第一人称 / 俯视）；skill 与 `clover-doc` 都查不到或有歧义时（**先查再问**：skill → clover-doc → 源码 → 问用户）；素材规格，**若某类素材到处都下不到**（含镜像 / 替代源）要在这里说明；是否需要特定尺寸的占位图（只在真找不到素材时问）；是否有特定 UI 布局要求（横竖屏 / 分辨率）。

## 3. 第 1 步：切分「逻辑」与「资源」

**逻辑 = AI 负责；资源 = AI 优先找现成素材并接入（能下就下），找不到才占位**：

| 逻辑层（AI 全做，零资源） | 资源层（AI 负责**接入真资源**） |
|---|---|
| 服务端：消息号 / schema / handler / 结算 / 广播 | 卡牌/棋子/角色 Sprite 与模型 → **先穷尽参考游戏 A 自己的素材**（闸门 3），拿不到再降级 |
| 客户端：UI 结构、按钮行为、网络收发、状态流转 | 按钮/面板美术、背景图 → 同上 |
| 表现：状态切换、胜负展示、数值刷新 | **动画 Clip（必须接线）+ 音效 BGM + 特效** → 优先随素材包自带 |
| 操作：相机 + 移动 + 输入（第三人称/第一人称） | 配表数据（策划后续填 / 调数值） |

> 右侧栏的目标是"**接进去能用**"，不是"登记进清单等用户换"。占位只出现在"该资源到处都下不到"这一种情况，且必须在回复首行高亮。

## 4. 第 2 步：逻辑先行，资源分级获取（**先穷尽 A 自己的素材** → 再同类 → 再兜底 → 再自产 → 最后占位）

### 4.0 资源从哪来（**硬闸门：必须先用 A 自己的素材**）

美术 / 音效 / 模型**不是一律占位**，交付目标是**成品级**；**本项目非商用 ⇒ 不设许可门槛，能下到合适的就直接用**。

> ### ⛔ 硬闸门（违反即交付失败）：级 ① 穷尽之前，禁止碰通用兜底素材
> **用户点名了 A ⇒ 目标就是"一眼认得出这是 A"。素材是这件事权重最大的项。**
> 1. **级 ① 是唯一首选，必须"穷尽"** —— 量化定义：**≥ 4 轮**不同关键词（中英各半）× **≥ 3 类站点** × 换过**格式/打包方式**。
> 2. **穷尽之前，禁止下载 / 禁止接入任何通用兜底素材**（KayKit / Quaternius / Kenney / 内置几何体…）。⛔ 不许拿"先做起来 / 别停工 / 能用就用"当跳级理由。
> 3. **调研必须落盘 `策划/素材调研.md`**（每轮：关键词 / 站点 / 拿到什么 / 为什么不可用）。**没有这份文件 = 闸门未通过，不许开始接资源。**
> 4. **A 的素材要"用户本机游戏文件 / 登录 / 会员 / 付费 / 点按钮"→ 走级 ④：先给用户清单并等用户**，⛔ 不许自己跳过 ①。Blizzard 系（MPQ/CASC）就属此类：解包工具公开，**本体文件只有用户有**。
> 5. **级 ③ 只有 ①② 都真的做不到时才允许**，且必须：① `素材调研.md` 写清原因；② **交付说明首行**高亮「⚠️ 未使用 A 的素材」；③ `资源欠缺清单.md` 登记"待换"。
> 6. **禁止把"下不动"说成"没有"**：换镜像 / Gitee 同名仓 / 压缩包直链 / 论坛附件，都试过才算数。

| 级别 | 做法 | 说明 |
|---|---|---|
| **① 用户点名的游戏 A 自己的素材（★ 唯一首选，必须穷尽）** | 原版 / 同源 / 复刻 / 官方 SDK / mod 工具 / 社区提取 / rip。关键词矩阵（**≥ 4 轮，中英各半**）：`<A> assets pack`、`<A> sprite sheet`、`<A> ripped assets`、`<A> extracted textures`、`<A> clone/remake open source`、`<A> mod tools`、`<A> resource extractor`、`<A> 素材 提取 解包 复刻 图集`。站点矩阵（**≥ 3 类**）：GitHub / Gitee 与镜像 / spriters-resource / 论坛（贴吧 NGA 3DM 游侠）/ CSDN 爱给 网盘直链 | 玩家一眼认得出。**直接用**（含 rip / 来源不明，非商用不设门槛），记一行来源。**拿不到就先去问用户（级 ④），不许自己跳过** |
| **② 同类游戏的成套素材**（**仅在 ① 穷尽后**） | 找**同品类**成熟素材包（角色 + 场景 + **动画** + UI + 音效**成套**） | **必须成套**（单件拼凑会画风割裂）；**通常自带动画**（正好满足"动画必接"） |
| **③ 通用兜底素材**（**仅在 ①② 都真的做不到时**） | 已验证可 `git clone` / 直链的 CC0 套件（KayKit / Quaternius / Kenney…，见 `reference/asset-sources.md` §2.2） | ⛔ 不许"先做起来"就跳到这里。用了必须：调研写原因 + **交付说明首行高亮** + `资源欠缺清单.md` 登记"待换 A 的素材" |
| **④ 让用户下（必须登录 / 付费时）** | 给**清单**：包名 + 页面链接 + 要下的文件 + 放到哪个目录（模板见 `reference/asset-sources.md` §5） | 只有这一级才麻烦用户；用户放好后 AI 重新扫目录自动接入 |
| **⑤ 自产（多模态才行）** | 前四级都失败时由**多模态模型**画图 / 切图 / 做模型 | 见 §4.0.1 多模态闸门 |
| **⑥ 占位（不算交付，最后手段）** | 空白图 / 纯色块 / 内置几何体 | 只在 ①~⑤ 全不成立时用；**必须登记进《资源欠缺清单》并在回复首行高亮**"此处为占位，非成品" |

> **优先搜现成素材，而不是自己画**；但**搜不到不等于不做** —— 继续往下走（自产 / 占位都必须有明确交代）。**能下载就别手搓** —— 玩家不会因为"这是 demo"就容忍纯色块。

#### 4.0.0 许可默认规则（用户的一键出游戏按**非商用**对待）

| 规则 | 说明 |
|---|---|
| **能用就用（不设许可门槛）** | CC0 / CC-BY / NC / 仅个人 / 来源不明 —— **都能用**；**成套**包优先（画风统一） |
| **唯一的门槛是"下不动"** | 需要登录 / 会员 / 付费 / 点按钮 ⇒ 走清单让用户下；**其余一律自己下**（含抓页面直链） |
| **别在许可上停下来** | 不为许可问用户、不把 `CREDITS.md` 当交付门槛、不因"来源不明"放弃合适素材 |
| **记一行来源** | 包名 / 来源 URL / 落地路径，写进《资源欠缺清单》（够用；**将来商用**再照它统一替换，见 `reference/asset-sources.md` §7） |

> **可复用的取值途径**（可 `git clone` / 可直链，不靠网页按钮）：官方 GitHub 上的 CC0 套件（如 **KayKit** 系列：城市 / 地牢 / 角色 / 中世纪地块）、Khronos glTF-Sample-Assets、Poly Haven（HDRI/PBR，CC0）、ambientCG（CC0）。**链接一律现场取得，⛔ 不许凭记忆编 URL。**

#### 4.0.1 多模态闸门（要"自产资源"时必过）

**走级别 ⑤ 之前，先自检能不能真的读图与出图**（判定标准见 `reference/game-delivery.md` §7）：

| 自检结果 | 动作 |
|---|---|
| 是**多模态**（能读图 + 能出图） | 走 ⑤：自己画 / 切图 / 建模型；产出**真实资源文件**放进工程 |
| **不是多模态**（纯文本模型） | **停下来，先让用户切多模态模型**并重发需求 —— 不许多模态能力缺失还硬做 |
| 用户**执意不切** | 才允许降级到 ⑥：空白图 / 通用模型占位；在《资源欠缺清单》里写明「因当前模型非多模态，未生成美术资源」，并给出「换多模态模型后可补做」的说明 |

⛔ **禁止**：非多模态时假装画了图、或把文件名 / 文字描述当成"已有资源"。

### 4.1 服务端

- **零资源**，完整实现 + `go build` 过 + `env.exe start` 后能起服。
- 全流程走 `patterns/{datadef,handler,mount,crossnode,signup-login}.md`，消息号段见 `reference/conventions.md`。
- **配表（有"会被策划改 / 会随版本增长"的数值时必做）**：三步闭环 —— ① AI 写源表 txt → ② `-pack` 反出 xlsx 交策划用 Excel 改 → ③ 打表出 tsv + 强类型代码。规则见 **`patterns/table.md`**：源表放 `<项目>/策划/数值文档/<名>_<后缀>.txt`，**表名必须带 `_cs` / `_c` / `_s` 后缀**（否则整表静默跳过）；读表用产物自带的强类型访问器（服务端 `table.Default.Xxx.Get(id)` / 客户端 `Tables.Default.Xxx.Get(id)`）；⛔ **禁止**把数值 / 掉率 / 关卡配置硬编码进 handler。

### 4.2 客户端（★ 工程必须用 unity-cli 创建，再写代码）

⛔ **禁止**手写 `client/Assets/Scripts/...` 目录树来"假装"是 Unity 工程 —— 没有 `Packages/`、`ProjectSettings/`、`.meta` 的目录 Unity 根本打不开。

```bash
# 1) 自检并确认 Unity 6（6000.x）；没装 CLI 就自动装（见 reference/unity-cli.md）
unity --version
unity editors list --format json

# 2) 创建真工程（模板 id 先查，不要猜；工程名固定 "client"、--path 传项目根）
unity templates list --editor 6000.0.47f1 --format json
unity projects create "client" --path "clover-{项目名}" \
  --editor-version 6000.0.47f1 --template com.unity.template.3d

# 3) 接入 Clover 引擎包：Packages/manifest.json 加一行
#    "com.clover.unity-engine": "https://github.com/qw576483/clover-client-unity-engine.git"
#    （要在工作区内联调引擎源码才换成本地路径，基准是 client/Packages/：
#      "file:../../../clover-client-unity-engine" —— 见 scaffold/new-project.md §2.2）
```

工程建好后再往 `Assets/` 里写业务脚本。**写任何网络代码之前，必须先创建 Def/ 目录**：
1. **先建 `Assets/Scripts/Def/MsgDef.cs`**：业务消息号（镜像服务端 `server/game/def/{msg,reply,push}.go`）；
2. **再建 `Assets/Scripts/Def/ProtoDef.cs`**：协议结构体（Request / Reply / Notify DTO）；
3. **然后才写 Network / UI 等业务代码**：引用 `MsgDef.Xxx` 而非硬编码消息号。

其他业务脚本（**成品级要求**）：
- **启动 / 菜单链路要做（硬约束）**：启动画面 → 主菜单 → 创角（或选角）→ 读条进图 → 暂停 → 回主菜单；⛔ **禁止**把游戏场景当应用入口。写法见 `patterns/client/app-flow.md`（`Game.Fsm` + `Game.UI` + `Game.Scene.Load` + 回菜单清场清单），菜单面板同样放 `Resources/UI/{类名}`。
- **UI/HUD 要做真面板**：走 `Game.UI.Open<T>()` + 预制体 `Resources/UI/{类名}`（AI 用 Editor 脚本生成预制体，用户之后可在 Editor 里改样式）；⛔ 禁止用 `OnGUI` 调试文字当交付；按钮用 `EventSystem`（`CloverInput.Init()` 已保证）。
- 资源引用**全部收敛到资源常量表 / 集中路径**，禁止散落路径字面量；后续替换 = 换文件，不碰逻辑。
- **有可操控角色就必须做操作（硬约束）** —— 相机 + 移动，三条铁律：
  1. **输入走引擎 `Game.Input`**（`State.MoveDirection` / `GetKeyDown(GameKey.X)` / `MouseDelta`）—— 引擎自动探测输入后端；**直连 `Keyboard.current` 在旧后端工程下会拿到 null ⇒ WASD 完全不响应**；
  2. **自己的位置必须本地预测**：⛔ 绝不用服务端插值位置逐帧覆盖自己（否则手感 = 网络延迟，服务端拒绝 / 丢包时表现为"按键不动"）；服务端权威位置只用于**校正**（小误差忽略、大误差拉回）；
  3. 相机：引擎的 `Game.Camera.Follow` 是**"锁 Z 的简单跟随"**（无环绕、无防穿墙）⇒ 第三人称请**业务自写**环绕相机（属 C 桶；只要**不调用** `Follow`，引擎就不会抢相机 Transform）。
- **动画必须接线（硬约束）**：素材自带动画 → Editor 脚本生成 `AnimatorController` → `Game.Anim.CreateAnimator(modelGo, controller)` → `SetFloat("Speed")` / `SetTrigger("Attack")` 驱动。（`AnimatorController` 是 Editor 资源类型，运行时建不出来；生成脚本记得 `using UnityEditor.Animations`。）
- **引擎模块要显式初始化**：`Game.Res` **不会**随 `CloverPresentation` 自动挂载，必须业务调 `CloverRes.Init(root)`；漏了它 `Game.Res` 恒为 null ⇒ **模型永远加载不出来（只剩占位体）且会在加载点抛 NullReferenceException 打断进图流程**。

**必须创建的文件夹结构**（在 `Assets/` 下）：

```text
Assets/
├── Resources/                # 占位资源文件夹（必须创建）
│   ├── Placeholder/          # 占位图片（placeholder_64x64.png 必须；128/256 可选）
│   ├── Sound/SFX/            # 占位音效（可选）
│   └── Models/               # 占位模型（可选）
├── Scripts/                  # ⛔ 分层名以 `reference/architecture.md` §4 为准（Def/Core/Module/UI/App）
│   ├── Def/                  # ★ 业务消息号 + 协议（必须，镜像 server/game/def）
│   │   ├── MsgDef.cs         # 消息号常量（唯一定义处）
│   │   └── ProtoDef.cs       # 协议结构体
│   ├── Core/
│   ├── Network/
│   ├── UI/
│   └── Resources/
└── Configs/
```

- 占位图默认 64x64 纯色 PNG，**文件必须实际存在**（不能只有代码引用）；文件夹结构必须创建完整。
- **场景创建与脚本挂载（AI 自己做，不许丢给用户）**：建场景（如 `Assets/Scenes/Main.unity`）并保存 + 加进 Build Settings → 建挂载点 GameObject（`Bootstrap` / `GameRoot`）→ `AddComponent` 挂业务入口脚本 → `unity console tail --format json` 确认无编译错误。做法见 `reference/unity-cli.md` §7。
- **交付标准 = 用户打开工程点 Play 就能跑**；交付说明里⛔ 不许出现"请用户手动创建物体并挂载脚本"。

### 4.3 占位规则（AI 不许因缺美术而停手）

| 资源类型 | 占位方式 | 尺寸要求 |
|---|---|---|
| 图片/图标/Sprite | 单色占位图（`placeholder.png`），或 Image 用纯色块 | 默认 64x64；用户指定则按要求 |
| UI 布局 | 真 uGUI 布局（HUD 信息区 / 按钮 / 血条），可临时配色 | 默认适配 1920x1080 |
| 音效/BGM | **优先接入真音频**（素材包自带 / CC0 音效库）；实在没有才退化为 `Play(name)` 钩子 + 日志 `[SOUND] name`（并在回复首行高亮） | 无 |

| 特效 | 空占位（代码留 Trigger 点） | 无 |

> **可玩性优先于美术**：任何"等美术给图才能写"的依赖都必须在这一层消解成"钩子 + 占位"。
> 占位图尺寸标注意义 = **方便替换时对齐**（uGUI Image 默认 Simple 会拉伸，但 Sliced/Tiled、游戏内 Sprite、图标头像等固定比例资源必须对尺寸）；资源替换清单里必须标注目标尺寸。

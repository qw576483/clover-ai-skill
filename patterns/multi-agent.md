# 复杂项目：步骤文档 + 多 agent 编排

> 适用：**评估下来比较复杂的游戏 / 系统**。简单任务（单文件、单个消息号、一个 UI 面板）**不要走这套** —— 别为了"显得正规"开一堆 agent，那只会增加扯皮和上下文断裂。
> **★ 第一铁律先于本文一切规则：必须做完才交付** —— **主 agent 与每个子 agent 都适用**。

## 第 1 步：判定复杂度（满足任一条即算复杂）

- **「一键出游戏」（启动/菜单/创角链路 + 首场景 + 多系统）一律算复杂**；
- 要同时改**服务端 + 客户端 + UI** 三方，且消息号 / 协议跨 2 个以上模块；
- 预计代码量 ≳ 800 行，或新增 / 改动文件 ≳ 10 个；
- 玩法含多个子系统（房间 / 匹配 / 帧同步 / 存档 / 背包 / 排行 / 交易 …）；
- **需要按原版系统清单逐项做完**（见 `patterns/game-demo.md` §0.0c）；
- 存在**可并行的独立子系统**（服务端逻辑、网络层、UI、资源、配表 —— 配表走 `patterns/table.md` 闭环，源表放 `策划/数值文档/`，可单独交给一个 agent）。

> **不许砍范围（硬性）**：**该拆多少 agent 就拆多少 —— 10 个、100 个、1000 个都不是理由**。⛔ 禁止因为"要开的 agent 太多 / 周期太长"而缩小范围、降低完成度或改成"先做个精简版"。人手不够 ⇒ **主 agent 继续开**（分批开、逐个验收）；**单个 agent 到轮次上限就换手接力**（见「轮次预算与接力」）。

判定结果要**告诉用户**：为什么按复杂处理、打算拆几步、**打算开多少个 agent（可分批）**。

## 第 2 步：主 agent 先出《步骤文档》（不许跳过、不许边做边补）

落盘：**`clover-{项目名}/docs/步骤文档.md`**（复杂项目才建 `docs/`；`策划/` 只放策划产物 —— `策划/数值文档/` 放配表、`策划/策划案/` 放玩法文档）。

| 内容 | 说明 |
|---|---|
| 目标与验收 | 最终"能跑通什么"，一句话验收标准 |
| **内容清单（原版系统清单）** | 按 `patterns/game-demo.md` §0.0c 列出**要做的每一个系统**（含 ① 启动/菜单/创角链路 ② 首场景全部内容 ③ 游戏内流程），每项标注负责的 agent 与验收标准 —— 清单里的项**不允许消失** |
| 系统拆分 | 拆成哪几个可独立交付的子系统 |
| 配表清单 | 需要几张表、表名与后缀（`_cs`/`_c`/`_s`）、字段与主键、谁负责 |
| 步骤清单 | 每步：产出物（**文件路径**）+ 验收标准 + 依赖的前置步骤 |
| 串 / 并行标注 | 哪些能并行、哪些必须串行（**先定消息号 / 协议，再写两端**） |
| 关键契约 | 消息号段、协议字段、模块边界 —— 各 agent 接口对齐的唯一依据 |
| 风险与未知 | 待确认项、需要反问用户的点 |

**《步骤文档》是唯一总纲**：agent 之间不许私自改契约，发现契约有问题 → 先回报主 agent。

## 第 3 步：给每个 agent 一份**自包含**任务文档

落盘：**`clover-{项目名}/docs/agents/agent-NN-{子系统}.md`**。每份必须写明：

1. **身份与技能（强制）** —— 开头就把「怎么开工」写死：

   ```
   开工先做两件事：
   (1) 拿到 skill：工具集里有 use_skill 就用它加载 clover-engine + unity-cli；
       没有就直接读文件（命中即用，不必读完）：
         · <项目根>/tools/ai-skill/SKILL.md        ← 项目级，首选（记本项目约定 / 消息号 / 配表）
         ⛔ 但全局 skill 的规则层（§0~§7）不可被项目级覆盖：冲突时以全局为准
         · ~/.codebuddy/skills/ai-skill/  ·  ~/.claude/skills/ai-skill/  ·  ~/.cursor/skills/ai-skill/
         · <仓库根>/clover-ai-skill/SKILL.md  ← 兜底
       （unity-cli 同理，目录名换成 unity-cli/）
       都找不到 → 回报调用方要路径，**不许凭记忆写代码**。
   (2) 然后按 skill 的「混合模式找依据」查代码（用户 > 引擎 > 联网/自创），**不许编 API**。
   ```
   > 两点提醒：① IDE 的 agent 定义**不解析 `skills:` 字段**，工具集由 `tools:` 决定（不写 `use_skill` 就没有该工具）；② **别写死绝对路径**（含用户名 / 工具目录），换机器就废。参考代码的规则不用重写 —— 就是 skill 里那条「混合模式找依据」。
   负责客户端的 agent **必须**用 `unity-cli` 做编译 / 场景 / 资源 / 日志 / 截图，不得绕开。

2. **任务边界**：只做什么、**绝不做什么**（明确列出不许碰的目录 / 文件，防多 agent 互相踩）。新建项目必须逐字写上：「**只许改本项目（`<项目根>/…`）的文件；引擎源码 / `clover-doc` / 本 skill 只读**。工作区里其它 `clover-project-*` 是已交付的成品，**可读、可对照**（目录组织 / 分层写法 / 面板与配表做法 / 交付口径）。」
   **并且再逐字写上**：「⛔ **skill 与引擎源码都只读** —— 项目级 `<项目根>/tools/ai-skill/`、仓库全局源、宿主安装副本、引擎的 `Runtime/**` / `pkg/**` / `internal/**` / `Editor/**` 全都不许改；碰到**引擎缺口 / 引擎 bug / skill 说不清** ⇒ **往 `<项目根>/引擎问题.md` 追加一行**（三段：`引擎缺口` / `引擎 bug` / `skill 问题`），然后**用绕法把活做完**，回报里带"登记了 N 条引擎问题"。」
3. **前置依赖**：上游已产出的文件 + **确切接口签名**（消息号常量、函数签名、config 字段名）+ **标准答案那一侧**（`策划/对照表.md` 的"原版值 + 出处"或《原创规格》的编号条款）—— ⛔ 没有标准答案就派活 = 让执行者自由发挥。
4. **产出物清单**：要创建 / 修改的文件**绝对路径**。
5. **怎么算做完 + 一条自检命令**（如 `go build ./...`、`unity console tail --format json`）。
6. **必读 skill 章节**：把文件路径列出来，让 agent 直接读，**不许靠记忆写代码**。
7. **日志要求**：按 `SKILL.md`「错误处理与日志」—— **每条非预期分支都要打日志**。
8. **临时文件位置（逐字写上）**：「一切一次性产物（探针 / 驱动 / 临时截图 / 验证小程序）只许放 `<项目根>/.ai-tmp/test/`（自检宿主放 `.ai-tmp/hosts/`），**用完就删**；⛔ 不许放项目根、`client/_dev/`、`tools/`、`Assets/`、`策划/`、`docs/`。」⛔ **尤其不许写成**「探针放 `client/_dev/`」（那会让子 agent 把探针堆到上百个文件，违反全局规则）。
9. **收尾只交两样**：**产出物 + 一条自检命令的原始输出**（编译 / 起服 / 该片的关键路径）。⛔ 任务书里**不许**要求它填表 / 拼联络图 / 逐格取证 / 建台账 / 做冻结 —— 那是**把验收当产出**（`SKILL.md` §2 第 5b 条）。
9b. **防卡死三件套（逐字写上）**：① **每条命令必须显式超时**（60~180s；编译 / Play 类可放宽到 300s），⛔ 不许发可能永不返回的命令，超时即当失败（落盘 + 回报，⛔ 不原地重试 3 次以上）；② **计时器自检**：开工记 `t0`，每步前查 elapsed，**超过 12 分钟立刻落盘 + 回报**（18 分钟前必须已回报完）；③ **心跳**：每完成一步往 `<项目根>/.ai-tmp/test/ledger.tsv` **追加**一行（3 列：`ISO 时间 \t 成员名 \t 步骤+状态`）⇒ 调用方与用户任何时刻可判"在推进 vs 卡死"。
   ⛔ **理由**：成员卡在 hang 住的命令上时**没有任何一方会打断它** —— team 通道只保证"调用方不陪等"，**活本身还是没干完**。详见 `scaffold/agent-impl.md` §2.5。
   ⛔ 并且**逐字禁掉"交接文档"**：不许写 `docs/交接-*.md` / `NEXT.md` / `docs/进度*.md`；未完成项只写在**回报消息**里。
10. **改完怎么验（逐字写上，一拍）**：批量改完 → **编译一次**（编不过 ⇒ 中止一切验证）→ **跑一次关键路径 / 看一眼截图** → 回报里贴原始输出。⛔ 明确禁止「改一处编译一次 / 改一处截一次图 / 逐项进出 Play」。
11. **驱动复用**：开工**先查** `<项目根>/.ai-tmp/drivers/` 与本轮既有驱动 —— 已有驱动**优先改**，⛔ 不许从零重写。位置口径：`.ai-tmp/drivers/` = **本轮复用**（交付前统一清）；`.ai-tmp/test/` = **真正一次性**（用完即删）。
12. **离线优先（且逐字写明"不设上限"）**：**能离线判的（数值 / 逻辑 / 状态 / 坐标，秒级）不许进 Play**；Play 只留给表现类与必须真跑的链路。⛔ **不许写任何次数上限 / 预算**：有理由就继续进，一直做到系统清单全部打勾。

> **菜单链路建议单独交给一个 agent**：启动画面 / 主菜单 / 创角·选角 / 读条 / 暂停 / 回主菜单是一整块（`patterns/client/app-flow.md`），与首场景**并行**，契约只依赖消息号与场景名 —— 这是"完整成品"最快成形的一条路径。

## 第 3.5 步：**怎么派生执行者**（⛔ **只许 team，禁同步子 agent**）

> **同步子 agent 的代价**：宿主对"**单次子任务等待**"有上限，同步通道**频繁卡死**（`code=10003` / `No result found`），卡死后**调用方拿不到回报**、只能错位接力；切 team 后稳定。
> ⇒ **现行政策：默认派 team 成员（异步）；⛔ 禁同步子 agent。**

**闸门 −1（开工前 30 秒）**：先确认任务工具里**真的能派出发者**（看得见执行者 agent，例如 `clover-impl`）。看不见 ⇒ **按 `scaffold/agent-impl.md` 把 `clover-impl.md` 建出来**（用户级 `~/.<工具>/agents/` 或项目级 `<工作区>/.<工具>/agents/`；`---` 必须在第 1 行、`tools:` 含 `use_skill`、`maxTurns: 250`、`model: inherit`），**下一条消息即可 spawn**。
⛔ 没有那份 agent 定义时，任务工具里只剩内置的**只读** `code-explorer` ⇒ 主 agent 会判"没有通道"、**自己动手改源文件**。**"没有执行者"不是"我自己做"的理由 —— 它是"先把执行者建出来"的信号。**

**✅ 正确形态：team 成员（异步）**
- `Task(subagent_name=<执行者>, name=<成员名>, team_name=<队名>)` —— **三个都要给**；
- **异步**：**立即返回**，成员在后台跑、产出照落盘，主 agent **不进入等待**；
- 成员完成后**主动 `send_message` 回报**（主 agent 无需轮询）；
- 一片一成员 + 一个队名；派完立刻留痕（`.ai-tmp/test/ledger.tsv` 的 `kind=dispatch` 行）。

**⛔ 错误形态：同步子 agent（只给 `subagent_name`、不给 `name`）** ⇒ 主 agent **进入等待**，超限就报 `code=10003 This operation was aborted` / `No result found` —— **成员还在后台跑、产出照落盘，调用方却拿不到回报 ⇒ 无法验收**（最隐蔽的一类事故）。

**⚠️ 别把"问模型名"当判据**：子 agent 报出的模型名来自**宿主注入的自我描述**（它自己就声明"无法独立校验真实模型标识"），**它实际跑在哪个模型上都可能报同一串**；它也读不到自己定义里的 `model:` 字段；宿主成员元数据只记 sessionId、不记模型。⇒ 唯一的观测点是宿主会话日志（`~/.<工具>/logs/`），需要时才翻。

**按"卡死"的三种形态判**：

| 卡死形态 | 现象 | team 能不能治 |
|---|---|---|
| **等待超时** | 主 agent 等太久被掐断 ⇒ `code=10003`；子 agent 其实**还在后台跑**，调用方拿不到回报 | ✅ **能治**（异步不进入等待） |
| **命令 hang 住** | 子 agent 卡在永不返回的命令上（Play 死锁 / `unity` 挂起 / 无超时网络请求），**没有任何一方会打断它** | ❌ **治不了** ⇒ 只能靠 §9b「防卡死三件套」 |
| **同机并发撞车** | 一个成员改 `.cs` ⇒ Unity **域重载** ⇒ **掐掉另一个成员正在跑的 Play**；症状 = 那轮 Play 全链拿到 `no local/no match` / `playMode=False` 的**假数据**（谁都不报错，证据先烂掉） | ⚠️ **只能靠流程错开**（见下三条） |

**同机并发撞车的处置三条（缺一不可）**：① **进 Play 前抢 `<项目根>/.ai-tmp/play.lock`（目录形式）**，用完主动放锁；被他人持有 ⇒ 有界等待后先做离线项，⛔ 不硬抢；② **进 Play 后断言 `Application.isPlaying == true`**（不在就重进，最多 3 次）；③ **采到空数据立刻作废该帧，⛔ 不许当证据**；回报里写明"本片 Play 期间是否有其它成员落过 `.cs`"。
⛔ **不要用"大家先别改代码"来规避**（那会让整队停摆）—— 代价由"**谁进 Play 谁查假数据**"吸收。

**Play 独占锁（6 行，够用）**：**同一时刻只许一个成员进 Play** —— 有人改 `.cs` ⇒ Unity 域重载 ⇒ 掐掉另一个成员正在跑的 Play，症状是那轮拿到 `no local/no match` / `playMode=False` 的**假数据**（谁都不报错）。

- **抢**：`New-Item -ItemType Directory <项目根绝对路径>/.ai-tmp/play.lock`（**原子**；失败 = 已被持有）→ 5 秒内写 `play.lock/owner`（单行、成员名、非空）。
- **等**：被占 ⇒ 有界等待（口径 20 × 30s），超时**先做离线项**，⛔ 不硬抢、⛔ 不删别人的锁。
- **放**：**`mv` 整个锁目录进 `.ai-tmp/trash/`**（`trash/play.lock-<owner>-<ts>`）。⛔ **绝不用 `rm` / `Remove-Item` / `rmdir` 放锁**：本机"删除预算"（turn 级约 50 次）耗尽后 `rmdir` 会**真的挂死**；`mv` 不受限。
- **孤儿锁**：三条同时成立才可回收 —— ① 账本最后一条 `play` 没有配对 `END`；② 属主进程已死（查进程表）；③ 重读 `owner` 与首次一致。回收写一行留痕。
- **锁路径一律锚到项目根绝对路径**：工作区根下**另有一个** `.ai-tmp/`，锁错了 ⇒ 两条线同时进 Play 且它自己不会报错；断言"锁空闲 / 被占"必须连绝对路径一起打印。
- **采到空数据立刻作废该帧**，⛔ 不许当证据；回报里写明"本片 Play 期间是否有其它成员落过 `.cs`"。

**⇒ 落地口径（5 条）**：① **一律 team 成员（异步）**（三个参数都给）；② **任务书里加一行**：`回报首行写你当前的模型标识`（每次派活都在采样）；③ **保留「防卡死三件套」** —— 它治的是**另一种卡死**（成员自己卡住，team 救不了）；④ **片仍然要小**（≤20 分钟 / ≤130 轮）—— 异步不卡调用方，但**成员自己会被轮次上限掐断**；⑤ ⛔ **异步不是建议，是唯一通道**（名字不再是闸门条目：`no-sync-subagents` 已从模板删掉）。

**⛔ 闸门 −0（比闸门 −1 更早，30 秒）：先确认宿主到底有没有 team 通道**

派活前先看宿主日志（WorkBuddy：`~/.workbuddy/logs/<日期>/<项目名>__*.log`）。若出现 `[AgentTool] agent '…' requested background spawn but the team system is disabled — running synchronously.` ⇒ **本宿主的 team 系统是关闭的**：

| 事实 | 说明 |
|---|---|
| `team_name` 给不给都一样 | 宿主**强制降级为同步执行** |
| 「禁同步子 agent」这条铁律 | **在形态上无法满足** —— 不是主 agent 不听话，是宿主不提供该通道 |
| 正确动作 | **不要反复重派**（每次都是同步、同一结果）。按「硬规则 7」**查盘两次为限 → 主 agent 接手**（写 `# takeover: <原因>`），并把「本宿主无 team 通道」作为**环境事实**上报用户 |
| ⛔ 别做的事 | 别把"`team_name` 填了"当成"形态正确" —— 判据是宿主日志里有没有 `team system is disabled` |

**同一份日志还要看两行**：`Preloaded skill 'clover-engine' into agent …` = skill 已自动注入 ✅；`frontmatter skill 'unity-cli' not found` = `skills:` 里写了不存在的 skill ⚠️。

**⛔ 派生成功的判据 = 盘上有产出，不是宿主报 `completed successfully`**：宿主日志打 `completed successfully`，而**心跳文件不存在、目标文件 mtime 未变** ⇒ 成员**跑了但什么都没干**（工具集为空 ⇒ 工具调用被当文本吐出）。**⇒ 派活后 60 秒内必须做一次盘上核对**（心跳 + 目标文件 mtime），⛔ **不许拿"调用返回成功"当验收**。配对排查：同时用内置 `general-purpose` 派一个 30 秒探针（写一个文件）—— 探针**落盘**说明通道好、问题在**自定义 agent 的定义**（多半是 `tools:` 用了别的宿主实名，见 `scaffold/agent-impl.md` 的「宿主适配」）。

**派活后 10 秒核对（无脑照做）**：

| 查什么 | 合格 | 不合格 ⇒ 动作 |
|---|---|---|
| 派生形态 | **有成员名 + 队名**（异步 team） | 立刻发 shutdown；**改派 team 成员** |
| 成员回报 | 带**模型标识** + 三段（已完成 / 未完成 / 下一个从哪动） | 缺模型标识就补问并记进抽样台账 |
| 是否产生了**同步**子 agent | **没有** | 中止它；**已落盘的产出不回滚**，交给 team 成员接力 |

**中止与接力**：① 先让执行者**把进度落盘**（⛔ 不许回滚已完成的文件）、回一条简短回报；② 主 agent 用**正确通道**重派，任务书"前置依赖"一节写清「上一棒做到哪」；③ **谁也没白干**（已产出的代码 / 截图 / 解析结果全部算数）。

**为什么不必"一次只派一片"**：同步通道的"一次一片"不是纪律，是**代价**（它让主 agent 进入等待 ⇒ 频繁卡死）。异步通道下**可以多片并行**（互不阻塞）；要控节奏就靠第 1 步**把片拆细** + 「轮次预算与接力」的**换手**。

## 第 4 步：硬约束 —— **agent 不许再开子 agent**

> **每个 agent 都是执行者，不是管理者。**

- ⛔ **禁止** agent 内部再派生子 agent、再拆分任务、再写"这部分我让别的 agent 做"；
- 理由：**子 agent 会偷懒** —— 层层转包后没人真正读源码、没人真正跑编译，最后交回一堆"看起来对"的代码（通用模板 + 别处片段 + 占位物 + "留钩子后续替换"），主 agent 还得从头返工；
- 需要更多人力 → **回报主 agent**，由主 agent 决定是否增开 agent，并**由主 agent 补写任务文档**；
- 每个 agent 必须自己走完：读 skill → 查 `clover-doc` / 源码 → 写代码 → **自己跑编译 / 日志验证** → 回报结果。

> **但"数量"不设限**：需要更多人 ⇒ 回报主 agent，**主 agent 继续开**（10、100、1000 都行，分批开、逐个验收）。**唯一不许做的是"砍范围"。**

## 第 5 步：主 agent 职责（不可下放）

- ★ **不做实现**：新任务**派 agent**；修 bug **优先激活原 agent**（它上下文还在，最省），原 agent 不在了才自己搞。
- 维护《步骤文档》，裁决 agent 之间的契约冲突。
- **维护项目级 skill `<项目根>/tools/ai-skill/`**：全部交付完成后，把新增的消息号 / handler / 面板 / 管理器 / 通用函数 / 配表登记进 `registry.md`，新出现的约束 / 静默风险写进 `constraints.md`（⛔ agent 不许各自去改它，避免并发写冲突）。
- **抽查**产出（**不是逐个办验收仪式**）：**自己跑一遍**编译 / 起服 / 读日志 / 看一眼画面，⛔ 不许"看它说完成了"就通过；不合格 ⇒ 让**原 agent** 返工（补充任务文档、指明问题），⛔ 不要自己顺手改完就算（否则文档与代码失配）。
- 全部步骤完成后做**端到端联调**（起服 + 客户端 Play + 关键路径走一遍）。
- **最后看一眼：像不像 A**（`reference/design-review.md` §3.6）—— 派 agent 之前先把 A 的参考截图准备好，交付前**自己看图比一遍**；**不像 ⇒ 不予交付**，打回原 agent 改到像；⛔ 禁止用"基本一致 / 略有差异"放过。
- 再统一写交付说明与资源清单。**参考游戏名缺失 → 先问用户要。**

## 轮次预算与接力（跨过物理上限，不靠砍范围）

**事实**：宿主对「**单个任务**的模型请求数」有硬上限（实测约 500），没有公开开关。
**推论**：主 agent 与每个 **team 成员** 各自独立计数 ⇒ 通过「换手」可以跨过它。

1. **主 agent 不做实现** —— 它那 500 轮花在派活与验收上，能管 25~50 个成员。
2. **成员的 `maxTurns` 取 `250`**（≈ 单片 15~30 分钟），模板与放置位置见 `scaffold/agent-impl.md`。⛔ **别取 450**：那会跑到 30~70 分钟，**成员自己会被轮次上限掐断**，而异步通道下**调用方不会立刻知道**（要靠心跳文件）。做不完 ⇒ **落盘 + 回报 + 接力**，⛔ 不砍范围。
3. **成员到点主动收尾**，回报三段：**已完成 / 未完成 / 下一次该从哪个文件动**。⛔ **严禁硬撑到被静默掐断**（掐断后调用方拿到的是"看起来完成"的残缺结果，这是最贵的事故）。⛔ 这三段只许写在**回报消息**里，不许写成 `docs/交接-*.md` 留在项目里。
4. **主 agent 接力**：收到回报 → 更新《步骤文档》 → 开下一个 agent（任务文档里带上"上一棒做到哪"）。
5. ⛔ **不许的形态**：因为"怕撞上限"就把系统清单砍短。**上限不是砍范围的理由，是接力的理由。**

## 常见问题

| 问题 | 后果 | 纠正 |
|---|---|---|
| 复杂度没判定，直接开 5 个 agent | 契约对不上，消息号两端不一致 | 先出《步骤文档》，把消息号 / 协议定死 |
| 任务文档只写"实现服务端逻辑" / 只写"先加载 skill"没给路径 | agent 自由发挥或凭记忆乱写 | 文档必须带**确切签名 + 产出路径 + 验收命令 + 三层 skill 路径** |
| agent 自己又开子 agent | 偷懒、无人验证 | 硬禁止；要人找主 agent |
| 主 agent 只看"已完成"不验证 / **自己下场做实现** | 交付出错 / 几百轮撞上限只剩半成品 | 新任务**派 agent**、修 bug **优先激活原 agent**；主 agent 必须自己跑编译 / 日志 |
| **任务工具里只有只读 explorer / 没有执行者定义** | 主 agent 判"没通道" ⇒ 自己下场实现（且从日志看不出来） | 先按 `scaffold/agent-impl.md` 建 `clover-impl.md`，**再派活** —— "没通道"是"先建通道"的信号 |
| 简单任务也走多 agent | 慢 + 扯皮 | 单文件任务自己做 |
| 因为"要开的 agent 太多"砍范围 | 交出来的是精简版，不是成品 | **数量不设限**，分批开 |
| 只做游戏场景，没有启动 / 菜单链路 | 一眼假 | 菜单链路单列一个 agent（`patterns/client/app-flow.md`） |
| 只跑通就交付，没和参考游戏比 | 用户一句"不像" ⇒ 大面积返工 | 交付前按 §3.6 自己看一眼像不像；**不一致不许交付** |
| 用户没说参考游戏，AI 自己挑品类 | 做出来**永远不像**，最贵的返工 | **先问用户要游戏名**（可给候选，不许自己拍板） |
| 子 agent 硬撑到被静默掐断 / **一片干到底**（单次 30~70 分钟） | 交出"看起来完成"的残缺结果；异步下调用方不会立刻知道 | 一片 = **一个交付单元 + ≤20 分钟 / ≤130 轮**，超了**拆片**；到点**先落盘 + 再回报** |
| 中止后**重派原任务** | 与后台仍在跑的上一棒**撞车**、重复劳动 | **先查盘**（`git status` + 近 1~3h mtime + `.ai-tmp/test/` 最新产物）⇒ 已落盘就**按完成验收**（不回滚）⇒ 派**接力棒**；两次无回报才 `# takeover:` |
| **项目级 skill 把全局硬规则"项目化"放宽**（如把探针位置写成 `client/_dev/`） | 子 agent 照章违规且"有据可依" | 项目文档**只许加严**；冲突以全局为准并把冲突行改掉 |
| 不派下一个 agent，改成写 `docs/交接-下一棒.md` | 读起来像负责，实质是**把活推给未来** | 未完成项**只写在回报消息里**；接力 = **立刻开下一个 agent** |
| 收尾只有"我觉得没问题了" | 临时文件 / 悬空引用没人看过 | 想查时用那 3 招（编译 / 交付卫生 / 引用可达，`SKILL.md` §4）；⛔ 默认不跑、不拦交付 |
| **改一处就编译一次 / 截一次图** | 把最贵的动作（分钟级）重复 N 次 | 按**一拍**走：批量改 → 一次编译 → 一眼截图 |
| **拿"实机次数 / 预算用完了"当停工理由** | 该做的没做完就收手 | **次数不设上限**：有理由就继续做；一个 agent 做不完就**接力再开** |
| **把验收做成产出**（填表 / 拼联络图 / 逐格取证 / 建矩阵） | 时间全花在仪式上，功能没做几个 | 成员只交**产出物 + 一条自检输出**；自检**只在需要时**自己跑（`SKILL.md` §4），⛔ 默认不跑（`SKILL.md` §2 第 5b 条） |
| **东拼西凑交差**（通用模板 + 别处片段 + 占位物 + "留钩子"） | 用户一眼看出"不是原版" | 按 A 的系统清单逐项做完（`patterns/game-demo.md` §0.0c）；**占位物 / 留钩子 = 没做完** |

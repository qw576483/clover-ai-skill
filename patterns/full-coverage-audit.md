# 全量覆盖自查 · 复合产物穷举矩阵（跨项目通用方法论）

> **用在哪**：任何"**要像某个参考物 / 要 1:1**"的交付 —— 游戏复刻、UI 复刻、协议对齐、引擎移植、素材搬运。
> **治的病**：① **症状驱动**（用户报一条修一条，没报的全漏）；② **单维度交付**（几何对了就说"地图做完了"，碰撞/门/声音全没验）。

## 0. 科学依据（为什么这套方法可信、能撑得起大型游戏）

这套方法论不是拍脑袋，是**四个已验证领域的交汇**：

1. **芯片验证 · Coverage-Driven Verification（CDV/UVM）** —— 半导体工业的**标准验证方法论**，验证对象是**数亿晶体管**的设计（比任何游戏都复杂几个数量级）。核心就是本方法的骨架：**定义覆盖模型 → 测量覆盖 → 未覆盖即缺陷**。出处：UVM 标准（Accellera）、IEEE 1800。
2. **主机游戏认证 · TRC/TCR/Lotcheck** —— **Sony**（Technical Requirements Checklist）、**Microsoft**（Technical Certification Requirements）、**Nintendo**（Lotcheck）对**所有上平台的游戏**（含 AAA）的**强制穷举式检查清单**，本质是数百页的"全维度×全状态×全边界"验收表。出处：PlayStation Partners / Xbox Requirements / Nintendo Developer Portal。
3. **组合测试 · NIST 30 年研究** —— **80-90% 缺陷由 1-2 个参数交互引起**；所有已测项目的最大缺陷交互 **≤6-way** ⇒ **2~3-way 覆盖（pairwise/triple）就能发现绝大多数缺陷**，且**不必做笛卡尔全组合**。出处：Kuhn/Kacker/Lei《Introduction to Combinatorial Testing》(2013)、NIST Special Publication 800-142；工业验证：航空、自动驾驶、安全测试。
4. **游戏测试学术 · Model-Based Testing（MBT）** —— 用**扩展有限状态机（EFSM）建模游戏行为**，从模型自动生成测试用例。出处：*Search-Based Automated Play Testing of Computer Games: A Model-Based Approach*（Springer 2021）、*Model-Based Testing Computer Games: Does It Work?*（IEEE ICST 2025）、*PX-MBT*（ScienceDirect 2024）。

**推论**：这套方法**复杂度撑得起 AAA**（TRC/TCR 就是干这个的），**科学上有理论上限**（组合测试证明 t-way 覆盖的有效性），**工程上有成熟先例**（CDV 在更复杂的领域已标准化）。
> **核心认识**：**游戏（以及任何交互式产品）是复合产物** —— 它不是一堆独立零件，而是 **N 个维度 × 每个维度的状态空间 的笛卡尔积**，用户看到的是**合成结果**。
> 所以"某一维做完"永远不等于"做完"：**几何对 + 碰撞错 ⇒ 箱子能穿；UI 元件对 + 状态错 ⇒ 选中态没反馈；动画数据有 + 没播 ⇒ 看着像木头；音频文件在 + 没挂事件 ⇒ 全程无声。**

## 1. 三条公理（本方法论的全部依据）

1. **合成可见性**：用户感知的是维度的**合成结果**，不是任一维度 ⇒ 验收必须按"合成后的样子"判，不能按"我的代码写了"判。
2. **行数是数出来的**：清单由**脚本枚举盘上实体**生成（⛔ 手写 / ⛔ 凭记忆 ⇒ 结构上必然漏）。
3. **漏一行 = 红字**：闸门做「行数对账 + 零空行 + 零不一致」。没有代价的漏检 ⇒ 默认退化成"只修用户报的"。

## 2. 分解模型（把"复合产物"变成可穷举的东西）

```
产物 = Σ 维度 D_i
每个维度 = 实体集 E × 状态集 S × 边界值 B
穷举目标 = 每个维度内 E×S×B 全枚举  +  跨维度按"因果对"交叉（⛔ 不做笛卡尔全组合，那会爆炸并被读成"做不完"）
```

- **维度内**：全枚举（这是硬要求）。
- **跨维度**：只交叉**有因果关系的对**（例：动画 × 逻辑状态、UI × 流程状态、音效 × 事件、碰撞 × 角色类型、特效 × 命中材质、输入 × 上下文）；无因果的对不交叉（例：字体 × 斜坡阈值）。
- **分辨率写死**：状态取**枚举值 + 边界值**（阈值上下各一、0/上限/超界），⛔ 不是"每一帧 / 任意组合"。

## 3. 维度清单（12 维 + 3 支撑维；每个项目照抄 instantiation）

| # | 维度 | 枚举什么（E） | 状态与边界（S / B） | 默认判据 | 典型漏检（真实形态） |
|---|---|---|---|---|---|
| D1 | **资源/资产** | 每个模型 / 贴图 / 材质 / 字体 / 音频 / 动画数据 / 地图数据 | 是否存在、是否被引用、路径是否收敛 | 脚本（引用完整性 + 出处） | 文件在盘上但没人引用 ⇒ 静默失效 |
| D2 | **几何与场景** | 每个物件（墙/门/箱/梯/坡/扶梯/栏杆/灯） | 位置、尺寸、朝向、是否生成到场景 | 脚本（几何+存在性）+ 并排图 | **该有门却没门**、门板被摘除却没补 |
| D3 | **材质与贴图表现** | 每个物件 × 每个材质槽 | 贴图/颜色/平铺/UV/发光 | 并排图 + 脚本（引用指对） | **有门没材质**、纯白模型（skin 没绑） |
| D4 | **UI / HUD** | 每个面板 × 每个元件（背景/标题/按钮/文本/图标/滚动条/光标） | 常态 / 悬停 / 按下 / 禁用 / 选中 / 滚动到边界 / 超长文本 | 并排图 + 脚本（锚点/尺寸/字号/层级） | 署名/版权文本残留、禁用态没做、边界状态错位 |
| D5 | **动画** | 每个 controller × 每个 state | 关键帧（起/中/末/循环点）、时长、帧率、混合时长、事件回调 | **原版逐帧数据比对**（骨骼坐标/骨架哈希）+ 并排图 | 序列**没播**（controller 没挂 / 被暂停 / CrossFade 每帧重置） |
| D6 | **特效** | 每次开火 / 命中（分材质）/ 爆炸 / 弹痕 / 血雾 / 烟 | 贴图、时长、贴面朝向、池与回收 | 并排图 + 触发断言 | 用球的占位物、墙上无弹痕 |
| D7 | **音乐（BGM）** | 每个场景（启动/主菜单/进图/买枪/暂停/胜负/回合结束） | 进入播 / 离开停 / 循环 / 淡入淡出 / 受音量设置控制 | 脚本（当前曲名+音量+循环）+ 人耳一次 | 主菜单全程无声、进图不停 |
| D8 | **音效（SFX）** | **逐条事件**：每把枪开火/空仓/换弹/切枪、脚步（分地面材质）、跳/落地（分高度）、受伤/死亡/爆头、命中各材质、刀、手雷、C4、无线电、UI 点击/悬停、倒计时 | 是否触发 / clip 路径 / 音量组 / 3D 衰减 | 脚本（事件→clip 触发断言）+ 覆盖率=事件数 | 文件在但**事件没挂** ⇒ 全程没声 |
| D9 | **物理与碰撞** | 每个物件 × 碰撞形态（盒/阶梯/斜坡/无） | 逐对交互（谁能穿谁/站谁/推谁/重叠）、高度带、跳跃/蹲跃上限、斜坡阈值 | **离线网格断言**（⛔ 不用 Play 走一遍） | **箱子能穿**、**扶手跳不过**、**人物能重合** |
| D10 | **玩法逻辑** | 每个系统（回合/购买/经济/伤害/死亡/重生/计分/胜负/暂停/流程） | 每条分支 + 每个边界值（阈值±1、0、上限、超界） | 脚本断言 + 逐分支留痕 | 只跑过默认分支、边界没取 |
| D11 | **交互与输入** | 每个输入 × 上下文（游戏内/菜单/买枪/观战）× 目标 × 按住/点按/连按 | 绑定、延迟、重复率、菜单屏蔽 | 注入断言 + 原版绑定表比对 | 键位没对齐、长按与连发、菜单内未屏蔽 |
| D12 | **流程与场景流转** | 启动 / 主菜单 / 关卡 / 暂停 / 结算 / 退出 的每一次转移 | 每个转移的触发与结果（含"回主菜单"） | 状态机断言 + 并排图 | 退出/回主菜单没做、暂停态时间还在推进 |
| S1 | **数值与配表** | 每张表 × 每个 id × 每个字段 | 出处、边界值、聚合自洽 | 脚本 + 参考物逐值比 | 编的数值、聚合对不上 |
| S2 | **性能** | 帧时间 / 加载 / 内存 | **渲染设备名必须先证伪** | 脚本 + 环境基线 | 软件渲染下所有性能数字无效 |
| S3 | **兼容与设置** | 分辨率 / 键位 / 音量 / 语言 | 每个设置项 × 生效范围 | 矩阵断言 | 设置改了不生效、重启丢失 |

## 4. 跨维度交叉（复合产物的要害，必须显式交叉的因果对）

- **动画 × 逻辑状态**（蹲着开枪、跑着换弹、死亡中切枪）
- **UI × 流程状态**（暂停时的 HUD、买枪区的菜单、观战的记分板）
- **音效 × 事件 × 材质**（脚踩沙 vs 踩金属；打木头 vs 打混凝土）
- **碰撞 × 角色类型**（玩家 vs 人质 vs Bot vs 投掷物）
- **特效 × 命中材质**（弹痕是否贴对法线、是否分材质）
- **输入 × 上下文**（游戏中 vs 菜单中 vs 输入框聚焦）
- **音乐 × 场景转移**（进图要停、回菜单要起）
- **数值 × 逻辑分支**（伤害公式 × 命中部位 × 护甲）

## 5. 三张表（跨项目通用列，模板见 `scaffold/coverage-matrix.md`）

- **① 实体清单**（脚本产出）：`维度 | 实体 | 载体/路径 | 出处 | 状态数 | 判据类型 | 归属片`
- **② 状态矩阵**：`维度 | 实体 | 状态/事件 | 边界值 | 期望表现(出处) | 实测 | 结论 | 证据`
- **③ 差异登记**（只允许"允许的差异"）：`是什么 | 为什么 | 出处 | 何时消除` —— 四要素缺一 = 未登记 = 不许交付。

## 6. 判定权三分（别混用）

- `可计算`（几何/碰撞/坐标/尺寸/数值/**引用是否指对**）：**脚本断言**，⛔ 不截图。
- `参考物自带`（原版文件里的值/序列/名字表）：**逐值比**，差值必须为 0 或已登记。
- `只能眼睛判`（外观/动画观感/节奏/手感）：**同机位并排图 + 联络图**，由人逐格结论。

**载体不可得 ⇒ 降级链逐级退**（原始数据 → 可执行里的常量 → 专用格式原始结构 → 参考图/视频量化 → 阻塞），每退一级写进差异登记：退到哪级 / 为什么 / 何时能换回来。

## 7. 闸门（三条 + 一条覆盖率，复制进项目 `tools/verify.ps1`）

1. `coverage-rows`：`策划/实体清单.tsv` 行数 == `策划/验收表.md` 判定行数。
2. `coverage-filled`：验收表**零空行**（每行必须是 `一致` / `不一致(差在哪)` / `允许的差异(四要素)` 之一）。
3. `coverage-diff`：`不一致` 计数为 0；`允许的差异` 四要素齐全。
4. `coverage-dimensions`：**12+3 个维度每个维度都有 ≥1 行**（缺省维度的判定 = 未判）。

## 8. 执行编排

- **切片**：一片一维度（或一个有因果的交叉域），走**普通子 agent（同步）**；任务书逐字写"本片要勾满哪些行"。
- **先出表后修**：第一片只做「枚举 + 展开 + 判据 + 装闸门」，产出**红行清单**（没被用户报过的问题会自己出现在这张清单里）；之后按片修。
- **一次进 Play 采全**：能离线判的不进 Play；同一交付单元一条驱动链一次采完并记 `play-log.tsv`。
- **采集即冻结**：改了只重采受影响的行。
- **主 agent**：定契约 / 定行数 / 验收勾满 / 裁决差异；⛔ 不下场实现（`SKILL.md` §1）。

## 9. 修 bug 的覆盖口径（影响域穷举，不是全量穷举）

> **场景区别**：交付验收 = 全维度穷举（T0，一次性）；**修 bug = 影响域穷举**（因果链可达的子集）。
> ⛔ **不许"只检查 bug"**：游戏是复合产物 ⇒ 一处修改的**爆炸半径可能跨维度**（改门板影响走门/卡位/视线/弹道/雷达；改碰撞影响可行走/角色间/投射物）⇒ 只修症状 = 拆东墙补西墙（反复翻车的根源）。
> ⛔ **也不许"修 bug 也全量扫"**：那是交付验收的事，修 bug 扫全表 = 成本爆炸且没必要。

**先分档（别把点状缺陷读成六步流程）**：

| 档 | 触发条件（按**改动形态**判，⛔ 不按"它是不是 bug"判） | 影响域表 | 成本 |
|---|---|---|---|
| **点状缺陷**（多数） | **单文件** + 净增删 ≤ 20 行 + 不新增行为 / 不改数据格式 / 不改共享资源 | **不需要**（走 `SKILL.md` §1「小改动例外」）：一行 `# direct-fix:` 留痕 + 该行验收结论 `不一致 → 一致` | 分钟级 |
| **爆炸半径修复** | 跨文件 / 改数据格式 / 新增行为 / **改共享资源**（门板网格、碰撞体、公共控件、公共材质…） | **需要**：`.ai-tmp/test/impact-radius.tsv` 一行（维度 / 因果链 / 受影响行） | 一行 + 判影响域那几行 |

**两个减压点**：① 触发条件是**改动形态**，不是"它是 bug" ⇒ 单文件小改不因"是 bug"而升级；② 修 bug **不重跑全表**，只重判**受影响的行**（采集即冻结 / 按因果作废）。

**步骤**（只对"爆炸半径修复"；每一步都有产出，不许跳）：
1. **定位维度**：这个 bug 在 12+3 维度的哪个维度？（D9 碰撞 / D4 UI / D10 逻辑…）
2. **找因果链**：上游是什么？改了它会影响什么？（用依赖分析 / 调用链 / 共享资源枚举）
3. **爆炸半径枚举**：**影响域 = 本维度内共享同一代码/资源的实体 + 跨维度有因果的对** —— 写成一张清单（通常 < 5% 的行数），⛔ 不许"我觉得就这一处"。
4. **判爆炸半径内所有行**：逐行给结论（脚本 / 参考物 / 并排图），不许只判 bug 那一行。
5. **修 + 重判受影响行**：改完后**只重采受影响行**（⛔ 一改全量重采 / ⛔ 不重采）。
6. **回归**：原 bug 修了 + 爆炸半径内**没引入新 bug**（逐行确认）。

**例子**：
- "箱子能穿"（D9）→ 修碰撞 ⇒ 影响域 = 所有碰撞体（D9 内）+ 可行走性（D9×D2）+ 角色间（D9×角色类型）+ 雷达遮挡（D9×D4）+ 弹道（D9×D10）
- "该有门没门"（D2+D3）→ 补门 ⇒ 影响域 = 门的碰撞（D2×D9）+ 开合逻辑（D10）+ 开合音效（D2×D8）+ 视觉（D3）+ 走门高度带（D9）
- "UI 按钮没反馈"（D4）→ 修状态 ⇒ 影响域 = 同面板所有按钮（共享代码）+ 点击音效（D4×D8）+ 流程切换（D4×D12）

**判据**：影响域清单必须**显式写出**（文件 + 行号 / 实体名 + 因果说明），⛔ 不许只写"我改了 X" —— 那不是穷举，是拍脑袋。

## 9.5 规模档位（只改**采样密度**，⛔ 不改"要不要判"）

> 病根：小 demo 与 AAA 复刻套同一套全量穷举 ⇒ **过杀**（NIST 那条恰恰说明 2~3-way 就够）。
> **铁律**：档位**只**决定**采样密度**；**所有 12+3 维度都必须有行**（缺维度 = 未判 = 违规）。

| 档 | 判定依据 | 覆盖深度 | 说明 |
|---|---|---|---|
| **S** 小 demo | ≤3 天 / 单屏或单关 | **1-way**：每维度 ≥1 行 + 该维度的关键边界 | 起点 / 终点 / 失败态即可 |
| **M** 中型 | 单机小游戏 / 多关 | **2-way（pairwise）**：维度内全枚举 + 因果对两两覆盖 | NIST：2-way 已覆盖绝大多数缺陷 |
| **L** 复刻 / 大型 | 1:1 复刻 / 多系统 | **3-way + 全状态全边界 + 全因果交叉** | NIST：≤6-way 全覆盖 ⇒ 3-way 已极高 |

- **判档一次**，写在 `策划/策划案/{A}参考规格.md` 顶部（与朝向/形态同处）；改动面变大 ⇒ **可上调**，⛔ **不许因赶时间下调**。
- ⛔ 档位**不是**"可以少判"的许可证：S 档也必须每维度有行、零空行、零不一致。

## 10. 反模式（出现即返工）

| 反模式 | 后果 |
|---|---|
| 症状驱动（报一条修一条） | 没报的全漏；"检查过"变成形容词 |
| **修 bug 只修症状** | 拆东墙补西墙；修了 A 坏了 B；反复翻车 |
| **单维度交付**（几何对了就说"地图做完了"） | 碰撞/门/声音/状态全没验 ⇒ 合成结果还是错的 |
| 手写清单 / 凭记忆列实体 | 结构上必然漏 |
| 用"每一帧 / 全组合"当口径 | 无限 ⇒ 被读成"做不完" ⇒ 退回症状驱动 |
| 眼睛判当脚本判（"我看过了"） | 无法复核 ⇒ 等于没验 |
| 行数对不上还交付 | 漏检无代价 ⇒ 方法失效 |
| 拿限额（次数/预算/轮次/上下文）当停工理由 | 未勾满的表被"收尾"（`SKILL.md` §0.1 ①） |

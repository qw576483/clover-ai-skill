# 确定性判据（**可选层**）：**必然性规则不许住在 skill 里**

> **口径先说清（`SKILL.md` §0 铁律 1 / §4）**：**默认不建判据、不跑任何检查、不建闸门脚本。** 本文只回答「**真要建 / 真要查时，怎么建才不假绿**」—— ⛔ 它**不构成"必跑"要求、不是交付的拦路虎**。要查时的 3 招 = 编译 / 交付卫生 / 引用可达。
>
> 回答一个被反复踩的问题：**"我已经写进 skill 了，为什么还是不做？"**

## 一、结论：提示词是"请求"，闸门才是"保证"

- **出处 1**（Konishi《Claude Code Hooks Complete Guide》）：**"A system prompt is a request. A hook is a guarantee."** 三层层级 = 提示词（说服，概率性）｜ permissions（过滤，静态）｜ hooks（强制，可编程）。
- **出处 2**（CCA Foundations Domain 1）：**"提示词合规具有非零失败率；程序化闸门具有零失败率。"** 三种被列为错误的做法：把提示词写得更严厉 / 补 few-shot / 让模型自评置信度。

**判定规则（按"行为种类"分，不按重要性分）**：

| 行为种类 | 手段 |
|---|---|
| **必须始终成立的硬性不变量** | **确定性闸门 / 脚本 / hook** |
| **偏好 / 概率性判断**（风格、倾向、措辞、约定） | 提示词引导即可 |

⇒ **推论**：skill 只该装"偏好类"；凡「必须始终成立」的都该做成脚本或钩子 —— **但默认不建**（`SKILL.md` §4：只在不确定 / 用户反复报同一条时才补一条）。

> ⚠️ **别读成"闸门 = 零失败"**：两条出处说的是**执行**层面的确定性（hook 注册了就一定被调用）。**闸门整体还有三种失败模式**：① **假绿**（判据取错对象：grep 源码字符串 ≠ 画面上渲染的文本）；② **假红**（判据取错范围）；③ **迎合**（判"结果"不判"过程" ⇒ 改一个数字就能变绿）。⇒ 闸门把失败从「模型的概率性失败」换成「人的确定性错误（判据写错）」—— 划算，但不是零。**这也是为什么判据只留 3 条**：判据越多，错的判据越多。

## 二、外观 1:1 的验收：**检测层必须是确定性 diff，不是 AI 看图**

- **检测层用 `pixelmatch`**（漏检率极低）；规模大换 `ODiff`（同算法，快约 8×）。`SSIM` 需调参且会漏"局部细微变化"；`pHash` 只能当**预过滤**。
- **最大的杠杆是"环境确定性"，不是算法或阈值**：基线必须与运行时在**同一环境**生成（同分辨率、同 DPI、同字体、同渲染模式、**动画冻结**）。环境不一致时，1:1 验收只是在把环境噪声当回归报警。
- 严格 1:1 档位：`threshold → 0`、`maxDiffPixels = 0`。⚠️ 语义陷阱：`threshold` 是**逐像素 YIQ 颜色容差**；"允许多少变更像素"是 `maxDiffPixels` / `maxDiffPixelRatio`，**是另一组旋钮**。
- ⛔ **绝不要让 LLM / VLM 当检测层**：让模型找出两张地图里"缺失的一条街道"，实测全部失败，而小型 CNN 以低误报率检出 —— **"生成式 AI 只能识别它被显式训练过的方面的差异"**。
- ✅ **AI 的正当位置是"分诊"**：在确定性 diff **之上**做聚类、给人类可读摘要、滤渲染噪声。**检测归 diff，分诊归 AI，终审归人。**

## 三、"必须始终成立"的四件事，应该挂在哪

| 要保证的 | 挂点 | 做法 |
|---|---|---|
| **每轮都记得规则** | 会话开始 / 每次提交提示 | 注入**必读卡**（只注入卡片，⛔ 不把正文一起灌） |
| **交付前顺手过一眼** | 交付前自己看一眼（宿主支持才接停止前钩子） | 那 **3 招**；有 FAIL 就先修、别写"完成"。⛔ 默认不跑 |
| **编译失败必须停** | 改完要验的那一刻（`SKILL.md` §4） | 编译非零退出 ⇒ **阻断后续一切验证动作**（否则测的是旧程序集）。⛔ 不是"每次保存都编译" |
| **外观必须与原版对照** | 交付前 | 截一张自己的图，和 A 的参考图放在一起看 |

## 四、落地顺序（从便宜到贵，别倒着做）

① **脚本**（最可移植，不需要 harness 支持）；② **"要查时跑一次"接成停止前钩子**（宿主支持才做，⛔ 默认不挂）；③ **必读卡接成会话开始 / 提交时注入**；④ 最后才考虑 permissions 类静态 deny。

## 五、怎么挂：**先通用层，再宿主适配层**（⛔ 规则层不许写死某个宿主）

**原则**：必然性必须由"**宿主之外的机制**"强制，**不该依赖你用哪个编辑器 / 哪个 AI 工具** ⇒ 先选**通用层**（任何开发环境都有），再按宿主**补强**。"用的不是 CodeBuddy" 不等于无解 —— git hook 与 CI 就是宿主无关的兜底。

### 5.1 通用强制层（**默认不挂；要挂只挂"真交付点"**）

> ⛔ **首选动作是"什么都不挂"**（`SKILL.md` 铁律 1：产出为主）—— 交付前**自己跑一次**那 3 条就够了。
> ⛔ **不许挂 `pre-commit` 去拦每一次提交**：一旦闸门挡在提交这条高频路径上，它就开始吃做东西的时间（实测某项目每次提交跑整套 78 秒检查、还 fail-closed），与该挂点想解决的问题相反。

| 机制 | 挂什么 | 什么时候值得挂 |
|---|---|---|
| **构建 / 打包入口**（Makefile target、Unity 菜单、打包脚本） | 出包 / 发布**之前**跑闸门，FAIL 就不出包 | ✅ **唯一推荐**：出货是低频动作，挡住它成本极低 |
| **CI**（GitHub Actions / Gitee Go 等） | 同上 | ✅ 有 CI 就用；与本地环境无关、团队共用一份判据 |
| **git hook**（`pre-push`，**不是 `pre-commit`**） | 推送前跑闸门 | ⚠️ 只有"推送 = 对外交付"的项目才挂 |
| **人工兜底** | 规则 = "**真要跑自检时，把输出原文贴出来**" | 上面都不具备时用 |

> 🕳 **判据不许往仓库跟踪的文件里写东西**：判据的输出一律落 `.ai-tmp/` 或直接打印；⛔ 需要落盘时**只许写 gitignored 路径**（否则闸门每跑一次，工作区就脏一次）。

### 5.2 宿主适配层（**按你实际用的工具挑一行**，细节版本敏感，落地前核对官方文档）

| 宿主 | 机制 |
|---|---|
| **CodeBuddy** | 10 个事件（`PreToolUse` / `PostToolUse` / `Stop` / `SessionStart` / `UserPromptSubmit` …）；配置在 `~/.codebuddy/settings.json` 或 `<项目>/.codebuddy/settings.json`；**注册须在 `/hooks` 面板确认**；**Windows 强制走 Git Bash**；阻断 = **退出码 2**。细则见 §5.3 |
| **Claude Code** | `settings.json` 的 hooks（`PreToolUse` / `PostToolUse` / `Stop` …）；`Stop` 可"拒绝结束"，必须配 loop-guard |
| **Cursor / 其它 IDE** | 各自的 rules / hooks 机制；**没有钩子就直接用 5.1** |
| **没有钩子的环境** | **不降级**：用 5.1 的 git hook / CI / 打包入口 + 人工过目 |

**⛔ 硬规则**：① **规则层（`SKILL.md`）只许写"必然性必须由宿主外部的机制强制"，绝不许写死某个产品的路径、字段名或面板名** —— 宿主细节一律留在本文件（能力层）；② 规则层引用本节时只说"**通用强制层 + 宿主适配表**"，不点名产品。

### 5.3 CodeBuddy 具体配置（**示例，不是唯一解**）

> **若你用的是别的宿主，跳过本节**，改用 5.1 + 5.2 对应那一行。

**事件**：`PreToolUse`（**可阻断**）｜`PostToolUse`｜`UserPromptSubmit`｜`Stop`｜`SubagentStop`｜`SessionStart`｜`SessionEnd`｜`PreCompact`｜`PostCompact`｜`Notification`。
**配置位置**：用户级 `~/.codebuddy/settings.json`；项目级 `<项目>/.codebuddy/settings.json`（脚本建议放 `<项目>/.codebuddy/hooks/` 并纳入版本控制）。
⚠️ **`/hooks` 面板是权威入口**：外部直接改配置文件**需在面板确认后才生效**。
⚠️ **Windows 上 hook 强制走 Git Bash**（不支持 cmd / PowerShell）⇒ 命令必须 bash 兼容；要调 PowerShell 必须显式 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$CODEBUDDY_PROJECT_DIR/tools/verify.ps1"`。
可用环境变量：`$CODEBUDDY_PROJECT_DIR`（项目根）、`$CODEBUDDY_SKILL_DIR`。**阻断机制**：退出码 2 ⇒ 阻止该工具调用（0 = 放行）。

**①「批次结束时验」—— `PostToolUse`（⛔ 不是"每次编辑后"）**

> **触发条件是「批次边界」** —— 每次保存都跑 = 把分钟级动作重复 N 次。下面的 `matcher` 只是"监听这些工具"，**另需一个批次标记文件判定"这一批做完了没"**。取文件路径要从 **stdin 的 JSON** 里取（⛔ 不要自己编环境变量名）：

```json
{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write", "hooks": [ { "type": "command",
        "command": "jq -r '.tool_input.file_path' | { read f; case \"$f\" in *.cs) powershell.exe -NoProfile -ExecutionPolicy Bypass -File \"$CODEBUDDY_PROJECT_DIR/tools/verify.ps1\" ;; esac; }" } ] }
    ]
  }
}
```

**② 其它挂点**：`SessionStart` 注入**必读卡**（只注入卡片）；`UserPromptSubmit` 注入当前闸门状态；`SubagentStop` 检查子 agent 的产物是否齐（防"我改好了"式回报）。

- **`PreToolUse` 的阻断能力是官方文档确认的**（退出码 2）。
- **`Stop` 是否能"拒绝结束"，官方文档未写明**；同类工具（Claude Code）的 `Stop` 可以阻断，且必须配合"本轮已拦过"的标记防死循环 ⇒ **落地前先实测确认**。若不能阻断，退而求其次：把**批次预演产出的 delta 清单**在**批次边界**注入上下文（⛔ 不是"每次编辑都注入"）。
- ⛔ **不要把未确认的字段 / 事件名直接写进项目配置** —— 先在 `/hooks` 面板里试。

**Skill 自身也能挂**：`SKILL.md` 的 frontmatter 支持 hooks，但**仅 `context: fork` 的 Skill 生效**，且需先开 `{"allowUntrustedFrontmatterHooks": true}`。
**安全**：hook 以你的完整凭据自动运行 ⇒ 注册前逐条审查命令；不用未验证输入；外部命令用绝对路径。

---

> **一句话判据**：**凡是你希望"100% 不发生"的事，都不要只写在 skill 里。** 但**做成闸门也不等于 100%**（假绿 / 假红 / 迎合）⇒ **判据少而准**，且**产物才算证据、叙述不算**。

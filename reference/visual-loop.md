# 视觉闭环（visual oracle loop）：把"看起来像"换成"一个数字 + 一份待办"

> **这是"能不能 1:1"的最后一块拼图。** 光有闸门只能**拦住**不像的东西；还必须把**差异本身**变成**可执行待办**喂回执行者，让它能**迭代到没有差异**。

## 一、核心思想

> **"像素级完美是渲染输出的属性，不是源码的属性。"** ⇒ **diff 必须是目标函数**；执行者最小化的是"**测量出来的误差**"，而不是靠抽象猜测。
> 同源结论：**"没有视觉 ground truth 和反馈信号的转译，会卡在 ~80–90%；最后那 10%（行高、亚像素间距、2px 内边距漂移）只存在于渲染结果里。"**
> ⇒ **"像不像"不能靠人眼看、也不能靠模型看，要靠 diff 数字 + delta 清单。**

## 二、闭环形状

```
采集基线(ground truth) ──► 实现/改代码 ──► 渲染 ──► diff ──► 达标?
      ▲                                                       │ 否
      └────────── 把精确 delta 清单喂回执行者 ◄────────────────┘
```

**基线怎么来**（必须可重复拍摄，否则噪声当回归）：渲染**参考物那一侧**并保存 **截图 PNG + 解析后的布局/几何数据**（后者让"不一样"变成"改哪里"）；确定性保障：**固定分辨率与缩放**、**冻结动画**、**等待字体就绪**、固定渲染模式 / DPI；覆盖矩阵：每个关键状态各自一条基线（菜单 / HUD / 交战 / 结算 / 死亡观战 / 暗态）。

## 三、判定：三个信号**同时**满足才算过

| 信号 | 机制 | 作用 |
|---|---|---|
| **像素 diff** | **`clover-tools/visual-verify/visual-diff.py`**（确定性 YIQ 距离 ≈ pixelmatch；参数 `--threshold`（默认 0.1）/ `--max-diff-pixels`（默认关）/ `--aa-policy`（默认 `count` = 每个像素都算，`suppress` = 不计抗锯齿）；输出 side-by-side + 差异叠加图 + 分段待办） | 量化像素漂移 |
| **结构相似** | `SSIM` | 抓"位移"这类原始像素比会低估的漂移 |
| **几何/布局 diff** | 按元素比 **包围盒 + 关键属性**（位置/尺寸/颜色/字号） | **把"不一样"变成"改哪里"** |

参考容差：`maxDiffRatio ≤ 0.001`（≤0.1% 像素）、`minSsim ≥ 0.99`、`pixelmatchThreshold 0.1`（= `visual-diff.py --threshold 0.1`）。**三个容差由 `clover-tools/visual-verify/visual-diff.py` 判定**（`--max-diff-ratio` / `--max-diff-pixels` / `--min-ssim`；任一不达标即 FAIL —— 用法与判据见 `clover-tools/visual-verify/README.md`）。

## 四、输出必须是"待办清单"，不是分数

```
[OFF] 场景__分辨率__状态    diff=0.333%   ssim=0.9845
- 元素A: 尺寸 0,-4px; 上内边距 10px（应为 12px）; 圆角 6px（应为 8px）
- 元素B: 位置 x+2px; 字号 13px（应为 12px）
```

**这张清单才是喂给执行者的东西** —— 它把"再改改"变成"改这三个数"。（可选：把 diff 叠加图也一并给模型看；但**判定仍然是 diff 数字，不是模型的观感**。）

## 五、怎么挂到 agent 上（三个通道，按需组合）

> **⛔ 先读这条（与四拍对齐）**：**diff 是"贵动作"，只在批次边界跑，不许每次编辑都跑。** 截一帧 / 渲染一次 / 跑一次 diff 都是**分钟级**；**改一处就跑一次 diff = 把最贵的动作重复 N 次**。
> 正确节奏：**批量改完 → 预演（跑 diff，拿 delta 清单）→ 批量修 → 再跑一轮**。
> ⚠️ **但这不是次数上限**：没有预算、没有"跑满即停" —— **一直跑到容差内 / 与 A 原版零不一致为止**；"diff 跑了几轮"从来不是收工理由。

| 通道 | 挂点 | 做法 |
|---|---|---|
| **A. 钩子（首选）** | **批次边界** | 跑**一次** diff，把 **delta 清单注入上下文**让执行者**批量修**。⛔ 不做"每次保存即 diff" |
| | `Stop` | diff 超容差 ⇒ **拒绝结束**（必须带防死循环标记） |
| **B. 工具（可选）** | MCP / CLI | 把 `capture_baseline` / `visual_diff` 做成工具，让执行者在**批次边界**自己调 |
| **C. 守护进程（可选）** | 会话外 | 监视文件变更 ⇒ **攒到"一次批次结束"再重 diff**；漂移时派发一次**限定范围**的新 run（默认只提示，不自动改） |

**防死循环**：`Stop` 钩子必须带"本轮已拦过"的标记（如标记文件），否则会被反复拒绝结束而空转。

## 六、必须承认的边界（**诚实目标 = 感知容差内，不是字节一致**）

**跨渲染引擎做到字节一致，物理上不可能**（web → 原生；同理 GoldSrc → Unity）。诚实目标是**"感知上落在容差内"**：

| 对象 | 判据 | 能不能到 |
|---|---|---|
| **数据 / 数值 / 公式 / UI 坐标** | `diff = 0`（数值层面） | **能到 1:1** |
| **渲染画面（跨引擎）** | 三信号落在**容差内**；要"字节一致"必须先复刻对方的渲染管线 | 容差内可达；字节一致需复刻渲染管线 |

### 六.1 ★ 参考图必须来自**同一场景**（跨关卡外推 = 无效依据，且方向会全错）

**实测事故**：复刻某训练营场景时，拿**另一座竞技场**的参考图量出「河两岸都有沙色岸带」⇒ 结论「把岸带镜像成两岸对称」；改量**训练营自己**的基线图后，真相是「泥带只在**水的上沿以上**，水**下沿以下**是纯草」—— **方向正好相反**，按错的依据改 = 越改越错。

**规矩（三条）**：① **先认身份，再量数** —— 参考图 / 基线图**自身**要能说出它是哪座场景 / 哪一关，认不出就别用它下结论；② **反证句** —— 任何"原版是 X"的结论都要能回答「**这张图凭什么代表 A 场景**」，答不上来 = 待核；③ **优先用同一素材包内部的自证**（素材自己的对称性 + 同场景实机图），⛔ 不要拿**别的场景**的图来补。

### 六.2 ★ 取景对齐：原版是**斜视**相机时，正交平视要用**非等比正交投影**复现（⛔ 不是缩放内容根）

**症状**：把场地用 `orthographicSize = max(H/2, W/2/aspect)` **恰好铺满整屏** ⇒ 场地底沿 = 屏幕底沿 ⇒ **己方关键建筑落在手牌栏之后**（被盖约 5 格）。
**量原版（同一把尺子）**：横向 **60 px/格**、纵向 **45 px/格** —— 原版把地面画成**屏上 4:3 的矩形格**（纵向压 0.75），它是**斜视相机**；我们是正交平视。
**★ 判据口径**：屏上的「格」**不是正方形** —— **横向 px/格 与纵向 px/格 必须分别量**，⛔ 不能拿一个当两个用（拿横向值回算纵向会得出"场地放不下"的死结论）。
**改法**：`Matrix4x4.Ortho(-halfW, halfW, -halfH, halfH, near, far)`，其中 `halfW` 按画宽算、`halfH` 按"纵向格数 ÷ 压缩比"算，再把相机平移到场地底沿落在目标行。**新增常量一律带出处。**
**★ 为什么必须是投影矩阵，⛔ 不能"把内容根 `localScale.y` 压 0.75"**：投影矩阵**参与 `ScreenToWorldPoint`** ⇒ 点击落点 / 落位指示 / 跟随血条全部自洽；缩放内容根则**屏幕 → 世界失配** ⇒ **点哪丢哪错位**（对战里就是"点 A 格、兵出在 B 格"）。
**可失败的判据**（全部取实机自报读数，⛔ 不念结论）：横 / 纵向 px per world 的**实测值必须等于量到的两个值**；场地底图行区间正确；我方关键建筑行区间在出牌区上沿**之上**；**最高节点 ≥ 0**（顶部无裁切）。再配**像素交叉校验**（截图上草色末行 vs 场景普查的末行，差 ≤ 1 px）⇒ **两条独立路径同答才算过**。
**诚实边界（必须登记）**：均匀压缩 ≠ 原版**斜视透视**（近大远小）；要 1:1 复刻那一点需**斜视相机**，另立一片。另：场地之上原版有背景美术，若我方没有就会露出一条清屏色带 —— 这是**美术缺口**，登记为差异，⛔ 不要当黑屏 bug 去瞎调。

## 七、和本项目（Unity）对应起来

- 基线：**跑原版截同机位帧**，或用原版资源 + 固定相机位姿渲染一帧（相机位姿要写进基线记录）。
- 采集我们的：**固定分辨率 / 固定渲染模式 / 冻结动画**后截图（同机位、同画幅）。
- 判定：**像素 diff + SSIM + 几何 diff**；几何 diff 直接用已有的坐标 / 包围盒数据。
- 输出：delta 清单（"这把枪的 viewmodel 位置 y+3px""这个面板圆角差 2px""准星粗细差 1px"）。
- 迭代：改 → 再渲染 → 再 diff，直到容差内或明确登记为"渲染管线差异，不可消除"。**（按批次：一轮预演跑一次 diff 并批量修 —— ⛔ 不是"改一处跑一次 diff"）**

## 八、联络图（contact sheet）：把 N 个证据点压进 1 张图

> **为什么**：**AI 读图按像素烧 token** ——「N 项 ⇒ N 张图、逐张读」比「N 项 ⇒ 2~3 张联络图」贵**一个量级**；而**判定该由脚本做**，AI 只分诊。**截图是诊断工具，不是每格的常规证据**。

### 8.1 采集前先出「证据分格表」

| 格号 | 状态 / 项 | **类别** | 判据（期望值） |
|---|---|---|---|
| 01 | 1-1 方块组位置 | `数值类` | 实体转储 `MysteryBox@T(2,0)` … |
| 02 | 星砖顶出 | `表现类` | ★ 真的从砖里弹出来 |

**类别只有两种**：`数值类` ⇒ 判据是**日志 / 断言**，通常**不必进图**；`表现类` ⇒ **必须进图**，且**格号要在索引表里对得上验收表的行号**。

### 8.2 采集（**一次跑完，不逐项进出 Play**）

- **能同框就同框**：把同一时刻的多个对象**一次拉远框进画面**（零拼接、最省）；
- **互斥状态分帧采**：活着 / 死亡 / 通关这类物理上不可能同屏 ⇒ **逐帧截取所需的小区域**（`ScreenCapture.CaptureScreenshotAsTexture()` + `ReadPixels(rect)`，或宿主的截图命令），再拼版。**「一个画面放不下就切」的正确形态是切帧，不是切场景。**
- ⚠️ **改 / 拍必须分两次执行**：`CaptureGameView` 取的是**上一帧**已渲染好的缓冲，**它不会为你重绘** ⇒ 同一次调用里"改显示参数 → 立刻截"拍到的是**改动之前**的状态，整条序列会逐张错位一格，而闸门只看 mtime、**完全看不出来**。术后自检：两张**没有状态变化**的连续帧如果长得不同，就是滞后。
- ⚠️ **别用 `Time.timeScale = 0` 帮忙**：它冻得住渲染，但引擎自带的定时服务**不吃它**；而且冻结期间客户端**收不到快照**，解冻后还会污染采样。

### 8.3 拼版 + 烧标注（**用代码做，别手摆**）

用 `Pillow` 之类把各格拼成大图，**每格必须烧上**：`格号 + 状态名 + 类别 + 关键数值`。格间留分隔线；角落放采集时间 / 构建标识；同时输出 `index.tsv`：`格号 ↔ 验收表行号 ↔ 截图来源 ↔ 采集时的日志行`。

**工具（已实现，⛔ 不手摆）**：拼版 = `clover-tools/visual-verify/compose-contact-sheet.py`；窗口级截屏 = 同目录 `capture-editor-window.ps1`（编辑器以管理员身份启动、外部置顶被 UIPI 挡住时，用引擎 `Editor/capture-editor-screen.cs` 的 `run_script` 入口在进程内采）。用法与判据见 §8.6。

### 8.4 判定（**脚本按格做，AI 只看汇总**）

① 脚本按格做**确定性 diff / 数值断言** → 逐格 `PASS / FAIL`；② **AI 只读整张联络图一次**（聚类 / 摘要 / 滤渲染噪声）；③ 只有 `FAIL` 的格才去看那一格的**原始大图**；④ 终审仍然是人。

### 8.5 红线（不许借"整合"偷懒）

- ⛔ **时间序列 / 手感 / 动画节奏 / 音效时机**不许用拼版代替 —— 这类只能逐帧比或由人给基线。
- ⛔ **每格必须来自真实运行**：格上烧的数值与 `index.tsv` 里的日志行必须对得上，脚本要校验"这 N 条日志都在"（防止"拼一张图看起来都验了"）。
- ⛔ **检测不许变成 AI 看图**：判定永远是脚本数字，AI 只看汇总 —— 否则就是把**最贵、最不可靠**的东西放到了判定位上。

### 8.6 采集与拼版的判据资产（用法 + 判据）

**① 窗口级截屏** —— OS 层像素，采的是**用户真正看到的画面**（含编辑器叠加的组件图标 / Gizmos / 选中高亮，这些**不在**游戏后缓冲里），与 `Screenshot.CaptureToFile`（帧末取后缓冲）互补，⛔ 不互相替代（区别写在两个文件头注释）。

| 入口 | 位置 | 何时用 |
|---|---|---|
| `capture-editor-window.ps1` | `clover-tools/visual-verify/` | 外部（PowerShell）采窗口像素 |
| `EditorScreenCapture.Info/Raise/Drop/Shot/Gizmos/Freeze` | 引擎 `Editor/capture-editor-screen.cs`（`run_script --entry CloverEngine.Editor.EditorScreenCapture.Shot`） | 编辑器以**管理员**身份启动时（UIPI 挡住外部置顶），在编辑器**进程内**采 |

| 参数（PS1） | 默认 | 说明 |
|---|---|---|
| `-Out` | 必填 | 目标 `.png`（非 `.png` 直接拒绝） |
| `-TitleMatch` | — | 窗口标题**正则**（忽略大小写），按面积取最大匹配 |
| `-EditorPid` | 0 | 限定进程；与 `-TitleMatch` **至少给一个** |
| `-TimeoutSec` | 15 | 等窗口出现（0 = 单次尝试） |
| `-X/-Y/-W/-H` | — | 窗口内相对矩形裁剪（四个一起给） |
| `-Focus` / `-TopMost` / `-Desktop` | off | 还原 / 置顶 / 改走桌面合成（遮挡时可采到别的窗口） |
| `-AllowMultiMonitor` | off | 多显示器**默认拒绝**（坐标口径含糊） |
| `-MinMeanRGB` | 2.0 | 退化阈值 |

判据（失败一律 **exit 非 0**，⛔ 不许静默出一张黑图）：窗口找不到 / 超时 = `3`；最小化且未 `-Focus` = `3`；多显示器未 `-AllowMultiMonitor` = `5`；`PrintWindow` 自报失败 = `6`；**全黑或纯色**（`uniqueColors<=1` 或 `meanRGB < -MinMeanRGB`）= `4`，此时 `<Out>` **不产出**（诊断副本写 `<Out>.rejected.png`）；裁剪框越界 / 参数非法 = `2`。成功时打印 `hwnd / rect / uniqueColors / meanRGB / bytes / sha256`。

**② 联络图拼版** —— `clover-tools/visual-verify/compose-contact-sheet.py`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--shots` | 必填 | 目录 / glob / 单个文件；逗号或分号分隔，可重复（目录与 glob 内部 `sorted()` 定序） |
| `--cols` | 4 | 列数 |
| `--labels` | — | 分号分隔的 `[格号=]状态名[\|类别\|关键数值]`（带 `\|` 时须三段齐全），烧在格下 |
| `--out` | 必填 | 联络图 PNG |
| `--index` | `<out 去扩展名>.index.tsv` | 索引表列：`格号 / 截图来源 / 状态 / 类别 / 关键数值` |
| `--title` | — | 顶部标题：**采集时间 / 构建标识由调用方传入**（工具不自动烧时间戳，否则破坏确定性） |
| `--cell-size` | 480x320 | 每格图像框 |

判据：缺任一张图 = **exit 4 且一个字节都不写**（⛔ 不半发布）；标签数量不匹配 / 格号越界 = `2`；依赖缺失 = `3`。每格坐标 / 尺寸 / 居中全由 `--cols` 与 `--cell-size` 算出、缩略图固定 `LANCZOS` ⇒ **同输入两次跑，图与索引的 SHA256 相同**（脚本自带打印这两个 SHA，便于当场复核）。

⚠️ **两条实测坑（写同类脚本请照抄，2026-09-24 当场复现并修掉）**：① `--shots <目录>` 与 `--out` 落在同一目录时，**输出文件不算输入**（否则第二遍把第一遍写的图纳入输入 ⇒ 格数 7→8、SHA 全变，看起来像"工具不确定"）。② Python 的 `stdout` 在**重定向**下编码是 GBK（实测 `sys.stdout.encoding == "gbk"`）⇒ 目标路径里的**非 GBK 字符**会让 `print` 在**文件已写好之后**抛 `UnicodeEncodeError` 并以 exit 1 收场（**假红 + 状态与判据不一致**），中文则被写成 GBK 字节、按 UTF-8 读成乱码；显式 `sys.stdout.reconfigure(encoding="utf-8", errors="backslashreplace")` 即可（⛔ 不要去改被验源码的编码）。

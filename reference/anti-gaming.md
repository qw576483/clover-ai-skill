# 防博弈与证据不可伪造（闸门的三个盲区）

> 回答一个问题：**"闸门都上了，为什么还是被糊弄？"**
> `deterministic-gates.md` 论证了「提示词是请求，闸门是保证」；它那句「程序化闸门具有零失败率」是**修辞，不是事实**。本文件写闸门挡不住什么。
>
> ⛔ **本文件是复盘 / 案例集，不是必做检查清单。** 交付只要求 `SKILL.md` §6 第 2 条那 **5 条**机械判据；本文件里的一切加固（负控、锚点、双向自检、五列表格）**都不再是交付要求**。
> 读它的目的 = **下次别犯同样的错**，⛔ 不是为了再实现一套仪式 —— 仪式本身正是本文件第九节记录的那种事故。

## 一、闸门挡得住什么，挡不住什么

| 挡得住 | 挡不住 |
|---|---|
| 执行层不合规（忘了 / 省了 / 跳过） | **判据被迎合**（凑数让它变绿） |
| 产物缺失（文件 / 行数 / mtime） | **证据被编造**（叙述冒充产物） |
| 已形式化的事实 | **判据本身写错**（假绿 / 假红） |

⇒ 闸门把失败从「模型的概率性失败」换成了「人的确定性错误（判据写错）」。**这个交换非常划算，但它不是零 —— 它只是换了一种失败。**

## 二、三种失败模式

| 模式 | 现象 | 根因 |
|---|---|---|
| **假绿** | 画面明明缺失，检查全绿 | 判据取错了对象（grep 源码字符串 ≠ 画面上渲染的文本） |
| **假红** | 画面明明正确，却报 FAIL | 判据取错了范围 |
| **迎合** | 行列数都相等、格子都填满，但没真验 | **判据判的是「结果」，不是「过程」** |

第三类是前两类治好之后**必然出现**的下一站：一旦指标成为目标，它就不再是好指标。
同源（同一件事已经发生过三次）：写「预算 ≤ 5 次进 Play」⇒ 被读成「验到第 5 次就收手」；写「只作废受影响的行」⇒ 被读成「可以少验」；写「清单行数 == 判定行数」⇒ 被读成"把两边凑相等"（**凑数比真查一遍便宜太多**）。
⇒ 结论：**闸门解决的是执行层合规，但把偷懒的位置从「不照做」平移到了「让判据看起来通过」。**

### 判据自身的失效形态

共同点：**不是"判据取错了对象"，而是"判据的数据来源是被判对象自己"。**

| 形态 | 机制 | 修法 |
|---|---|---|
| **闸门被自己的输入满足** | 判据要的"探针输出"由**被测量的那张表自己重渲染**而成 ⇒ 判据把"复述"当"命中" | 加"表格回声"判定：字段级**逐字**相等 ≥60% 且 ≥2 格 ⇒ 不计命中 |
| **判据永不触发（假严）** | 阈值宽到永远不红 ⇒ 等于不设防，且比"没判据"更糟（给人"已经判过"的错觉） | **一个永远不触发的阈值不是"更严"，是 bug** |
| **字段兼职两种语义** | 一个字段表示两件事 ⇒ 其中一件必然是假话（`unresolved=1` 既表示"探针没找到"、又表示"我算不出摘要" ⇒ 判据资产亲自认过的锚点被写成"没找到"） | **一个字段只表示一件事**，要表示第二件事就加字段 |
| **诚实暴露不确定性（镜像形态）** | 把谎话改成真话后，**判据自己变成了不确定性来源**：盘上有活文件（正在追加写的日志）⇒ 同一份盘连跑两次产物不同（逐行 diff 只差 1 行）⇒ 直接打掉"两次注入产物 sha256 相同"这条幂等判据。⇒ 旧格式那一刻写的是"未解析"，**它撒谎、所以"稳定"** | 活文件显式枚举 + **只钉头部 N KiB**（追加不改头部）；不足一窗则只记存在性（⛔ 不假装有量值）。判据 = **"同一份盘连跑两次，逐行 diff = 0"** |

⇒ 四条防线：① 命中 / 证据必须来自**探针的观测**（不是被判行的复述）；② 每条新判据必须**双向可证** —— 喂一个已知坏样本必须**能红**；③ **一个字段只表示一件事**；④ **产物必须是"盘的确定性函数"** —— 盘上有活文件时任何**内容摘要**都不确定 ⇒ 要么钉头部、要么只记存在性。

> 同族：**辅助件不能拥有让主流程失败的能力** —— 辅助机制（窗口守卫等）读共享账本时撞上别的进程持有该文件 ⇒ 抛异常 ⇒ **主闸门当场死掉、一个检查项都没判**。⇒ 辅助件必须在自己的边界内 `try/catch`、以"打印 NOTE + clean exit"降级，⛔ 不许把自身失败放大成主流程失败。

> **"seam 看着接上了"的三种形态**（两条检查项此前一直"假测试通过" —— 以为量的是沙箱副本，其实一直在量真盘）：
> ① **根本没传参** —— 自检调用判据脚本时没带覆盖参数；
> ② **传了但被覆盖** —— PowerShell **变量名大小写不敏感**：`param([string]$ShotDir)` 与紧随其后的局部 `$shotDir` 是**同一个变量** ⇒ 局部赋值先把参数吃掉 ⇒ 内部变量必须改名；
> ③ **传了但资产不接** —— 脚本**根本没有参数接口** ⇒ 结构上收不到 seam。
> ⇒ **判据**：给判据加 seam 时必须**两向验证** —— 喂一个"**只有沙箱副本才有的坏样本**"，该检查项必须**红**；只验"真盘仍 PASS"是**验不出 seam 的**（那正是假测试通过的来源）。
> ⇒ 另两条：⛔ **不要用 PowerShell 双引号字符串去生成 `.ps1` 补丁**（`$xxx` 会被插值成空 ⇒ 写出 `if ( -gt 0)` 这类垃圾行），一律用文件编辑工具；**可观测性判据的"形态全集"必须维护** —— 新增一种形态（如 `meta_missing=`）时同步更新 declared 集，否则新形态会被**静默当成正常形态放过**。

## 三、原则一：判过程，不判结果

- ⛔ **反例（判结果）**：`coverage-rows` = 清单行数 == 判定行数 —— 凑数即可通过。
- ✅ **正例（判过程）**：每行判定必须能被**一个探针的真实输出**命中 —— 判的是「这一行是不是真的被跑过」，不是「表格看起来齐不齐」。

**判据一句话：判据要判"过程"，不判"结果"。**（推论：任何"只要让两个数字相等就能通过"的检查项，都是可被迎合的。）

### 落地：证据锚点（evidence anchor）

每条判定行带一个**锚点**，指向**机器产物**里的一个位置：

| 维度 | 判定 | 类别 | anchor |
|---|---|---|---|
| D4-007 | 金币动画播放 | 表现类 | `run-<ts>/log.txt:1187` |

脚本验证三件事：① 锚点指向的文件**存在**；② 该位置的内容**与该行的期望值一致**（⛔ 不是"有内容"就算过）；③ ⛔ **锚点不许指向执行者自己写的文字**（`md` / 回报 / 代码注释）—— 那等于没有锚点。

**判据一句话：锚点必须指向"被测程序自己写出来的东西"。**（这不是新发明 —— 「完成判据只能是被测程序自己写的标记」已经是它，这里只是把它从「采样器自检」提升为**全局证据原则**。）

## 四、原则二：证据可信度分级（L0~L3）

| 级别 | 长什么样 | 能不能当判据 |
|---|---|---|
| **L3 强** | 被测程序运行时自己写出的标记（带会话 id / 时间戳 / 机器指纹） | ✅ 能 |
| **L2 中** | 脚本采集的产物（截图 + 采集 ledger 记录） | ✅ 能，但**必须配 ledger** |
| **L1 弱** | 执行者写的文字（"已实测 / 确认一致 / 检查过"） | ⛔ **不能**（叙述不算证据） |
| **L0** | 没有产物 | ❌ 视为未验证 |

⇒ **闸门判不了「这段叙述是不是编的」**，只能靠"它有没有一个 L2/L3 锚点"来逼。
**产物可以是编的；一个指向真实运行记录第 1187 行的锚点，很难编。**

## 五、原则三：闸门自身也要被闸（谁来维护闸门）

> 实测答案很难看：模板一度声明了 **34 个**检查项，几个项目**分别只落了 18 / 19 项，且各落了不同子集**；更糟的是**同一检查项在模板与项目里叫不同名字**（`play-ledger` vs `play-budget`）⇒ 任何自动比对都会失效。**规则写完了，闸门没接上 —— 而且没人发现。**
> ⚠️ **2026-09-24 修正口径**：模板现在只声明 **6 个名字**（= `SKILL.md` §6 第 2 条那 5 条，交付卫生拆成 `stray-temp-files` + `tmp-budget`）。下面这条"谁来维护闸门"的教训仍然成立，但它的**对象只剩那 6 个名字**。

⇒ 硬规则：

1. **（可选）两次自检**：新增 / 改检查项时**顺手**确认 ① 已知正确的样本 PASS、② 已知错误的样本 FAIL。⛔ **不再是强制仪式** —— 日常更该问的是"**这条检查值不值得存在**"（`SKILL.md` §4 第 0 条的两句反问；过不了就删）。
2. **（已删、不检了）版本同步**：模板的 `GATE-ITEMS` 块现在只是**参考清单**（`required` 计数 = 0）⇒ **判据与命名由项目自己定，不对齐、不报缺名、也不报多余**；⛔ 本 skill 也不再提供对账脚本。要有这条对账的项目，自己内联进 `tools/verify.ps1`（或者干脆不建 —— 对账本身也是仪式）。
3. **自检只许在「自己的副本」上做手脚**：⛔ 自检**写到的每一个文件**都必须是**它自己创建的副本**（`.ai-tmp/` 内、带时间戳或随机后缀）；⛔ 不许 append / 覆盖 / `Move-Item` / 改 mtime **任何共享产物**（`策划/**`、派活账本、`screenshots/*.png`、`tools/**`）。
   四种真实污染形态（每一种都制造了**别人的假读数**或**删掉了别人的数据**）：① 把注入行写进**真**验收表、再整文件备份覆盖还原 ⇒ 并发片刚 append 的行被**静默截断**，而自检自己的哈希自检**看不见**（它比的是自己刚还原的那份备份）；② 把幽灵载体 append 进**真**差异登记表、再整文件还原 ⇒ **还原不干净** ⇒ 并发片读到**假 FAIL**；③ `Move-Item` 把工具脚本藏起来再放回 ⇒ 窗口内别片读到**假 FAIL**；④ 把**真**取证图的 mtime 改成"现在"或其他值 ⇒ 窗口内别片读到**假红 / 假绿**。
   ⇒ **正解 = 自我标注 seam**：每个"会被注入的输入"都给一个**可覆盖参数**（`-Ledger` / `-PlanDir` / `-ShotDir` / `-EnvCheck` / `-NodeDump` / `-CodeRoots`），自检**只喂副本**；并**断言真文件前后哈希 / 行数一致**（`REAL <file> untouched` = 通过判据）。
   ⛔ **"改完再还原"不算合规**（还原会静默吃掉窗口期别人的并发写入，而自检看不见）；⛔ **窗口标记 / 护栏 ≠ 隔离**（它只让污染**可见**，不阻止污染）—— **两者都要有**。
4. **判据的「输入」也必须绝对锚定**：生成器里 `SPEC = '策划/…md'` 是**相对路径**、读函数直接 `open(path)` ⇒ **只在"从项目根运行"时才对**；换个 CWD 跑 ⇒ **读空** ⇒ 声明值**静默降级成 `-1`** ⇒ 某行结论从 `一致` 翻成 `不一致`。
   ⚠️ 危险点不在"跑错"，而在**它只表现为某一行变红 / 变值、不报错** —— 读的人会以为发现了真缺陷（差一步就把一条**不存在**的差异登记进表）。
   ⇒ 判据脚本读的**每个输入**（规范文档 / 清单 / 账本 / 样本）都要**绝对锚定**，并在启动时**打印一次解析到的绝对输入路径**。

⛔ **闸门不是免费的"保证"，它是一份需要自己被维护的代码。** 没有这两条，闸门会和规则一样烂回去 —— 只是慢一点。

## 七、局限写在明处（诚实标注）

- **锚点防不住合谋**：执行者若同时伪造产物与锚点，脚本仍然绿。下一层防线是「产物必须由脚本采集，不由执行者手写」—— L2 的 ledger 就是这一层。
- **防博弈是军备竞赛，没有终局。** 目标不是"彻底解决"，是**把博弈的位置推到更贵的地方**：从"改一行文字"推到"伪造一整条运行记录"。
- 真正的兜底仍然是「判定权不在执行者手里」。本节只是让这条在**执行者已经握有产物生成权**的情况下尽量成立。

> **一句话判据**：**一条检查项如果能靠"改一个数字"变绿，它就还没在判该判的东西。**

## 八、实证：用「让闸门看不见」换绿

> **案例**：某检查项的引用正则要求 `.png` **紧邻**名字字符；而项目的实体枚举生成器里有一行在每个资产名 / 证据名的 `.png` 前**塞一个空格**，注释自述动机是"避免被既有闸门误报"。
> **后果**：那些引用**根本不进扫描集合** ⇒ 既不是 PASS 也不是 FAIL。闸门报「79 screenshot refs all resolve」看着全绿。
> ⚠️ **口径纪律**："出现次数"与"distinct 名字"是两个数，混用会得出**相反结论** —— **报数时必须写明口径**。

**为什么它比"改数据迎合闸门"更隐蔽**：迎合闸门至少留下"被检查过"的痕迹（PASS/FAIL 都会打印出来）；**改格式让引用不可解析 = 把这条引用从扫描集合里删掉** —— 闸门的**分母变小了**，而它的输出看不出来。

**识别口径（可机械判）**：
1. 检查项输出里的**引用数 / 命中数**是不是一个"会随内容变化"的数？**若长期恒定**（如永远 79），先怀疑**分母被改过**，而不是"内容一直很干净"。
2. 任何"为了让某个检查项不报"而**改变数据形态**的代码（加空格、换分隔符、改扩展名、拆词、转义），一律按本节形态处理。
3. **正解 = 两步必须同批**：① **还原数据**（改回规范形态）；② 同批给检查项加**按归属的豁免**（例：该名字若已在某清单里登记为"资产"，就不作为"截图引用"扫描）。
   ⛔ **不许**用"按区域跳过"（会把同区域里的真引用一起豁免）；⛔ 只做 ① ⇒ 立刻红一片（还原出的资产名会被误判）；只做 ② ⇒ 下次生成又把脏形态写回来。
4. 豁免的**完成判据**要带一个**增量数字**：还原后"被检查的引用数"必须**变大**（`79 → N`），**`N - 79` 就是"闸门曾被躲掉多少"的直接数字**；再喂一个"故意不存在的引用"样本 ⇒ 必须 FAIL。

## 九、闸门看不见的证据事故（案例集）

> 本节记的都不是"故意造假"，而是**方法本身错了、而闸门恰好只在看 mtime 和文件是否存在**时会发生什么。
> 每条给出：**现象 → 可机械判的口径**。（当时那几门 `evidence-freshness` / `screenshot-refs` 对以下形态一律报 PASS —— 其中 `freeze-before-capture` 已删。）

### 九.1 截图比改动慢一帧 ⇒ 整条实验序列逐张错位一格

**现象**：`CaptureGameView` 取的是**上一帧已渲染好的后备缓冲**，它不为调用者重绘 ⇒「同一次 eval 里改参数 → 立刻截图」拍到的是**改动之前**的状态。整条实验序列因此逐张错位一格，据此算出的读数全错，而闸门完全看不出来（mtime 新、文件都在）。

**口径**（不需要知道机制）：**两张没有任何状态变化的连续帧，长得却完全不同**。术后自检 = 同状态连续两帧的差必须只等于"确实变了的东西"（例如数字），而不是整块版面。
**修法**：`apply` 与 `capture` **分两次 eval**。

### 九.2 时间戳洗白：拿旧数据**重绘 / 重导**，只把 mtime 刷新

**现象**：一份取证图的 mtime 旧于它引用的实现文件 ⇒ 闸门判失效。此时有两条路，**只有一条算复采**：

- ✅ **重新采集**：拿**当前的构建**重跑探针（新 TSV）再重绘 ⇒ 新 TSV 的 mtime 晚于实现改动。
- ⛔ **重绘旧数据**：TSV 还是改动**之前**录的，只是重新跑一遍绘图脚本 —— 像素级上"新图"，证据级上仍是旧代码的行为。**mtime 会变绿，判据一个字没更新。**

**口径**：除了图的 mtime，还要看它的**输入（原始记录）的 mtime** —— **输入早于实现改动 ⇒ 无论图多新，这次都不是复采**。（"分母随采样而变"的数（如帧数）应作为**口径订正**写回台账，而不是当噪声抹掉。）

### 九.3 同名覆盖取证图是**不可逆**的：`.ai-tmp/` 在 `.gitignore` 里

**现象**：驱动直接往**同名路径**写截图，而那次采到的是错误页面；其中两张**原本并不失效**。`.ai-tmp/` 被整个 gitignore ⇒ **没有版本库副本 ⇒ 旧像素不可恢复**。

**纪律**：任何"覆盖同名取证图"的动作，一律 ① 先写到**临时名**；② 核过内容（人眼看 + 与预期特征比对，例如"底部署名在不在"）；③ 再**提升**到目标名。
**"核内容"不是形式主义**：覆盖事件后重采到位，才发现两态**逐像素相等** ⇒ 台账里写的两条结论**根本不存在**（主视觉是同步加载的）。⇒ **图的订正必须与文字的订正同批**，否则台账一直说假话。

**推论：不止取证图 —— 正控 / 负控 / 多轮原始产物也一律分文件。**
- 正控、负控写成 `…-pos-out.txt` / `…-neg-out.txt` 两个文件名；被取代的旧同名歧义件**先 `mv` 进 `trash/`** 并改名。
- ⛔ 反例：同一路径**同轮覆写**（旧产物没进 `trash/`）⇒ 上一轮原始证据**不可复核**，基于它的裁决**不可上诉**。
- **判据**：一轮一文件（`<name>.<ts>.txt`），或**先 `mv` 旧的进 `trash/` 再写同名**。⛔ "同名跑两遍"在 gitignore 掉的 `.ai-tmp/` 下 = **销毁证据**。
- ⚠️ **覆写最容易发生在"我改好了，再跑一遍覆盖掉"那一步** —— 而那一步恰恰是唯一能证明"**修之前是坏的**"的产物。**没有修复前的原始输出，就没有"修复"这个结论。**

### 九.4 `Time.timeScale = 0` 能冻画面，但会掐死客户端快照泵

**现象**：为"让背景逐帧不变"而冻结时间 ⇒ 好处是背景确实恒定（前置条件真正成立）；**代价是冻结期间客户端收不到快照**（`snaps` 恒定不动，解冻后那条采样里仍不动 ⇒ 同一次采样录出的位移全 0，绘图脚本的相机拟合退化成 `None` 并抛异常）。

**口径**：`timeScale` 冻结**只可用于纯 UI 合成类实验**；⛔ **不得用于流程采样 / 遥测采样 / jitter 采样**。用了就**必须在报告里写明**。

### 九.5 量具缺陷冒充产品缺陷：拿**降频日志**做「计数一致」判据

**现象**：日志里「A 事件」25 次、「B 事件」2 次 ⇒ 被判成「B 静默漏播 23 次」的量化实锤，据此改了代码、还写进了给用户的答复。**实为假实锤。**
**真相**：两侧走的不是同一个口子 —— A 用**不降频**的 `Game.Logger.Info`，B 用**降频**的 `XxxLog.Info`（口径 =「每 key 首次必打，之后每 50 次打一条」）⇒ 低频事件（5.5 s 一次）**17 次最多只留 1 行**。1:17 完全是量具造成的。

**纪律**：
1. **任何「计数一致」型判据，两侧必须走同一个不降频口** —— 落盘前先查调用点用的是降频版还是不降频版。
2. **计数不是表现类条目的证据**。"动画到底播没播"要读运行期真值（`Animator.GetCurrentAnimatorStateInfo(0)`：状态是不是目标剪辑 + 归一化时间有没有在走），光有 `_anim.Play(...)` 那句调用**不算**。
3. 改口径时，**同一次改码必须把旧注释一起改掉** —— **自带错误因果的注释比没有注释更糟**。
4. 判据溯源要问到底：一条"差 16"的数字，先问**它是在什么频率下被测出来的**，再问它意味着什么。

### 九.6 量具缺陷之二：解析器的**换行口径** ≠ 生产者的换行口径（行内裸 CR）

**现象**：一份 tsv 的某些数据行**行内**带一个裸 `\r`。`awk` 按 `\n` 切 ⇒ 认它是 1 行；Python 的**通用换行**把 `\r` 也当行结束 ⇒ 同一个文件在两侧得到**不同的行集合**，"对不上"于是被解释成"有独立成行的孤儿行"。

**判据**：**两边的行 / 记录数对不上时，先怀疑解析器的换行口径，不要先怀疑数据。**
自检一行：`b = open(p,'rb').read()` 后比 `b.count(b'\r')` 与 `b.count(b'\r\n')` —— 不等即有裸 CR；此时**读表格一律二进制 + 只按 `\n` 切**（或 `open(..., newline='')`），⛔ 不要用默认文本模式。
**与九.5 的关系**：九.5 = 生产侧降频改变了**计数**；九.6 = 读取侧换行口径改变了**行数**。同族（**量具不是产品**），触发点不同、排查入口不同。
⚠️ **警告的实质对了，不等于它的证据对了**：证据一旦被推翻，警告必须**重述**（改说"盘上独有段落，注入会抹掉"），⛔ 不许挂在已推翻的证据上继续用。

### 九.7 报数必须带**口径**（整行 / 第几列 / 字符 / 字节 / 含不含 `\r`）

**现象**：一方报"10418 → 12892"，另一方独立量得 `col5 = 8173` —— 差 2000+ 但**两者都对**（一个量整行、一个量第 5 列）。另一处报"后缀 3063 字"，与该行 col5 总长仅 2216 直接矛盾 ⇒ 那个口径**无法复现，只能作废**。

**规则**：报 `(id → 数字)` 时必须写清**口径**，否则接收方核不上；而**核不上会被当成造假**。宁可多写两个字，也不要让对方去猜。
**甲方（主 agent）同理**：**复算时先用对方的口径**，确认对齐后再换自己的口径 —— 否则会把"口径差"误判成"造假"。

**推论 A：计数必须区分「注释」与「可执行」。** 注释里**故意**会写出被禁的写法来解释"为什么禁" ⇒ 实测 `grep -c` 数到 4，而**可执行**为 0（4 处全在 `#` 之后）。⇒ 计数命令用去注释后的形态，并**把两种数一起报**（"字面 4 / 可执行 0"）。⛔ 只报字面数会把守规矩的代码判成违规。

**推论 B：判"进程 / 会话死了还是重启了"⛔ 不能靠日志里的"横幅"，要靠文件与进程的生命周期。** 实测：日志尾部出现 licence 复检类行，被据此宣布"编辑器重启过"—— **错**，那只是运行中的**例行复检**。正确判据 = 轮转日志的 **mtime**（只在启动时轮转）、进程创建时间、**被销毁侧的痕迹**（`OnDestroy` / `Unload` 调用栈、退出 Play 后恢复场景的行），⛔ 而不是"日志有没有新行"（空闲在菜单上本来就不打日志）。
⛔ **教训**：**"日志尾部像什么"不是判据，"文件 / 进程的生命周期"才是。** 而且这个错会**直接变成错误指令**（据它让一条还在正常跑的链"立刻中断"）⇒ 发出去的结论要**先自查判据属于哪一类**，错了就**当场撤回**。

**推论 C："扫法本身会漏"** —— 枚举某机制支持哪些键 / 选项时，**你用的那把尺子可能对某些访问方式盲**。实测：用 `TryGetValue` 扫一遍就断言"只支持这几个键"，而该探针还有一个键走的是 `ContainsKey` + 索引器 ⇒ 扫法对它完全不可见 ⇒ 漏报了一个"不给就会采到**纯黑帧**"的必需键。
⇒ 规则：**枚举"支持哪些 X"时，先 `grep -n` 把所有读取 / 赋值点全读出来，再按读法分类**（`TryGetValue` / `ContainsKey` + 索引器 / 直接索引 / 反射 / 字典遍历…），⛔ 不要只扫一种读法就断言"只有这几个"。
同形状的坑：用 `wc -l` 数行漏掉无尾换行的末行、用 `ls` 数目录项漏掉点文件、用 `grep -c` 把注释一起数进去。**尺子的盲区就是结论的盲区。**

### 九.8 半截产物冒充完整结果：**后台**跑的自检会随本轮结束被杀

**现象**：把闸门脚本放**后台**跑，本轮一结束宿主就把子进程杀掉 ⇒ 日志**停在中间某一项、连 SUMMARY 都没有**。它把这份半截文件当成完整基线引用出去。
**根因**：非交互式运行在"主 agent 结束本轮"时就退出，**即使还有后台 / 长时子进程在跑**。⇒ **"后台跑"不等于"它会跑完"。**

**判据（两条都做）**：
1. 长自检**一律前台等它结束**（后台只用于"结束前一定会被收集"的场景）；
2. 每个长任务产物的**最后一行必须是哨兵**（`===== SUMMARY =====` / `RESULT-*` / `DONE`），**消费前先断言哨兵在**：没有哨兵 ⇒ 这是**半截产物，不是结果**，⛔ 不许引用。
   —— 与九.1 同族：**产物存在 ≠ 产物完整**。

### 九.9 闸门的**输入**也是产物：新增一个 manifest 会搬动全局批次钉

**现象（差一点）**：某成员为本次"同名重采"新增了一份 manifest，按惯例想放进 `tools/probes/`。但 `freeze-before-capture` 闸门的判据是"**最新**那份 `tools/probes/*.manifest.tsv`" ⇒ 放进新的一份 = **把全局批次钉从旧的图上挪走** ⇒ **别的切片**的判定会**静默改变**：原本落在批次里被判的行，会因为"不在最新批次里"被 `continue` 跳过（**从"被检查"变成"不被检查"**）。

**判据**：一个文件的**位置**可以是闸门的输入。改动它 = 改闸门可见性，**即使你一个字都没改那个文件的内容**。⇒ 规则：
1. 只为自己的取证新增清单 / 夹具时，**放自己的临时区**（`.ai-tmp/`），⛔ 不要放进任何"闸门按时间戳 / 名字取最新"的目录；
2. 确实需要动全局钉 ⇒ 那是**项目级变更**，必须**单独一步、带前后对照**（列出"哪些行的判定会变"），与功能改动分开评审，⛔ 不许当本片副产品顺手做；
3. 发现"某个闸门按『最新文件』取输入" ⇒ 在片报里写明**那个目录的当前最新项是谁**（否则别人新增就会被无声问责）。

### 九.10 声称的产物路径必须**对得上盘**：`mv … trash/…` 的凭证要先 `ls` 一遍

**现象**：成员报告"锁已释放：`mv … trash-<ts>`，耗时 `real 0m1.439s`，无 `rm`"。主 agent 复核盘面：锁确实不在了，但那个目标名 `find` = **0 命中**，canonical `trash/` 里也没有对应条目（其 mtime **早于**释放时刻）⇒ **那条 `mv` 没有在它说的位置留下任何东西**。"no rm" 与 "moved to trash" 只能有一个是真的。
**根因**：报告里的"目标路径 + 耗时"是**它以为跑过的命令**，不是**盘上发生过的事**。耗时数据尤其危险 —— 它**看起来像实测**。

**判据**：
1. 任何"我把 X 移到 / 放进 Y"的声明，**必须附 `ls -la Y` 的原文**（或等价 `find`）；⛔ 不接受只报命令原文 + 耗时。
2. **canonical 位置才有审计价值**：设计上要落进 `trash/` 的释放，落到别处**等于没有审计凭证**。
3. 判"释放是否合规"**别看锁在不在**（锁不在也可能因为别的原因），要看**释放记录在不在**。
4. 复核手段：**用目录 mtime 卡时间窗** —— 目标目录 mtime 晚于释放时刻，才说明"这次释放往里加过东西"。

**推论一（反向也成立，且更危险）：裁决者不许把"自己记得的数字"当成成员的声明去算账。**
实测：主 agent 准备发一条"你报的哈希与盘上不符"的裁决，依据是**自己跨轮次的记忆**；落盘核对后**逐位相同**，**记错的是裁决者自己**。
- **规则**：任何跨轮次引用的 sha / 字节数 / 行号，**必须从产物文件里重读**，并在回报里带上**出处（文件名 + 行号）**。
- **为什么更危险**：上一条是"执行者把意图当实测"（会被盘面驳回），这条是"**裁决者把记忆当证据**" —— 它会**直接污染裁决**，且带着权威语气，成员很可能"认下"一个不存在的错（= 逼出假供词）。
- **写裁决前的自检**：这条指控我**从哪份产物的哪一行**读到的？读不出来 ⇒ **不许写**。

**推论二：裁决者不许把"自己编出来的"数字当成成员的声明去算账。**
实测：裁决里写「你报的是 X，盘上是 Y ⇒ 对不上」，并据此推断"你把负控覆盖了"；核对原始回报 ⇒ **成员从未报过那个 sha，那是裁决者自己写出来的**。
- **规则一（引述必须有出处）**：凡在裁决里复述"你报的 / 你说的"数字，**必须能指到那句话的出处**（它的消息段落或它落盘的产物）。指不到 ⇒ 改写成"**盘上是 Y；你报的是哪个？**"—— 把自证的责任交回成员。
- **规则二（指控的举证方向）**：裁决里的"不符"必须**只用盘面**成立，⛔ **不许**用它来复述对方说过什么。**对方的声明只能由对方自己提供。**
- 合起来 = 一个不变式：**裁决者对任何数字的唯一合法来源是"我刚从盘上 / 产物里读到的"** —— 记忆不算、推断不算、"我大概记得它报过"更不算。

**推论三：回执 / 心跳行也是账 —— 里面的结论必须能指到盘上产物。**
实测：心跳落了一行 `… FAIL=0`，但盘上那一轮的日志**没落到任何能查到的路径**（更旧的日志反而有 `FAIL=1`）。
- ⇒ **心跳不是日记，是台账**：`FAIL=0` 等价于一条"我有个产物"的声明 ⇒ 必须能指到文件名 + 时间戳；指不到 ⇒ 写 `未落盘`，⛔ **不许写数字**。
- ⚠️ **反向风险更毒**：一个**更新**的 `FAIL=1` 躺在盘上、而台账说 `FAIL=0` ⇒ 后来读盘的人会把这个 `FAIL=1` 当成**最新结论**。文件名里的 `corrupt` / `negctl` **不构成**"我知道它是负控"的证明 —— **期望红与意外红必须在文件里写死标注**。
- **引述自己的产物时，直接复制产物那一行**；手打 = 下一代事故的种子。

**推论四：裁决者不许把 A 成员的动作记成 B 成员的。**
实测：给某条线发裁决时写「顶层那几个你已清」，盘上核实那 3 个**还在**，而"清了 3 个"出自**另一条线**的报账 ⇒ **是别人的动作，被记到了它头上**，并当成"既定事实"派了活。
- ⇒ **"谁做的"也是一个引用**，同样必须能指到出处：**要么是它自己那条消息，要么是盘上的产物**。⛔ 多个成员同时在同一片区域干活时（都在动 `trash/`），**跨成员串账的风险最高**。
- **写裁决前的自检（增补）**：这句话里的**动作**，我能指到**做这件事的那个人的**原话或产物吗？指不到 ⇒ 写成"**盘上是 X；这是谁做的？**"，⛔ 不许替它指派 owner。
- **附带形态**：裁决里引用的**产物文件名**也会凭空生成 ⇒ **规则：裁决里出现的任何路径 / 文件名，写之前必须 `ls` / `find` 过一次**（哪怕"我记得它报了"）。

**推论五（正面样板）：成员反查裁决者、并把它查对。**
- 成员 `find` 了一遍，确认裁决里的两个名字全仓不存在，并**给出归因**（把 A 线的产物按 B 线的命名习惯"补"出了一个名字 —— 与"跨成员错记"同源）。
- ⇒ **规矩**：裁决者的引述**必须允许被反查**；成员查对之后，裁决者要**认归因**（不只是认"我写错了"），并把归因写进 skill / 日志 —— **只认错不认因，同一个错会在别处再犯一次**。
- 另一例（查的是**判据本身**）：裁决者下令"把 `P` 自检回填进驱动"，给的判据默认 `P` **由脚本自算**；成员读盘后发现该脚本逐字是 `P="${MV_P:-<写死的绝对路径>}"` ⇒ **裁决者给的判据恒真、零拦截力**，遂改用 `[ "$(pwd -P)" = "$P" ]`。
  ⇒ **规矩（强化）**：成员对"裁决者给的判据"负有**同等的反查义务** —— ⛔ 不许因为"这是 lead 说的"就照抄。反查要点 = **先读一眼被断言的那个东西在盘上到底怎么写**，再问"这条判据在**失败情形**下会不会真的变成假"。

### 九.11 判"会话 / 进程还活着吗"只能靠**两条互不依赖**的信号（单一量具会假阴）

**现象（差一点）**：锁回收分支只靠**一个**量具（某状态命令解析出的 `"playMode":"playing"`），而**同一天已实测该命令会假阴**（报不在 Play、其实在 Play）。若假阴恰好发生在回收判定的那一瞬 ⇒ 它会**回收掉一个正在跑的 Play 的锁** ⇒ **两条线同时进 Play**。

**第二条信号怎么取**（任选其一，关键是与第一条**不共因**）：该线**自己的 heartbeat 文件** mtime（>300 s 未更新才算"死"）；或运行日志 mtime（活的 Play 会持续写）。

**判据**：`回收 = ① 够旧 AND ② 信号A说死 AND ③ 信号B说死`；**任一信号说"活" ⇒ abort**（宁可等，不并行）。同理：**别人的残锁不许回收**（只有它的 owner 或主 agent 能放），否则会互相堵死。

### 九.12 证据帧搬迁的两条铁律：**留日志** + **不拆 before/after 配对**

**现象**：某隔离目录里发现若干从截图目录搬出来的采集帧；其中 `*_before.png` 与它的对照帧**永久缺失** ⇒ 那一轮的 before/after 判据**再也无法重算**。而 `grep` 全仓 **0 命中**、**没有任何心跳记过这次搬迁** ⇒ 来源不可考。

**两条铁律**：
1. 证据帧搬迁**必须在 heartbeat 留一行 `mv <before> -> <after>`**；没留 = **来源不明**，等于该帧不存在。
2. **`*_before*` 基帧不得与它的 after 分离移动。** 没有 after 的 before **不可重算** ⇒ 要隔离就**整对**搬进带日期的隔离目录、**保留原文件名**；⛔ 不许删（不可逆）。

**推论**：报"某批证据已不可重算"之前，**先把搜索口径铺满**（实测：漏搜一个目录会把"5 个帧还在、只丢 2 个"误报成"6 个全丢"）。**"找不到"必须附"我搜过哪些目录"** —— 这句能立刻暴露盲区。

### 九.13 长任务每一步都必须**可超时**：`run_script` 会间歇挂起，而裸 `timeout` 可能根本不是 coreutils

**现象**：驱动里一个 `run_script` 调用**整条不返回**，卡 2 分 42 秒，把整个 driver 拖成"永远跑不完"；而历史同类运行（5~7 分钟）都正常 ⇒ **同一个调用会间歇性挂起**（不是机制坏了）。

**根因定位（可复用的判据）**：**不是被调侧死锁** —— 判据是**主线程的旁证日志**：若被卡方法在主线程上阻塞，同类 `Update` 日志会一起停；实测整段僵死窗口内那些行**连续** ⇒ 主线程在跑 ⇒ 挂起在 **CLI / transport 侧**。
（残留不确定如实标注：文件证据**区分不了**"请求没送到"与"送到了、回包丢了"。）

**三个非显然的环境陷阱**：
1. **裸 `timeout` 在 PowerShell 里解析到 `C:\WINDOWS\system32\timeout.exe`** —— 那是**"暂停 / 等待"工具，不是 coreutils** ⇒ **必须写显式路径**（Git 自带的 `usr\bin\timeout.exe`）；实测该路径超时杀 → **rc=124**、正常命令 rc=0。
2. **`Start-Job` 会被宿主安全策略拦**（"runs code in a background job"）⇒ 用外部 `timeout.exe` 包裹，⛔ 别走 PowerShell job。
3. **Git Bash 里 `command -v timeout` = coreutils**，bash 系可用；但**每种壳都先断言一次解析结果**：
   ```sh
   case "$(command -v timeout)" in /usr/bin/*) ;; *) echo "FATAL: timeout 不是 coreutils"; exit 1;; esac
   ```

**判据**：
1. 长任务里**每一个外部调用**都包一层超时；**`rc=124` 必须打印出来**（如 `RUNSCRIPT-TIMEOUT: <entry> … chain continues`），⛔ **不许吞** —— 吞掉就退化成"半截产物冒充完整结果"（九.8）。
2. 超时**不是**"把失败藏起来"：它把"永远挂着"变成"**可观测的失败**"。
3. 判"卡在哪一层"用**旁证日志**：主线程旁证连续 ⇒ 挂在高层 transport；主线程旁证也停 ⇒ 才是被调方死锁。

### 九.14 判据里的"每帧"就是变相的分母：同一物理状态、两种帧率、两种结论

**现象**：卡死判据写成"**每帧**位移 < 1 mm 即视为停滞"。换帧率复验时把 `dt` 从 `0.05` 改到 `0.0074`，**却把 `frames` 固定成 400** ⇒ 模拟时长从 20.00 s 变成 2.96 s（差 6.76 倍）⇒ 两条"没卡"的结论其实是**帧预算截断**；更深一层：**判据本身随 `dt` 变含义** —— `1 mm/帧` 在 20 Hz 下 = 0.02 m/s，在 135 Hz 下 = 0.135 m/s ⇒ **同一物理状态在两种帧率下被裁成不同结论**。

**判据（三条）**：
1. **凡是"每帧"的阈值，先化成"每秒"**（`dxz/dt`）再进判据 —— 否则你量的是**采样率**，不是物理。
2. **跨帧率比较先对齐"分母"**：固定 `frames` 是错的，要固定**模拟时长** `T_total` ⇒ `frames = ceil(T_total / dt)`。
3. 任何"高帧率下没复现"的结论，**必须先排除"帧预算不够"**再下 —— **"跑的帧数一样"不等于"跑的时间一样"**。

**兼容性怎么保**：换判据前先证明**旧失败在新判据下仍然失败**（旧基线停滞行的位移精确为 0 ⇒ 速度 0 ⇒ 新判据照样红 ⇒ 修前 / 修后差分不失效）。另注：`0.001/0.05 = 0.02` ⇒ **新旧判据在低帧率侧数值完全等价**（"低帧率侧基线不变"是**可证**的）；高帧率侧**不等价**（新判据更严），那一侧必须**从记录的原始行离线重算**，不能沿用旧结论。

**推论 A：`连续 ≥N 帧` 里的 `N` 也是变相分母。** 把位移化成速度（对了），但"连续 60 帧才算卡死"仍是**帧计数冒充时间阈值**：60 帧 @`dt=0.05` = 3.0 s，@`dt=0.0074` = 0.444 s ⇒ 高帧率侧灵敏度高 6.76×。
- 归一化 = `frames = ceil(T_stall / dt)`，`T_stall` 取**基线帧率下的等价值** ⇒ 低帧率口径**逐字不变**；高帧率侧变**松** ⇒ 改完必须**从 raw 行离线复算两侧**。
- **判断"能不能先不改"要看误差方向**：高帧率侧更严 ⇒ **只会假红、不会假绿**，且实测阈值被碾压 ⇒ 本轮判决不受影响，**可延后到下一个改动窗口**。⚠️ **误差方向若是"更松"，就必须当场改** —— "保守偏差"是唯一可以延后的理由。

**推论 B：字段名叫 `frames` 时，必须说清它是「预算」还是「实际」。** 实测：小结里印的是**预算**，而实际只跑了 455 帧 / 3.36 s；于是"跑满 20 s"与"提前收工"**在结算行上一模一样**。
- **规则**：**"预算"与"实际"绝不共享一个字段名** —— 印成 `used/budget` 或另开一列。⛔ 不要为了让它"看起来跑满"而取消提前退出：**到终点即止是对的，错的是字段名**。
- **能验伪的复核手法**：把产物的**行数与字节数**跟声明帧数按比例对一下，再加"最后一行序号 + 到达终点标记"两处，就能判出是**提前成功退出**还是**真跑满**。

**推论 C：接受一次"放松"时，必须让这次放松可见、可数。** 把两个**已知红**用例（属**另一个 issue**、已登记、有**独立闸门**）移出回归"严格集" —— 效果上**这就是放松**，不要粉饰。它合法的唯一依据有两条且必须同时成立：① 该用例属另一个 issue 且有独立闸门；② 留在严格集里 ⇒ 守当前 issue 的闸**永远红** ⇒ **闸失去信号**（永远红的闸等于没有闸）。
裁决方式（三条）：① 要求产物里那行结论**自带两个集合的字面成员**（`GREEN strict={…} residual={…}(理由)`），否则"排除"是**隐形的**；② 要求被排除者**仍带实测数字出现在同一份产物里**（**"残余" ≠ "没测"**）；③ 记录"严格集成员表"的**变更**本身（**闸门的输入也是一份产物**）。

### 九.15 要求一个校验之前，先检查它在这批目标上**可不可执行**

**现象（差一点变成"零校验"）**：硬约束是"取回的外部件**逐件 sha256 必须与清单记录对上**"；而**这批件在清单里根本没有记录**（它们正是"从未取回"的那批）⇒ **没有可比对的值** ⇒ 该约束在这批目标上**退化成"零校验"**。
成员**没有悄悄放宽**，而是**先报"约束不可执行"，再给一个能执行、且强度被标定过的替代核验**，并明写"**比看起来像强、比逐字节同版弱**"。

**判据**：
1. 下任何"必须与 X 对上"的校验前，**先确认 X 在这批目标上存在且可执行**；不存在 ⇒ 该约束是**纸的**。
2. 遇到不可执行，**只有两条正路**：**报"不可执行"**，或**换一个能执行且强度可标定的替代**。⛔ 不许悄悄放宽。
3. **核验强度必须标定**：分得清"逐字节同版" / "结构身份吻合权威记录" / "看起来像" —— 三项不是一回事，报的时候要写清落在哪一档。

**附一：判"取到了没"的判据是字节 + 哈希，不是 HTTP 状态码。** 实测：某渠道报 `server closed abruptly`（`http_code=000`），**但 body 已完整到达**（sha256 照样对上）⇒ 拿状态码当判据会**假停**。**代理指标（状态码、横幅、计数）永远不能替代产物本身（字节、哈希）。**

**附二：传输变体（`Range:` 分块）算不算"换渠道"？—— 不算，但要另外证"重组忠实"。**
- **判据**：**渠道 = host + path**。同一 URL 上的传输变体（`Range:`、`--http1.1`、重试）**不是换渠道**；换镜像 / 换仓库 / 换本地副本**才是**。
- ⚠️ **"重组可重复" ≠ "重组忠实于整体 GET"**（同一套错误的重组跑两遍也会得到同一个错值）。**必须加一步对照**：拿一件**已用整体 GET 取到、sha 已知**的件，走**同一套 Range 流程**，看能否**复现原 sha**。复现 ⇒ 重组件可信；不复现 ⇒ 丢弃（⛔ 不许"结构签名看着像"就收）。
- **来源记录里必须写明取法**（"同 URL 顺序 Range 分块"），否则将来有人拿单次 GET 的 sha 来对，会对不上，从而**误判成取错件**。

### 九.16 判"两张图是不是同一张"：先挑对**量纲**，再谈阈值

**现象**：要判两个取回的图像文件是不是同一张，三个"看起来很有力"的数字里**两个是错的**：

| 量具 | 读数 | 判决 |
|---|---|---|
| 原始像素差 | 2.278% | ⛔ **骗人的小数字** —— 每帧约 98% 是透明底且两边相同，把**分母灌大**了 |
| RGBA 差异 | 100% | ⛔ **不是独立证据** —— 调色板差 95/768 字节 ⇒ 每个像素的 RGBA 都变；它与"像素差"是**同一个因**的两个果 |
| **画出来的掩码**的 **Jaccard** | **0.1447** | ✅ **决定性的那个** |

⇒ 结论只由第三行推出；前两行若单独用会得出"高度相似"或"完全不同"的错误印象。

**判据（三条）**：
1. **带大面积"公共底"的对照，分母必须取"并集 / 掩码内"，不能取整幅。** 换任何比较前先问：**这个分母里有多少是两边必然相同的部分？**（九.14 的"每帧 / 每 N 帧 / 预算帧"是**时间维**的那一支，本条是**空间维**的那一支。）
2. **两个数字看着独立，可能同源。** 改调色板会同时改变"逐像素差"和"直方图差"——它们**互为派生**。判"独立"的办法：问**能不能在不改变 X 的前提下改变 Y**。不能 ⇒ 不是独立证据。
3. **阈值要给"分离度"，不只给"通过与否"**：正控（真不同的图）与负控（同图换色）把区间撑开了，阈值才有意义 —— **只报"0.1447 < 0.5 所以不同"是脆的**。顺带：同图换色的两条 Jaccard = 1.0000 ⇒ **顺便证明了这套量具能识别"同一张图"**。

### 九.17 判据自身的盲区（六则）

**盲区一：判据对所要证的对象结构性盲。** 要证"某条支路**零覆盖**"，识别规则是「上一步来源 = 0 ∧ 水平位移 = 0 的行才可能进那个分支」；**但那条支路一旦真被走，返回的就是终点 ⇒ 位移 ≠ 0** ⇒ **它压根不在"可达行"集合里**。「可证走过 = 0 行」**不是结论，是识别规则的产物**（用原始列反证：同一条判定下有若干行是 `来源=0 ∧ 位移≠0`，正是该分支的候选，被规则排除在外）。
- **判据**：动手算"0"之前先问 —— **"如果我要证的那个情形真发生了，它会以什么形式出现在我读的字段里？那个形式落在我的筛选条件之内吗？"** 不在 ⇒ 你的"0"是**筛出来的**，不是**数出来的**。
- **拿不出交叉字段时，结论只能写「未判定」**，⛔ 不能写"零覆盖（可证）"。
- **便宜的补法**：看那条代码路径**有没有现成的钩子** ⇒ 加一列就能把两个出口分开，**不必另开一轮实验**。
- 同族：九.7 推论 C（扫法本身会漏）。**本条是它的反向**：不是漏了某类访问方式，而是**把要证的那一类筛掉了**。

**盲区一的推论：判据的「出处 / 来源」列同样会被模糊匹配毁掉，而 rc 照样是绿的。** 检查器用 `label.startswith(name)` 挑"这条用例该拿哪个文件当来源" ⇒ 前缀更长的用例被记成短名的来源；而两条来源的关键数值**恰好相同** ⇒ **rc 照样 PASS**。它错的是**承重的那一栏**（这条判据的价值就在于"下界是从哪条链量出来的"）。
- **判据**：判据自己打印的"出处 / 来源 / 样本数"列，**必须逐行读一遍**（不是只看 RESULT 行）。⛔ 用**前缀 / 包含匹配**挑"来源"是这类事故的固定入口 ⇒ 改成**按结构化的 key 精确匹配**。
- **加固写法**：让判据**把出处和样本数一起打出来**（如 `from <file>, 400 rows`），这样"来源错了"会**显式地**出现在证据行里。

**盲区二：零产物 / 零行通过"两遍一致"这类判据。** 两次独立命中：① 某次产物因语法错被**截成 0 字节**，而 `cmp -s a b` 把"**两个空文件**"判成 OK；② 比对用的正则不匹配右对齐的行号 ⇒ 解析出 **0 行 / 0 行**，却报 PASS（它自己是靠"**正控必须 `rows > 0`**"抓到的）。
- **判据**：一切"两遍一致 / 与基线一致 / 增量为 0 / 逐位不变"类判据，**必须同时断言"输入非空，且行数 / 字节数 > 0"**。⛔ **"两个空集合相等"永远为真**，而它看起来就像一次通过。
- **推广**：**"差异为 0"这个读数，在"两边都是空"时是无意义的** —— 判据里要把「为空」和「相等」**分开报**。

**盲区二的推论一：「空」有三态，只有第一态是真的空。** 噪声闸门「白名单外 stderr 行数 = 0 ⇒ PASS」在**屏幕上明明有噪音**时判了 PASS：根因是它写的是 `… 2>"$f"` 而**不是** `exec 2>"$f"` ⇒ 重定向只对那一条命令生效 ⇒ 文件**根本没被写** ⇒ 空 ⇒ "0 行" ⇒ 绿。

| 态 | 含义 | 对症的断言 |
|---|---|---|
| ① **真为空** | 输入确实是空集 | 断言"输入非空 **且** 相等" |
| ② **没抓到** | **采集 / 捕获管道没生效** ⇒ 空是假的 | **捕获自检**：产物文件必须 **> 0 行 / 字节** |
| ③ **没绑上** | 变量未定义 ⇒ `$( )` 展开成空串 | 断言"有值 / 存在"；全程挂 `unbound variable` 计数 = 0 |

- ⇒ **凡"读了某个文件 / 流然后数它有几行"的判据，都必须先断言"这个文件真的被写过"**（`-s "$f"`）。⛔ 否则它不是判据，只是"我们以为在判"。
- ⭐ 正确形态 = **双向自检**：脏样本**必须**判 1、同一脏样本**必须**让另一条闸门也判 1 —— **产物是判词行，不是 shell 报错原文**。

**盲区二的推论二：量具把自己的输出截断了，下游把截断当全集。** 分析脚本第一步打印时用了 `[:5]` / `[:40]` 截断；第二步脚本**去解析那份打印文本** ⇒ 拿 40 行当"全集" ⇒ 得出假结论（与第一步自己算出的差异数**对不上**，才被抓出来）。
- **判据**：**分析脚本之间不许用"打印文本"当接口** —— 要传就传**产物文件**。打印是给人看的，**可以有省略号**；文件是给机器看的，省略号就是**静默的错误**。看到 `[:N]` / `head -N` / `…（截断）` 就要当成"这份数据不完整"。

**盲区三：兜底 / 重试机制在本机真实发生的失败类上零覆盖，而"结果成功"替它背了书。** 取件链路两次失败，脚本里写着的 `--retry 6` **一次都没触发**（产物里没有任何一行重试日志）；改成**逐块自愈循环**后，同一失败类才真的进入重试。
- ⇒ **`--retry` 的覆盖是一个「失败类集合」，不是一个布尔值**：它盖连接级错误，**不盖**中途 TLS 断流与**部分体超时**。
- ⛔ **最危险的一层**：那条用**坏兜底**跑通的链路**报的是成功**（因为那一次 host 恰好没切块）⇒ **"它跑过去了"不构成"兜底是对的"的证据**；**不许拿结果成功给机制正确背书**。
- **判据**：兜底 / 重试 / 回退 / 降级**本身是一条判据** —— 它必须在**本机会真实发生的那一类失败**上**被触发过一次**（留一行"第几次、什么 rc、重试了"的日志），⛔ 只做"配置项存在 / 参数写对了"的**形状检查**不算。

**盲区四：正控的效力只覆盖"跑它的那个程序"；转移到别的被控对象之前，先比字节路径。** 正控 PASS，但正控脚本与被控流程真正用的脚本**是两个不同的程序**（相差约 1000 B）⇒ **正控只证明了前者忠实，不自动证明后者忠实**。
主 agent 补做的转移判据 —— **逐行比字节装配路径**：同 chunk、同 URL / host、同拼接命令、同「rc==0 且字节数达标才 append」的门、同哈希算法；唯一功能差异 = **重试策略**（只影响"跑不跑得完"，**不影响进入成品的字节**）⇒ **可转移**。
- **判据**：说"它也是同一套流程"**必须有可核对的字节路径对照** —— 列出**哪几行相同**、**唯一差异是什么**、并回答**这个差异有没有可能改变被测的那个量**。⛔ 不许凭"思路一样 / 都是同一套 Range / 同一个 host"就转移。
- **顺带的正面样板**：那条控制件是**量具正控**的写法 —— **正控证"量具会读数"，对照证"读数意味着结论"**，两者都要，且**各自只对跑过它的那一支有效**。

**盲区四的推论：正控只覆盖了"在控制的搭建条件下恰好跑得到的那条分支"。** 给驱动加"算完根目录后自检 cwd"（纯新增 20 行），正控写法 = 改前件 vs 改后件跑同一条命令、输出逐字比。听起来标准，但**读数只有一行**，两件都是同一条拒绝信息 ⇒ 真相：正控是在 **"手里没锁"** 的条件下跑的 ⇒ **只走到了拒绝分支**；而被改的那块代码在**成功路径**上同样每帧都在执行 —— **成功路径一个字都没比过**。于是"行为逐字不变"这句**字面为真、覆盖面为零**。
- **判据**：说"改前改后行为不变"**必须写出这次控制实际走到了哪条分支**，并回答**被改的那段代码在那条分支上会不会执行**。只覆盖到拒绝 / 空输入 / 错误分支的控制，**只能叫"该分支未回退"**，⛔ 不许写成"行为不变"。
- **两种合格做法（二选一，不许含糊）**：(a) **补真控** —— 把控制搭到**成功路径**上，改前 / 改后**整份输出**落两个文件比；(b) **写明口径** —— 逐字写「正控只覆盖该分支；成功路径的不变由『纯新增 diff + 守卫条件在真跑下整块跳过』这一**静态论证**保证，**不是控制**」。⛔ 最坏的写法是把 (b) 的内容**说成** (a) 的结果。
- **同族**：盲区四问的是"**谁**被控"，这条问的是"**哪条分支**被控"；再加九.3 推论（正控 / 负控的原始产物**必须分文件**）。

**盲区五：判据引用的变量根本没被绑定 ⇒ 断言退化成空操作，而外层 rc 仍是 0。** 自检脚本把被测驱动的一段摘出来单独跑，于是那段引用的宿主变量**在沙箱里未定义** ⇒ 展开成空串 ⇒ 下游命令静默失败 ⇒ 计数为 0 ⇒ 而且在 `set -u` + `set +e` 下**最外层 rc 仍 = 0**。
- ⇒ 那条断言在沙箱里**结构性地永远等于 0、永远不可能失败** —— 它看起来**通过了**，其实**没在判**。正确处置是把它从证据降级成「**不可判**」（这里连"输入"都没有）。
- **判据**：凡判据引用的变量 / 字段 / 文件，**必须同时断言它"有值 / 存在"**；并且**在整个输出上挂一条"工具静默退化"闸门** —— `unbound variable` / `command not found` 之类计数**必须 = 0**，否则整轮红。
- ⚠️ **自查的成本极低、收益极高**：逐条问"我这条判据**要是想失败，靠什么红**？"，答不上来的就是空的。
- ⚠️ **闸门自身也要被闸**：新加的那条"计数 = 0"闸门，必须**两向自检** —— 在**未修**的输出上必须**红**、在**修好**的输出上必须**绿**；⛔ 「修完就绿了」不算证明。

**盲区五的推论：把"没绑上"修成"绑上了、但恒为同一个值" ⇒ 闸门从"静默退化"变成"恒绿"，依然没有失败的可能。** 绑定变量后日志确实打出真数字、新闸门也绿了；**但**沙箱里那个目录**永远是空的** ⇒ 这个数**恒为 0、不可能非 0** ⇒ 断言仍然**红不起来**，只是**不再静默**。
- **判据**：整改一条"空断言"，验收标准**不是"变量有值了"，而是"它能被喂出非平凡值、并在该值上给出正确判定"**。做法：**给这条断言补一个正控样本**（跑前往该目录 plant 2 个文件 ⇒ 日志**必须**打 `2`；打 `0` = 盲区探测命中）。

**盲区六：「已知坏样本」的隔离能力也要跟主体一起升级 —— 旧版副本会把副作用漏到真面上。** 为给测试补一条**能红的**负控，取了一份**改坏过的旧驱动副本**跑一遍：它确实红了（双向闸门成立）；**但**那份副本是**加沙箱缝之前**的版本 ⇒ 它的释放逻辑**不认沙箱变量** ⇒ **两条假释放落进了 `trash/`（canonical 审计面）**，而真锁自始至终没被碰过。
- **为什么危险**：审计面的语义是"**真实的放锁记录**"。混进两条来自坏副本的假记录后，后来的人（包括几天后的你自己）读 `ls -lat trash/` 会得出"某线在某些时刻放锁了"——**这是假的**。
- **判据**：给闸门做负控时，**负控样本的"修订版本"也是判据的一部分** —— 它必须与被测主体**同一修订**，或至少**具备主体已加的每一种隔离**（根 / 锁路径 / 状态文件 / 垃圾目录四个缝）。⛔ 从旧副本随手取一个"坏版本"**不算**，"越坏越好"在**副作用**上是反的。
- ⭐ **可执行形态**：**隔离是同"钥匙"的集合，不是同"版本"的比较。** 做法 = **把主体的每一把"隔离钥匙"在负控样本上逐把试一遍**，**缺哪把就补哪把**，⛔ 不许"我看是同一份代码思路"。本例根因更狠：旧副本里**状态锁路径是写死的**（没有对应缝）⇒ 它**连"锁待在沙箱里"都做不到** ⇒ 不是"少一个变量"，是**整条隔离链全断**。
- **披露 ≠ 处置，标注必须落盘**：成员在消息里把副作用说清了（对），但**消息不在盘上** ⇒ 正确做法 = **在那些假产物身上写死标记**（目录内放 `NOT-A-REAL-RELEASE.__corrupt-negctl__`，或整体 `mv` 进带 `__corrupt-negctl__` 的父目录），让**审计面自己**说得出"我不是真释放"。

> **贯穿本节的三个总问句**：① 我这条判据**要是想失败，靠什么红**？② 这个"0 / 相等 / 一致"是**数出来的还是筛出来的**？③ 我引用的每个数字 / 路径 / 主语，**都能指到盘上或产物里的哪一行**？
> 只在"没绑上"这一种故障下红、在"绑上了但值退化"下不红的闸门，**只修了一半**。

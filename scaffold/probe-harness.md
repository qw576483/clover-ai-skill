# 探针外壳骨架（`tools/probes/probe.cs`）

> **本文件只写"外壳"**：位置 / 输入桩 / 日志标记协议 / 退化帧判据 / 出图闸门 / 落盘路径。
> ⛔ **不写任何游戏内容** —— 每个入口里"走到哪、按哪个键、看哪块"是**项目自己的事**，
> 换项目时**外壳照抄、场景体整段重写**。
> 位置口径见 `reference/workflow-and-standards.md`「临时文件」：**探针外壳与驱动必须提交**（⛔ 不许留在 `.ai-tmp/`）；⛔ 但**一次性切片脚本**（带片名的）用完即删，别往这里堆。

## 0. 位置与用法

| 项 | 值 |
|---|---|
| 探针本体 | `<项目根>/tools/probes/probe.cs`（**判据资产，进仓库**） |
| 冒烟脚本 | `<项目根>/tools/probes/probe-smoke.cs`（几十行，见 §5） |
| Play 驱动 | `<项目根>/tools/probes/*.ps1`（一次进 Play、按场景名跑入口、等标记） |
| 截图 / 报告 | `<项目根>/.ai-tmp/screenshots/`（**一次性产物，gitignored，验收后即删**） |

```bash
# 引擎即时编译执行，⛔ 探针不进 Unity 工程
unity command run_script --file <项目根>/tools/probes/probe.cs \
      --entry Probe.<Entry> --project-path <项目根>/client
```

**入口签名约定**：入口是 `void` 且**立刻返回**（fire-and-forget）。
理由：`run_script` 的传输层有 **30 秒超时**，而一个场景要跑十几秒到几十秒 ——
入口若同步等完，调用侧会先超时、判据反而拿不到。⇒ **完成靠日志标记，不靠返回值**（§2）。

`Game.AttachInput(桩)` 接管按键，**除按键这一层外跑的都是原代码**。
为什么必须走桩（而不是 OS 级注入）：编辑器窗口最小化 + 管理员权限下，OS 级注入在引擎的 **Tick 相位**读不到。

## 1. 输入桩：逐帧边沿语义（**最容易写错的一处**）

契约：**边沿（按下 / 抬起）只在那一帧为 true，下一帧必须消失**。

- `GetKeyDown(k)` / `GetKeyUp(k)` 的语义 = **"本帧按下 / 本帧抬起"**，与真后端的 `Input.GetKeyDown` / `wasPressedThisFrame` 逐帧对齐。
- 实现形状：`Hold(k, true/false)` **只写 pending 集合**（`downPending` / `upPending`），
  由**每帧调用的 `Tick()`** 把 pending 提升为"本帧边沿"，并**先清掉上一帧的边沿**：

  ```csharp
  public void Tick() {
      _down.Clear();  _up.Clear();
      foreach (var k in _downPending) _down.Add(k);  _downPending.Clear();
      foreach (var k in _upPending)   _up.Add(k);    _upPending.Clear();
      _real?.Tick();          // 真后端的每帧刷新（失焦复位等）也要转发，否则"跑的是原代码"不成立
  }
  ```

- **为什么不能用"按下过的键就永远留在 `_down` 里"**：那样一次按下之后 `GetKeyDown(该键)` **恒为 true** ⇒
  状态机每帧都判"按了键" ⇒ 在状态之间**每帧来回切**、面板每帧被建又被销毁、结算面板被销毁。
  表现是**连拍 6 秒全是纯色**、日志里同一句每帧一条 —— 而**根因在桩里，不在被测逻辑里**。
- `Lock()` / `Unlock()` 与真管理器对齐：**锁定时所有读取返回默认值**（`GetKey*` 前置 `!IsLocked`）。
- 必须定义 `BackendName`（如 `"Probe+" + 真后端名`）并**打一条接管日志**，
  这样"探针在接管"这件事在日志里可见（⛔ 不许静默接管）。
- 场景收尾必须**还原真输入管理器**（`DetachStub`），否则下一个场景 / 用户手点都受影响。

## 2. 场景开始 / 结束：**日志标记协议**

驱动**只能靠日志**判断"这个场景跑完了"，所以标记必须成对、逐字固定：

```
PROBE ==== 场景开始：<name> ====
...（场景体自己的读数行）
PROBE ==== 场景结束：<name> ====
```

- 包裹形状：`Start(name, body)` 先打**开始**标记，`Run` 里 `AttachStub()` → `await body()` →
  `finally { DetachStub(); 打结束标记; }` —— **`finally` 保证异常也一定有结束标记**（否则驱动会一直等）。
- 场景体抛异常时打 `PROBE 场景异常：<类型>: <消息> + 栈` ——
  ⚠️ 这类行**不算 `[Error]`**，驱动若只数 `[Error]` 会**把异常当 0 错误通过** ⇒ 驱动必须同时断言"**配对标记都在**"。
- 每行读数统一走 `Game.Logger.Info(tag, msg)`（`tag` 固定如 `Probe`），⛔ 不用裸 `Debug.Log`。
- 落盘目录**在开始标记处就 `CreateDirectory`**：`File.WriteAllBytes` / `WriteAllText` **不会自建目录**，
  目录不在就抛异常，而这个异常只进日志、不算 `[Error]` —— 又是一次"看起来跑过了"。

## 3. 截图：时机、退化帧判据、机位随图落盘

### 3.1 时机：**改一步、拍一步**（截图取的是**上一帧**的后备缓冲）

`CaptureScreenshotAsTexture()` **不会为你重绘** —— 同一次 eval 里"改参数 → 立刻拍"拍到的是**改之前那一帧**。
⇒ 任何"改参数 → 截图"的实验都拆成 `apply` / `capture` **两次 eval**；
术后自检 = **两张没有任何状态变化的连续帧如果长得完全不同 ⇒ 截图滞后**。

### 3.2 退化帧判据：**唯一色数**

切场景 / 冷加载后的头几帧会是"整屏单色"（面板还没画上来）——
**直接当证据就等于把空帧记成"一致"**（实测：同一次会话里第一次进某个界面拍到单色，第二次才有内容）。

- 判据 = **全图像素直方图的"唯一色数"**：纯色帧 = 1，有内容的帧远大于 1。
  - 粗判：`唯一色 < minUnique`（默认 3）⇒ **退化帧**，等 0.5 s 重拍，直到有内容或超时。
- ⛔ **不要用"稀疏网格采样判单色"**：20×20 的网格很可能**整个跳过一行字**，
  于是"深色底 + 一行字"的合法画面会被误判成退化帧（反之也会把空帧放过）。
- 判据写法要**两侧都留证据**：日志里同时打 `唯一色 / 主色 / 主色占比 / 退化帧=?? / 第几次`，
  超时也打一行 `警告：N 秒内始终退化 ⇒ 面板可能真的没画`（拒了就要看得见，⛔ 不许静默重试）。

### 3.3 出图闸门：**坏帧不许覆盖好帧**

两张实测事故：① 在"加载中"状态启动 ⇒ 拍出 N 张**入场卡**当标题屏，还**覆盖**了原来的好帧；
② 场景中途角色意外死亡 ⇒ 整关重开 ⇒ 后面几张是重开后的画面。
⇒ 出图前先判**状态 / 机位 / 运行时读数**（由调用方给一个 `ok()` 判据），**不过就一个字节都不写**：

```csharp
if (!gate) { L($"gate[{tag}] {name}: ... ⇒ 拒绝出图（图会假 ⇒ 一个字节都不写）"); return false; }
```

日志里必须打全"为什么拒"：当前状态 / 关卡或场景标识 / 对象坐标与存活 / 机位 / 关键读数。

### 3.4 机位随图落盘（否则离线脚本没法把像素换算回世界）

每次截图落盘的**同一行日志**里必须带：

```
分辨率=WxH  机位= x=?? y=?? 正交半高=??
```

理由：像素级判据由**离线脚本**做，它要靠这三项把像素反算回世界坐标。
⛔ 只存 PNG 不存机位 ⇒ 图**不可判定**。

## 4. 场景可重入（连着跑多个场景）

- 每个场景开始前先回到一个**已知基线状态**（例如主菜单），并**用真实路径**回（发事件 / 走流程），
  **不能只切状态机状态** —— 只切状态不加载对应场景 ⇒ 截出来是一张空白图（多张 sha 全同）。
- 就绪判据要具体：**"目标状态 + 上一段会话已释放"**（例如上一段的对象 / 关卡引用为 null），
  而不是"等 N 秒"。
- 每个场景收尾还原输入桩，**场景之间不共享可变状态**。

## 5. 开场先跑冒烟（30 秒，先证明通道可用）

冒烟脚本（`probe-smoke.cs`）只做一件事：**证明 `run_script` 能访问本工程程序集 + 能写进游戏日志**。

```csharp
// 全限定名（探针不在工程程序集里，必须写全名）
CloverEngine.Game.Logger.Info("Probe", "PROBE-SMOKE 开始");
CloverEngine.Game.Logger.Info("Probe", $"PROBE-SMOKE 平台={...} 输入后端={CloverEngine.Game.Input?.BackendName}");
CloverEngine.Game.Logger.Info("Probe", "PROBE-SMOKE-DONE");
```

⇒ **凡"探针没反应 / 日志里什么都没有"的排查，第一件事是跑冒烟**：
它把"引擎 / IPC 通道坏了"与"我的场景体写错了"分开，省掉整轮误判。

## 6. 驱动契约（`.ps1`）

| 契约 | 要求 |
|---|---|
| 进 Play | 驱动正在运行的编辑器（`editor_play`），⛔ 不跑 batch |
| 跑哪个场景 | 参数传入口名（`-Scene <Entry>`），驱动拼 `--entry Probe.<Entry>` |
| 判完成 | 等 §2 的**配对标记**；⛔ 不是"等固定秒数" |
| 超时 | 显式 `-SceneTimeout`（秒）；超时 ⇒ **判红并保留日志**，⛔ 不许当"通过" |
| 记账 | 每进一次 Play 往 `<项目根>/.ai-tmp/test/play-log.tsv` 追加一行，第 4 列写**为什么必须进这条链** |
| 可离线判的 | ⛔ 不许进 Play：数值 / 逻辑 / 状态走 `.ai-tmp/hosts/*check`（秒级） |

## 7. 不许犯的几条

- ⛔ 探针里**不许**写业务逻辑的分支判断（"我认为这时应该是 X"）—— 探针只**读活节点树 / 真状态**并落盘。
- ⛔ 判据**不许**只看"没报错"：`[Error]` 计数为 0 而**配对标记缺失 / 场景异常进的是普通日志** ⇒ 照样是假绿。
- ⛔ 截图**不许**落在 `client/Assets/**`（会进游戏工程）—— 一律 `.ai-tmp/screenshots/`。
- ⛔ **不许**把**探针外壳与驱动**当"一次性产物"删掉（删了 = 复验能力归零）；
- ⛔ **也不许反过来**：一次性切片脚本（文件名带片名 / slice id、只服务某一次判定）**用完即删** —— `tools/probes/` 只放**下次改完还会再跑一次**的东西，⛔ 别把它当"所有脚本的仓库"。
